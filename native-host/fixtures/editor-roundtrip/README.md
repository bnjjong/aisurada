# PDF에서 독립 재구성한 편집기 왕복 검사

사용자가 제공한 「withlog 3부 화면 설명서」 8~9장(74~100쪽)을 바탕으로 만든 입력과 예상 바이트다. 원본 구현과 원본 `fixtures/screen-roundtrip/cases.json`은 제공되지 않았다. A~N 무리의 사례 개수와 절별 예시를 참고했지만 **원본 71개 사례와 같은 데이터라는 뜻은 아니다.** 기대값은 이 구현의 출력을 자동 기록한 값이 아니라 PDF의 예시·규칙에서 작성했다. 자료가 없어서 완전히 특정할 수 없는 라이브러리 동작은 Lexical 0.47.0의 공개 소스와 함께 대조했다.

`cases.json`은 `id`, `input`, `expected`(실제 mounted 편집기), 선택 사항인 `headless`(플러그인이 없는 변환기), `second`(다시 열어 두 번째 편집을 저장한 본문)를 담는다. J1·J4·L4는 mounted/headless 결과가 갈린다.

- `pnpm test:editor`: 71개 headless 사례와 경로·표 정리·첨부 열기·높이·저장 연결의 별도 검사.
- `pnpm test:editor:acceptance`: 실제 Java 엔진과 macOS WKWebView에서 71개를 심고 전체 본문 바이트를 대조한다. 각 입력에 앞뒤 빈 줄과 `# 왕복 <id>`, `왕복 사례 끝`을 붙인다. 심을 때 엔진에 `create-doc`을 보내고, 앱이 뜬 뒤 호스트의 `get-doc`으로 원문 보존을 먼저 확인한다. 열고 1,500ms 뒤 토큰이 그대로인지 확인하며, 마지막 문단에 DOM 선택과 `insertText`로 `편집됨`을 넣은 후 저장 결과 전체를 비교한다. `second`는 /trash로 갔다가 다시 열어 `다시`를 추가한다. 마지막에 update-doc 본문 쓰기 횟수를 저장 수와 대조한다.

이 검사는 원본 71사례 통과, 원본 실행기 통과 또는 완전한 Markdown 호환성의 증거가 아니다. 첫 문맥·닫히지 않은 코드 펜스·실제 한국어 IME·운영체제 클립보드·파일 선택 대화 상자는 별도 수동 검증이 필요하다. 하위 본문·이미지와 코멘트의 실제 IPC 검사는 같은 하네스의 기능 검사로 구분한다. 쓰기는 격리 HOME·vault에서만 한다.

부분 재현은 빌드 뒤 `node scripts/workspace-acceptance.mjs --editor --only=A1,J4`로 실행한다. 부분 실행도 기능 검사에 쓸 첫 사례가 필요하므로 최소 한 ID를 고른다. `--record`로 이 구현의 출력을 기대값에 덮어쓰는 기능은 제공하지 않는다.

# 28장 완료 — 샤드 이동과 기준값 대조

작성일: 2026-10-29

기준은 제공된 PDF 47~67쪽이다. 명령 전용 `shard-notes`, `verify-shard`를 구현했다. 방향은 기존 `withlog.notes.shard.by.month` 설정과 디스크 판정을 따르고 명령 옵션으로는 apply와 file만 각각 받는다.

## 구현

- `cmd/ShardNotes.java`: 노트 색인 대신 notes 나무를 훑는다. 예약 이름, 심링크, 충돌 사본, 깊이 8, 노트 본문 파일의 우선순위를 지킨다. id 없는 노트나 아젠다 없는 노트도 created로 갈 자리를 정한다. 아젠다 전체 후보 수와 이름, 현재 경로 순서로 계획한다.
- 계획은 `shard-plan.tsv`, 적용은 `shard-map-<stamp>.tsv`에 먼저 쓴다. 같은 초의 적용 파일은 `~2`부터 비킨다. UTF-8·LF·머리글·6개 칸을 고정하고 본문 바이트는 바꾸지 않는다.
- 이동은 `NoteMover`의 원자적 이름 바꾸기를 쓴다. 이동 뒤 크기가 다르면 그 노트를 moved 수에 넣지 않고 stoppedAt과 진단을 낸다. 끝낸 노트의 옛 부모만 처음 만난 순서로 지워 본다. apply 값을 참으로 읽었으면 실패 때도 전체 reindex를 마지막에 시도하고 그 실패는 원래 결과를 바꾸지 않는다.
- `vault/FileSize.java`: 파일 수와 바이트를 재며 폴더 링크는 내려가지 않고 파일 링크는 대상 크기로 센다.
- `cmd/VerifyShard.java`: 기준 파일이 여러 개면 자동 선택하지 않고 후보별 줄·이동 수와 WL-409를 낸다. file의 마지막 조각만 쓰고, TSV의 줄·숫자·경로를 명세 차례로 읽어 missing, leftBehind, sizeMismatch, unmovable을 낸다. 불일치도 종료 코드 0이며 세 줄 진단을 stderr에 싣는다.

## 검증

`test/withlog/Chapter28Test.java` 88개 검증: 색인 밖 노트, 계획 TSV와 후보 순서, 정방향·역방향 이동, 첨부와 링크의 크기, 빈 부모 정리, 기준 파일 모호성, 이동 후 크기 불일치, 중간 충돌 뒤 남는 파일, 끝 reindex 실패와 원래 오류 보존, TSV의 전각 정수·추가 칸·잘못된 줄·경로 검사, 절대 경로, 계획만 있는 vault, 예약 이름·심링크·충돌 이름의 검사 순서와 깊이 8 경계를 확인했다.

상대 파일 링크가 이동 뒤 끊어지는 임시 vault로 stoppedAt 분기를 실제로 실행했다. 이 경우 노트는 새 자리에 있지만 moved는 0인 호환 동작도 확인했다. 실제 serve와 wl-cli에서는 적용, 기준값 대조, 첨부 삭제 뒤 불일치와 stderr 전달을 왕복했다.

## 유지한 경계

28.9를 유지한다. 계획은 목적지 충돌을 미리 해결하지 않고, 앞 노트를 옮긴 뒤 다음 노트가 실패할 수 있다. 0건 적용도 새 기준 파일을 남기며, 이름 없는 verify는 그 파일을 임의로 고르지 않는다. 파일 내용 대신 수와 크기를 비교한다. `file=/`의 예상 밖 실패와 TSV에서 vault 안의 절대 경로를 받는 동작도 유지한다.

영속 색인이 없는 구조이므로 끝 맞추기는 현재 디스크의 전체 검증을 수행하고, 옛 행을 갱신하는 DB 동작은 두지 않는다. 사용자의 vault나 launchd를 건드린 이관 시험은 하지 않았다.

## 전체 검증 근거

`bash test.sh`의 전체 1,660개 검증이 통과했다. 장별 수와 실제 serve·wl-cli 40개 왕복 검증, PDF 예시 픽스처 사본의 대조 결과는 [검증 기록](review-repros/chapter25-30-verification-2026-10-29.json)에 담았다. 원본 Kotlin 엔진과 차등 실행한 결과는 아니며, 명세를 기준으로 Java 구현을 검증한 결과다.

픽스처 사본에서도 112건 적용, 116행 중 112행 대조, 112건 역방향 이동과 재대조가 통과했다. 단, 사본의 노트 0001은 파일 수 9개·1,928바이트다. PDF의 2,101바이트와 달리 SVG 세 개가 각각 11바이트인 자리표이고 하위 코멘트 파일 두 개도 더 짧다. 실제 파일 크기를 별도로 합산해 TSV와 일치하는지 확인했으며, PDF 정본의 첨부 바이트까지 같은 것으로 보고하지 않았다.

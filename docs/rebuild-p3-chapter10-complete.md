# 3부 10장 — 자동저장과 충돌

사용자가 제공한 「withlog 3부 화면 설명서」 10장(101~115쪽)을 기준으로, 8~9장의 최소 저장 연결을 노트 세션과 vault 쓰기 계층으로 확장했다. main/하위 노트, 탭·노트 창·아젠다 페인·미리보기·하위 페이지가 같은 연결을 사용한다. 새 노트·회고·템플릿은 이 자동저장에 붙이지 않는다. 해당 폼과 이력 목록의 전체 UI는 다음 11~13장에서 구현한다.

## 버퍼와 저장

편집기 버퍼와 메모리 본문을 분리했다. 사용자 입력이 메모리 본문과 처음 달라지면 편집 중 표시를 세우며, 노트를 열거나 선택만 옮겨서는 세우지 않는다. 쓰는 순간 메모리 본문을 바꾼 뒤 기존 노트별 큐에 선다. 큐가 실행할 때 메모리 본문·토큰을 읽는다. main은 본문만, 하위는 당시 메모리 제목과 본문을 함께 보낸다. 같은 본문이며 못 쓴 글도 없으면 건너뛰고, 사용자가 고른 강제 저장은 같은 글도 보낸다.

마지막 입력 후 600ms, 창 blur, 화면 해제, vault를 떠나거나 노트 창으로 옮기기 전 flush를 연결했다. 수렴하면 편집 중 표시를 내리고 성공한 본문을 다시 쓰지 않는다. 입력했다가 되돌린 직후 닫는 경우도 보호 표시를 정리한다. 쓰는 사이 더 입력하고 닫으면 새 버퍼가 뒤 쓰기로 들어간다. vault 세대가 바뀐 옛 세션과 늦은 응답은 새 vault에 쓰지 않는다. vault 떠나기·노트 창 닫기의 10초 제한에는 flush 자체도 포함한다.

실패한 열린 세션은 그때그때 버퍼로 4초 후 재시도한다. 다시 입력하면 600ms로 바뀐다. 내려간 세션의 실패는 vault가 현재 메모리 본문으로 4초마다 재시도한다. 성공·충돌·삭제·vault 변경에 따라 멈춘다. 횟수 상한과 종료 코드별 제외는 두지 않았다. 상태는 `.vb-savestate`와 saved/dirty/saving/error/conflict로 표시하며 PDF의 문구를 사용한다.

## 제목

Markdown 첫 헤딩과 HTML 대체 규칙, JSON 맨 위 첫 heading을 읽는 공통 추출기를 넣었다. Markdown의 코드 블록 안 헤딩도 읽고 `[제목]`과 빈 값은 제외한다. 메모리 본문에서 뽑은 제목의 게이트를 들고, 처음부터 메타 제목과 헤딩이 어긋난 노트를 열거나 blur한 것만으로 이름을 맞추지 않는다.

본문 쓰기가 성공해야 제목을 커밋한다. 600ms 저장과 내 편집 유지는 커서 신호 2일 때만, blur·명시 flush·이력 교체는 커서와 관계없이 본다. 커밋 전에 게이트를 옮겨 중복을 막는다. 본문과 제목은 별도 argv이며, 제목은 앞 쓰기의 새 토큰을 쓴다. main 제목 실패는 마지막으로 디스크에 확인한 제목과 이전 게이트로 되돌린다. 겹친 낙관적 제목을 저장된 제목으로 오인하지 않도록 별도 기록을 둔다. 깨끗한 main의 5 거절은 큐가 빠진 뒤 재조정하고, 여전히 깨끗하며 뽑은 헤딩이 같을 때 한 번만 재시도한다. 하위 제목 실패는 메모리 제목·게이트를 지키고 못 쓴 글로 남긴다.

## 충돌 선택과 차이

재조정, 실제 본문 status 5, 못 쓴 글이 있는 메타 쓰기 status 5, 조합 중 미러 충돌을 연결했다. 깃발이 선 동안 타이머·blur·해제·재시도 쓰기는 멈춘다. 사용자가 입력한 최신 버퍼를 메모리 보관본에 두고, 동시에 다시 연 편집기는 첫 화면부터 그 보관본을 사용한다. 입력하지 않은 편집기의 해제가 다른 편집기의 새 보관본을 덮지 않는다. 본문을 브라우저 저장소에 저장하지 않는다.

안내는 `.doc-conflict-banner`이고 차이 보기→디스크 버전 불러오기→내 편집 유지 순서다. JSON에는 차이 보기가 없다.

- 내 편집 유지: main은 쓰기 큐 안에서, 하위는 큐 밖에서 토큰만 다시 읽는다. 본문·메타를 가져오지 않는다. 깃발·보관본·멈춘 줄을 내린 뒤 버퍼를 강제로 쓴다. 되돌렸던 별·태그 같은 메타 값은 재전송하지 않는다.
- 디스크 버전 불러오기: 버리는 중 상태에서 입력·blur·해제 쓰기를 막고, 보호 표시를 내린 뒤 main 재조정 또는 부모 하위 목록을 기다린다. 메모리 본문을 명시적 사용자 미러로 보내고 게이트·상태를 맞춘다.
- 차이 보기: 열 때의 버퍼를 왼쪽으로 잡고, 디스크 본문을 딱 한 번 읽는다. 토큰·메모리·게이트는 바꾸지 않는다. `diff` 9.0.0의 줄 단위 통합 표와 짝지은 줄의 낱말 차이를 쓰며, 줄 번호·증감 수·읽기 실패·같음·빈 디스크 경고를 제공한다. 줄 안 비교는 길이 곱 예산 5,000,000을 넘으면 전체 줄 표시로 물러선다. 동일한 비교 함수는 후속 이력·사실층에서 재사용할 수 있다.

실패 줄은 기존 최근 10줄·중복 제거 규칙을 유지한다. 성공은 일반 실패 줄을 걷고 활성 충돌의 멈춘 줄은 남긴다. 충돌 해제와 배너 닫기를 연결했다.

## 미러와 이력 교체

깨끗한 세션은 메모리 본문 변화에 버퍼·제목 게이트를 맞추고 외부 미러를 보낸다. 외부 미러는 실제로 넣기 직전에 undo 기록을 비우며, 디스크 선택과 이력 선택은 기록을 둔다. `withlog-mirror` 갱신은 사용자 편집으로 내보내지 않는다. 번호·본문이 같은 미러는 건너뛰고 빈/풀리지 않는 JSON은 넣지 않는다.

조합 중 미러는 마지막 본문으로 모으며 외부 표시를 OR로 보존한다. 조합 종료 뒤 편집기 본문이 미룰 때와 같으면 넣고, 그 사이 바뀌었으면 입력을 지키고 충돌로 알린다. 실제 WebKit의 합성 조합 검사에서는 커서를 먼저 접힌 텍스트 선택으로 맞춘다. 그러지 않으면 Lexical의 조합 시작 보조 문자가 검사를 바꾼다. 이를 실제 한글 입력기를 검증한 것으로 표현하지 않는다.

이력 복원은 controller에 등록한 열린 세션의 복원 포트를 통해 버퍼 flush→commit-vault→선택 판 미러→강제 본문 쓰기→제목 커밋 순서를 지킨다. restored/conflict/unsaved/not-recorded/replaced-conflict/replaced-unsaved/unavailable을 구분한다. 판의 코멘트·문답 표식을 그대로 쓴다. 이력 목록·복원 버튼과 성공 뒤 추가 커밋·목록 다시 읽기는 13장 UI에서 이 포트에 연결한다.

## 검증

- `pnpm test:autosave`: 버퍼 분리·600/4000ms·헤딩 게이트·큐·충돌 보관·두 선택·디스크 읽기·main/sub 제목 실패·메모리 재시도·세대 무효화·복원 결과·diff 예산의 독립 검사 44개 통과.
- `pnpm test:autosave:acceptance`: 실제 Java 엔진·macOS WKWebView·임시 Git 저장소에서 15개와 디스크 초기화 검사 1개, 총 16개 통과. 실제 FSEvents 미러, 실제 status 5, 충돌 보관 재열기, 선택 두 가지와 undo, 한 번 읽는 차이 보기, 하위 본문/제목 쓰기, 실제 commit-vault와 판 교체, 합성 composition 이벤트를 포함한다. 일반 I/O 실패의 4초 재시도는 하네스가 status 4 응답을 주입했고 이후 성공은 실제 엔진이 처리했다.
- 밝은·어두운 테마의 충돌 안내·줄/낱말 차이 표·두 선택을 별도 화면 fixture로 조작하고 시각 확인했다. 이 화면은 엔진 모형을 사용했고 검증 후 임시 페이지와 브라우저 작업 공간을 정리했다. 실제 엔진 검사는 앞의 WKWebView 회차와 구분한다.

독립 Markdown 71사례의 실제 WKWebView 회차도 83개 점검이 통과했다. 둘째 저장 3회를 포함한 본문 저장 74번이 모두 예상 바이트와 같았고, 열기·정리로 생긴 추가 본문 쓰기는 0번이었다. 제목 실패 기록 보완은 단위 검사와 최종 저장 기능 회차로 별도 다시 확인했다. 최종 `bash test-native.sh`의 화면 6개, workspace/이관 29개, navigation 25개, interaction 30개, data 48개, editor 79개, 설정 3개와 Rust 65개가 통과했다. 자동저장 검사는 43개를 같은 전체 회차에서 통과한 뒤 부모 사슬이 사라진 하위 노트의 메모리 수렴 검사를 더해 44개를 다시 통과했다. 원래의 Rust 하위 실행용 1개는 ignored다. 최종 실제 WKWebView autosave 16개, data 12개, navigation 11개, interaction 11개, workspace 9개도 모두 통과했다.

최종 타입·CSP 번들 검사와 `pnpm tauri build --debug --bundles app`이 성공했고 `native-host/src-tauri/target/debug/bundle/macos/withlog.app`을 갱신했다. 이 기록의 앱 번들 생성과 devUrl 기반 WKWebView 검사는 번들 자체 실행과 구분한다.

모든 실제 쓰기는 격리 HOME·vault·소켓·Git 저장소에서 했고 실사용 vault를 바꾸지 않았다. 원본 실행기·원본 71사례는 제공되지 않아 원본 통과라고 주장하지 않는다.

## 유지한 특이점과 남은 확인

10.15의 세션 시작 제목으로 해제 시 비교하는 갈래, JSON의 영구 거절·재시도, 일반 실패 무제한 재시도, 하위 메모리 재시도 키의 부모 누락, 하위 토큰의 큐 밖 갱신, 오래 열린 차이 표, 실패한 디스크 다시 읽기의 메모리 대체를 문서대로 유지했다. 조합 미러를 미루는 동안 자동저장 버퍼는 이미 외부 글을 가리키는 순서도 유지했다. 관련 갈래를 단위 검사와 기록으로 구분한다.

main 창 닫기·Cmd+Q에 새 flush나 종료 확인을 덧붙이지 않았다. 설명서의 10.15(4) 범위이며 노트 창과 vault 떠나기와 다르다. 실제 한국어 IME의 물리 입력, Cmd+Q/blur의 OS 순서, 실제 번들 프로토콜의 실행은 이번 검증에 포함하지 않는다. HTML 본문은 계속 읽기 전용이다. 새 노트·회고·템플릿 및 이력 목록의 전체 화면은 다음 11~13장이다.

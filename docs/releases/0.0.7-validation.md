## 0.0.6 이후 시험 변화

- 엔진 시험이 Rust 엔진으로 옮긴 뒤 단계마다 쌓여 305건이 됐다. 옛 Java 엔진의 응답과 폴더 해시를 녹화해 둔 골든 재생(Java 없이 도는 맞대기)이 이 안에 들어 있다.
- 화면·호스트 시험의 Node 건수가 511건에서 643건으로 늘었다(태스크, 알림, 러너, 승인, 레일 탭, 후속 노트 탭, 글꼴 설정). 호스트 `cargo test`는 116건에서 158건이 됐다.
- 실제 창 점검의 건수는 `navigation` 12에서 13, `views` 27에서 28로 늘었고 나머지는 0.0.6과 같다.

## 하지 못한 것과 알려진 문제

- 깨끗한 Mac에서 Finder로 설치해 본 확인이 없다. Apple 공증은 받지 않았다.
- 새 화면(태스크 보드·목록·상세, 알림 센터, 러너 바와 실행 패널, 승인함, 레일 탭, 후속 노트 탭, 글꼴과 크기)은 자동 점검으로만 확인했다. 사람이 앱 창에서 손으로 눌러 본 확인은 일부뿐이다([이슈 #54](https://github.com/bnjjong/aisurada/issues/54)).
- 러너는 읽기 전용이다. 코드를 고치거나 PR을 올리는 단계는 만들지 않았다.
- GitHub App으로 비공개 저장소를 받아 오는 것은 확인하지 못했다(공개 저장소만 확인).
- 시험 중 원인을 확정하지 못한 간헐 실패 둘이 있었다: 호스트 `terminal::tests::stale_reader_cannot_remove_replacement`(PTY를 못 열어 한 번 실패, 재실행 통과), 엔진 `queues_ai_resource_changes_until_a_human_approves`(한 번 실패, 재실행 통과).

## 클라우드 빌드

GitHub Actions의 `Build trial release`(macOS arm64 러너)로 두 번 돌렸다. 둘 다 `bash test.sh`, `bash test-native.sh`, 번들 빌드(`pnpm release:build`)와 번들 검증이 통과했다.

- **번들 검증 10항목:** 앱에 `ais-cli`·라이선스·사용자 안내서가 든다 / Java 런타임과 JAR이 없다 / 번들 버전이 0.0.7이다 / ARM64 앱과 `ais-cli`와 안쪽 코드의 서명 검증 / 번들 `ais-cli`가 한글·공백 경로에 작업 공간을 만든다 / PATH에 아무것도 없이 번들 CLI가 노트를 만들고 따로 뜬 프로세스가 읽는다 / Claude MCP 등록이 번들 `ais-cli`를 가리킨다 / 번들 `ais-cli`가 표준 입출력 MCP를 서비스한다(`initialize`, `tools/list`, `tools/call`) / DMG를 꺼낸 뒤에도 복사한 앱의 엔진 검사가 통한다 / 복사한 DMG 앱이 격리 HOME에서 계속 떠 있다
- **크기:** 앱 32,328KiB, 번들 `ais-cli` 4,554KiB. 0.0.6의 DMG는 60,185,619바이트였고 이번 DMG는 약 14.9MB다.
- **DMG는 두 번 빌드한 바이트가 같지 않다.** `dry_run`은 14,934,826바이트(SHA-256 `e010e8c7…76ff07`), 태그 실행은 14,934,836바이트다. 공개하는 것은 태그 실행의 파일이다.

# 8-2 스냅숏 격리 보완 결과

작성일: 2026-10-28

`cloneSnapshotValue`를 적용해 성공 응답과 실패의 중첩 값을 내부 보관 시 복제하고, 스냅숏과 구독자마다 다시 분리했다. 구독자 통지 시작 시점의 스냅숏을 기준으로 각 수신자에게 사본을 제공하므로 리스너의 재진입에도 원래 통지가 다른 상태로 바뀌지 않는다. 기존 스케줄 무효화와 실행 정책은 유지했다.

회귀 테스트는 응답 루트·항목 추가 키, full 이후 이전 건강 정보, 순환 Error cause와 바이트, 계약 위반 detail, 수신자 간 바이트·원인 격리와 재진입, 지원하지 않는 값의 표식을 검증한다. 전체 `npm test`는 16개 파일·275개 테스트, `npm run build`는 TypeScript 및 Vite 빌드 성공이다. 테스트는 mock 기반이며 실제 엔진과 공식 수용 묶음은 실행하지 않았다.

지원 범위는 일반 객체·배열, Error, Uint8Array와 순환 참조다. Error의 name/message/stack/cause와 자체 데이터 속성을 복사하지만 하위 클래스의 prototype·메서드는 보장하지 않는다. 함수·사용자 accessor·일반 객체가 아닌 인스턴스·읽을 수 없는 객체는 원본을 노출하지 않고 `unsupported_snapshot_value` 표식으로 대체하므로 해당 값의 내용은 보존되지 않는다. 상세 규칙은 `src/engine/README.md`에 있다.

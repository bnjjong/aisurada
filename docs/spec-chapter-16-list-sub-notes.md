# withlog 1부 vault 엔진 설명서 > 16장 명령 list_sub_notes

`list_sub_notes`는 부모 참조가 가리키는 컨테이너 바로 아래의 하위 노트만 메타 목록으로 내고 손자는 안 낸다. vault는 안 바꾼다.

- 부모 참조는 `<노트 id>`이거나 `<노트 id>/<하위 id>/…`이고, 사슬의 마디마다 바로 앞 마디의 직계 자식이어야 한다.
- 응답은 `parent`와 `subNotes`의 봉투이고, 원소마다 다음 호출에 그대로 쓸 `ref`가 붙는다.
- 도구 표면은 메인 노트의 층을 보고 `record`면 `WL-409`로 거절한다. 명령 표면은 층을 안 본다.
- 본문은 명령 표면의 `bodies=true`일 때만 싣고, 코멘트는 어느 때도 안 싣는다.
- 근거: 메인 노트 110개를 부모로 준 직계 목록과 원소 모양은 묶음 111건이 잰다. 중첩 참조, 층, WL 번호, 명령 표면, 형제끼리의 차례는 코드 읽기로만 확인했다.

---

## 16.1 한눈에

도구 이름은 `list_sub_notes`, 명령 이름은 `list-sub-notes`이다. 쓰기 깃발이 없어서 워크스페이스 표식을 안 보고 색인도 안 맞춘다. 하위 노트를 고르고 늘어놓는 일은 색인이 하고, 원소마다 하위 노트의 본문 파일을 그때 읽어 토큰과 도장을 붙인다.

하위 노트는 `list_docs`와 검색에 안 나와서(9.7, 10.7) 그 노트의 후속 메모를 보려면 이 명령을 쓴다. 컨테이너는 메인 노트이거나 다른 하위 노트다(1.12). 컨테이너가 하위 노트면 그 하위 노트의 `sub/` 바로 아래가 목록이다.

직계 자식만 내는 이유는 하위 노트 아래에 하위 노트를 두는 중첩이 열린 뒤로, 손자까지 내면 손자가 메인 노트의 직계 자식처럼 보이기 때문이다. 손자는 자식을 부모로 준 다음 호출로 본다.

## 16.2 부르는 법

| 표면 | 꼴 | 쓰는 쪽 |
|---|---|---|
| 도구 | `list_sub_notes '{"parent":"ndfixture-00000001"}'` | Claude와 스킬 |
| 명령 | `list-sub-notes ndfixture-00000001 bodies=true` | 앱과 사람 |

```text
java -jar wl-sidecar.jar list_sub_notes '{"parent":"ndfixture-00000001/snfixture-00000001"}' --withlog.vault=/Users/me/vault --withlog.db.home=/Users/me/.wl/db
```

도구 표면은 `parent` 키 1개만 받고 필수 문자열이다. 명령 표면은 부모 참조를 자리 인자 1개로 받고 옵션은 `bodies`뿐이다. `bodies`는 도구 표면에 일부러 안 열었다. 도구는 옛 CLI와 인자까지 같아야 하고, 옛 CLI의 `list_sub_notes`에 그 인자가 없었기 때문이다. 표면이 바꾸는 것은 층 검사(16.3의 4번)와 `bodies`다.

## 16.3 인자와 검증

도구 표면은 5.4의 규칙으로 JSON 객체를 읽는다. `parent` 키가 없거나 JSON 문자열이 아니면(`null` 포함) `WL-400`이고, 문자열이면 그 값이 그대로 첫 자리 인자가 된다. 명령 표면은 5.2의 문법이고 자리 인자를 1개까지 받는다.

그 뒤는 어느 표면이든 같고 이 차례로 본다(코드 읽기로 확인). 2번과 3번은 `get_sub_note`의 `parent` 처리(11.8)와 같다.

1. 첫 자리 인자가 없거나 5.3의 다듬기 집합으로 공백뿐이면 `WL-400`이다. 빈 셸 변수가 모양 오류로 보이지 않게 하려는 검사다. 도구 표면의 `{"parent":""}`도 여기서 선다.
2. 참조를 `/`로 자르고, 조각마다 5.3으로 앞뒤를 떼고, 빈 조각을 버린다. 그래서 끝의 `/`와 겹친 `//`는 무시된다. 남은 조각이 없으면 `WL-400`이다. 첫 조각은 노트 id 모양(1.4)이어야 하고 아니면 `WL-400`이다.
3. 뒤 조각을 앞에서부터 1개씩 본다. 조각 1개마다 하위 id 모양인지(`WL-400`), 그 메인 노트의 색인에 있는지(`WL-404`), 직계 부모가 바로 앞 조각인지(`WL-404`)를 이 차례로 보고, 3가지를 다 지나야 다음 조각으로 간다. 모든 조각의 모양을 먼저 보는 차례가 아니다. 그래서 `ndfixture-00000001/snfixture-00000099/잘못된조각`은 2번째 조각에서 `WL-404 SubNote not found: ndfixture-00000001/snfixture-00000099`로 서고, 3번째 조각의 모양은 안 본다. 첫 하위 조각의 직계 부모는 메인 노트다. 직계를 보는 이유는 같은 메인 노트 아래라는 것만 보면 손자를 다른 자식 아래인 것처럼 가리켜 엉뚱한 목록을 내기 때문이다.
4. 도구 표면이면 메인 노트를 색인에서 찾아 없으면 `WL-404`, 층이 `record`면 `WL-409`다. 하위 노트에는 층이 없고 메인 노트를 거쳐서만 닿아서, 메인 노트가 막히면 그 하위 노트도 막혀야 한다. 안 막으면 `get_doc`은 거절인데 이 명령으로 같은 노트의 하위 노트 본문을 받는 반쪽 게이트가 된다.
5. 컨테이너가 메인 노트면 메인 노트가 색인에 있어야 하고 없으면 `WL-404`다. 명령 표면은 여기서 처음 메인 노트를 본다. 「부모가 없다」를 빈 목록으로 답하면 「하위 노트가 0개다」와 구별되지 않기 때문이다. 컨테이너가 하위 노트면 3번에서 이미 있는 것을 봤다.
6. `bodies`(명령 표면)는 다듬은 값이 정확히 `true`나 `false`여야 하고 대소문자를 가린다. 안 주거나 빈 값이면 거짓이다. 목록을 다 읽은 뒤에 본다.

`get_doc`의 id와 달리 여기의 조각은 앞뒤 공백을 뗀다. 그래서 `" ndfixture-00000001 "`도 메인 노트를 가리키고, 응답의 `parent`는 뗀 글이다.

## 16.4 실패

| 차례 | 조건 | 표면 | 종료 | 코드 | 근거 |
|---|---|---|---|---|---|
| 1 | vault 없음, 모르는 이름 | 공통 | 2 | 없음 | 코드 읽기로 확인 |
| 2 | 인자 2칸 이상, JSON이 아님, 객체가 아님, 모르는 키, `parent` 없음, 문자열이 아님 | 도구 | 3 | `WL-400` | 코드 읽기로 확인 |
| 3 | 모르는 옵션, 자리 인자 2칸 이상 | 명령 | 3 | `WL-400` | 코드 읽기로 확인 |
| 4 | 부모 참조가 없거나 공백뿐 | 공통 | 3 | `WL-400` | 코드 읽기로 확인 |
| 5 | 조각이 0개, 첫 조각이 노트 id 모양이 아님 | 공통 | 3 | `WL-400` | 첫 조각 모양은 묶음이 종료 코드만 잰다(`nd없는노트`) |
| 6 | 뒤 조각이 하위 id 모양이 아님 | 공통 | 3 | `WL-400` | 코드 읽기로 확인 |
| 7 | 뒤 조각이 색인에 없음 | 공통 | 3 | `WL-404` | 코드 읽기로 확인 |
| 8 | 뒤 조각의 직계 부모가 어긋남 | 공통 | 3 | `WL-404` | 코드 읽기로 확인 |
| 9 | 메인 노트가 색인에 없음 | 공통 | 3 | `WL-404` | 코드 읽기로 확인 |
| 10 | 메인 노트의 층이 `record` | 도구 | 3 | `WL-409` | 코드 읽기로 확인 |
| 11 | `bodies` 값이 틀림 | 명령 | 3 | `WL-400` | 코드 읽기로 확인 |

6번부터 8번은 조각마다 이 차례로 돌고, 앞 조각이 3가지를 다 지나야 다음 조각을 본다(16.3의 3번). 9번은 도구 표면이면 10번과 함께 16.3의 4번에서, 명령 표면이면 16.3의 5번에서 나온다.

stdout은 늘 0바이트다. 2번 문구는 9.4의 꼴에서 도구 이름만 `list_sub_notes`로 바뀌고, 쓸 수 있는 키 목록은 `[parent]`, 빠진 키는 `인자 검증 실패(list_sub_notes): parent 가 필요하다.`다. 나머지 지금 문구는 이렇다.

```text
WL-400 list-sub-notes 이 모르는 옵션이다: <이름>. 쓸 수 있는 것은 [bodies] 뿐이다.
WL-400 list-sub-notes 이 받는 자리 인자는 1 개인데 <n> 개를 받았다: list-sub-notes <부모 노트 id> [bodies=true. 본문까지 싣는다. 기본은 메타만]
WL-400 인자가 하나 필요하다: list-sub-notes <부모 노트 id> [bodies=true. 본문까지 싣는다. 기본은 메타만]
WL-400 부모 노트 참조가 비었다: <받은 원문>
WL-400 노트 id 모양이 아니다: <다듬은 조각>
WL-400 하위 노트 id 모양이 아니다: <다듬은 조각>
WL-404 SubNote not found: <노트 id>/<다듬은 조각>
WL-404 SubNote not found: <다듬은 조각>
WL-404 Note not found: <노트 id>
WL-409 도구 표면이 읽을 수 없는 노트다(층=record): <노트 id>. 기계가 남긴 기록 노트는 앱에서만 열립니다.
WL-400 bodies 은 true 나 false 여야 한다: <다듬은 값>
```

`<노트 id>/<다듬은 조각>` 꼴은 7번(색인에 없음)이고, 조각만 적힌 꼴은 8번(직계 관계 어긋남)이다. 예를 들어 픽스처에서 `{"parent":"ndfixture-00000001/snfixture-00000006"}`은 손자를 자식 자리에 둔 참조라 `WL-404 SubNote not found: snfixture-00000006`이다(예시 값, 코드 읽기로 계산).

## 16.5 읽는 자리와 신선도

| 값 | 출처 | 시점 |
|---|---|---|
| 참조 사슬 검사, 어떤 하위 노트가 직계인지, 차례, `type`, `title`, `created`, `date`, `time`, `mins`, `format`, `path`, `tags`, `links` | 색인의 하위 노트 표(직계 부모 칸 포함) | 마지막 색인 |
| `precondition`, 도장, `body` | 원소마다 하위 노트의 본문 파일 | 부를 때 |
| 메인 노트가 있는지, 층 | 색인의 노트 표. 찾을 때 메인 노트의 본문 파일과 HTML 첨부도 읽지만 응답에는 안 싣는다 | 마지막 색인 |

메인 노트는 도구 표면에서는 늘 찾고, 명령 표면에서는 컨테이너가 메인 노트일 때만 찾는다. 컨테이너가 하위 노트면 명령 표면은 메인 노트를 아예 안 본다. 참조 사슬의 하위 조각을 검사할 때와 컨테이너가 하위 노트일 때 그 컨테이너를 다시 찾을 때도, 엔진은 그 하위 노트의 본문 파일을 읽는다. 읽은 값은 응답에 안 싣고, 그 읽기의 실패만 16.9의 9번처럼 명령에 닿는다.

직계는 색인의 직계 부모 칸으로 가린다. 컨테이너가 메인 노트면 그 칸이 빈 하위 노트를, 컨테이너가 하위 노트면 그 칸이 그 하위 id인 하위 노트를 고른다. 이 칸은 훑기가 `sub/`를 부모 먼저 적는 전위 차례로 돌며 정한 값이다(1.12).

차례는 색인에 적힌 `created` 글자(1.9의 꼴)의 바이트 차례이고, 같으면 하위 id 글자의 바이트 차례다(코드 읽기로 확인). 픽스처의 컨테이너는 직계 자식이 1개를 넘지 않아서 묶음이 이 차례를 안 잰다.

신선도는 9.5와 같다. 색인 뒤 디스크에 생긴 하위 노트는 안 나온다. 본문 파일은 색인의 경로와 포맷으로 고르고, 폴더 하위 노트면 `<path>/note.md`, `sub/` 바로 아래 옛 단일 파일이면 그 파일이다. 그 파일이 사라졌거나, 1,000,000바이트를 넘거나, UTF-8이 아니거나, 읽다 입출력 오류가 나면 원소는 메타로 나오되 `precondition`과 도장이 없고 `bodies=true`면 `"body": ""`다. 엔진은 그 파일의 `id`를 색인과 맞대지 않아서, 같은 경로에 다른 하위 노트의 파일이 들어서면 그 파일의 값이 섞인다(16.9). json 하위 노트는 본문 파일을 안 연다. 코멘트 파일은 안 읽는다. 원소마다 코멘트 파일을 더 열지 않으려는 것이고, 코멘트는 고치기 직전에 부르는 `get_sub_note`(11.8)가 싣는다.

## 16.6 응답

맨 위는 객체이고 키는 `parent`, `subNotes` 차례다. 바이트 규칙은 6.1과 같다.

| 차례 | 키 | 타입 | 뜻 |
|---|---|---|---|
| 1 | `parent` | 문자열 | 16.3의 2번으로 다듬은 조각을 `/`로 이은 참조 |
| 2 | `subNotes` | 배열 | 직계 하위 노트. 없으면 `[]` |

배열 대신 봉투를 쓰는 이유는 부모 참조를 함께 돌려주면 부르는 쪽이 다음 호출에 쓸 참조를 스스로 조립하지 않아도 되기 때문이다.

`subNotes`의 원소는 아래 차례의 객체다.

| 차례 | 키 | 타입 | 있는 조건 | 근거 |
|---|---|---|---|---|
| 1 | `id` | 문자열 | 늘. 하위 id만 | 묶음이 잰다 |
| 2 | `ref` | 문자열 | 늘. `<parent>/<id>` | 묶음이 잰다 |
| 3 | `type` | 문자열 | 늘 | 묶음이 잰다 |
| 4 | `title` | 문자열 | 늘. 공백뿐이면 하위 id(1.7) | 묶음이 잰다 |
| 5 | `created` | 문자열 | 늘 | 묶음이 잰다 |
| 6 | `date` | 문자열 | 늘 | 묶음이 잰다 |
| 7 | `time` | 문자열 | 늘 | 묶음이 잰다 |
| 8 | `mins` | 정수 | 늘 | 묶음이 잰다 |
| 9 | `editedBy` | 문자열 | 도장이 있을 때 | 코드 읽기로 확인 |
| 10 | `editedAt` | 문자열 | 도장이 있을 때 | 코드 읽기로 확인 |
| 11 | `editedSessionId` | 문자열 | 도장에 세션이 있고 `editedBy`가 정확히 `app`이 아닐 때 | 코드 읽기로 확인 |
| 12 | `format` | 문자열 | 늘 | 묶음이 잰다 |
| 13 | `precondition` | 문자열 | markdown이나 html이고 본문 파일을 읽었을 때 | 묶음이 잰다 |
| 14 | `body` | 문자열 | 명령 표면이고 `bodies=true`일 때 | 코드 읽기로 확인 |
| 15 | `links` | 배열 | 늘. 비면 `[]` | 묶음이 잰다 |
| 16 | `tags` | 배열 | 늘. 비면 `[]` | 묶음이 잰다 |
| 17 | `path` | 문자열 | 색인된 하위 노트에는 늘 | 묶음이 잰다 |

값 규칙은 `get_sub_note`(11.8)와 같다. `ref`는 이 하위 노트를 다음 호출의 `parent`로 줄 때 그대로 쓰는 참조다. 하위 노트는 메인 노트 안에서만 유일해서 자기 id 1개로는 못 가리키고, 그 규칙을 부르는 쪽이 몰라도 되게 여기서 이어 준다.

`tags`는 `list_docs`와 달리 비어도 싣는다. 하위 노트 목록에는 원래 `tags`가 없었는데, 하위 노트의 태그가 저장에서 사라지는 사고를 겪은 뒤 「태그가 없다」를 빈 배열로 또렷이 말하도록 넣었다. `agenda`와 `agendaTitle`은 없다. 부르는 쪽이 부모 노트를 통해 부르고 그 아젠다가 곧 하위 노트의 아젠다라서, 실으면 같은 값의 출처가 2곳이 된다. `sessionId`, `tier`, `favorite`, `favoriteCategory`, `template`, `evaluation`도 하위 노트에 없는 칸이라 없다(1.7).

`bodies=true`의 원소는 `get_sub_note` 응답에서 `parent` 대신 `ref`가 서고 `comments`가 빠진 것과 키 차례까지 같다. `body`가 `precondition` 뒤, `links` 앞에 서는 것이 그 차례를 맞추는 자리다. json 하위 노트는 `"body": ""`다. 메인 노트 목록과 달리 `attachText`는 없다.

픽스처 vault에서 `list_sub_notes '{"parent":"ndfixture-00000001"}'`은 이 바이트를 낸다(묶음이 잰다). 손자 메모 `snfixture-00000006`은 직계가 아니라서 없다.

```json
{
  "parent": "ndfixture-00000001",
  "subNotes": [
    {
      "id": "snfixture-00000001",
      "ref": "ndfixture-00000001/snfixture-00000001",
      "type": "free",
      "title": "후속 메모",
      "created": "2026-06-16T11:00:00+09:00",
      "date": "2026-06-16",
      "time": "11:00",
      "mins": 0,
      "format": "markdown",
      "precondition": "f1:595c8397b26b6e276b8802e60163e04d26a63fdd0d9609f0c176e5396bc9f1d3",
      "links": [
        {
          "to": "ndfixture-00000002",
          "kind": "attach"
        }
      ],
      "tags": [
        "후속",
        "랭킹"
      ],
      "path": "notes/serving/2026-06-16-1000-픽스처-노트-0001/sub/2026-06-16-1100-후속-메모-0001"
    }
  ]
}
```

그 자식을 컨테이너로 준 `list_sub_notes '{"parent":"ndfixture-00000001/snfixture-00000001"}'`은 손자를 낸다(예시 값, 코드 읽기로 계산). 값은 `get_sub_note` 묶음 케이스(11.8)와 같다.

```json
{
  "parent": "ndfixture-00000001/snfixture-00000001",
  "subNotes": [
    {
      "id": "snfixture-00000006",
      "ref": "ndfixture-00000001/snfixture-00000001/snfixture-00000006",
      "type": "free",
      "title": "손자 메모",
      "created": "2026-06-16T12:00:00+09:00",
      "date": "2026-06-16",
      "time": "12:00",
      "mins": 0,
      "format": "markdown",
      "precondition": "f1:093f0094cbb7bc34f3bcd96cef4341760573cafb67e1ce31357e44e1016a25b4",
      "links": [],
      "tags": [],
      "path": "notes/serving/2026-06-16-1000-픽스처-노트-0001/sub/2026-06-16-1100-후속-메모-0001/sub/2026-06-16-1200-손자-메모-0006"
    }
  ]
}
```

하위 노트가 없는 부모는 `subNotes`가 빈 배열이다. `list_sub_notes '{"parent":"ndfixture-00000002"}'`은 아래 바이트에 줄바꿈 1개를 낸다(묶음이 잰다).

```json
{
  "parent": "ndfixture-00000002",
  "subNotes": []
}
```

## 16.7 모양이 다른 대상

| 대상 | 응답 | 픽스처 | 근거 |
|---|---|---|---|
| 하위 노트가 없는 메인 노트 | `subNotes`가 `[]` | 0002, `ndbulk-` 101건 | 묶음이 잰다 |
| 단일 파일 메인 노트(`.md`, `.html`) | 하위 노트를 못 두는 모양이라 늘 `[]`다. 실패가 아니다 | 0007, 0004 | 묶음이 잰다 |
| json 메인 노트 | 아래 markdown 하위 노트를 그대로 낸다 | 0005, 0008 | 묶음이 잰다 |
| json 하위 노트 | `format`이 `json`이고 `precondition`이 없다 | 0003 아래 `snfixture-00000002` | 묶음이 잰다 |
| 손으로 바꾼 메인 노트 폴더 | `path`가 디스크 이름 아래다 | 0006 | 묶음이 잰다 |
| 같은 id 2벌의 메인 노트 | 이긴 쪽의 하위 노트만 본다. 진 쪽은 하위 노트째 색인에 안 든다 | 0024 | 코드 읽기로 확인(0024가 빈 목록인 것은 묶음이 잰다) |
| `sub/` 바로 아래 옛 `.md` 단일 파일 하위 노트 | 원소로 나오고 `path`가 `.md`까지다 | 없음 | 코드 읽기로 확인 |
| 직계 부모 하위 노트를 못 읽은 하위 노트 | 그 자손과 함께 색인에 없어 안 나온다(1.12) | 없음 | 코드 읽기로 확인 |
| 기록 층 메인 노트 | 도구 표면은 `WL-409`, 명령 표면은 보통처럼 낸다 | 없음 | 코드 읽기로 확인 |

## 16.9 받아들임 묶음과 얼어 있는 특이점

이 장에는 같은 장에서 다룰 짝 명령이 없어서 공통 절의 16.8은 두지 않는다. 하위 노트 1건 읽기 `get_sub_note`는 `get_doc`의 짝이라 11.8에서 다룬다.

묶음이 덮는 것은 도구 표면 111건이다. `list_docs '{}'`가 내는 메인 노트 110개를 1개씩 부모로 준 110건과 틀린 id 1건(`list_sub_notes/missing`, `{"parent":"nd없는노트"}`)이다. 실패 1건은 종료 코드 3과 빈 stdout만 맞대고 WL 번호는 안 본다. 중첩 참조, 직계 관계 실패, 층, 명령 표면의 `bodies`, 형제가 2개 이상일 때의 차례, 도장, 색인 낡음은 안 덮는다.

아래는 지금 엔진의 특이점이고, 표시의 뜻은 9.9와 같다. 지킬지 고칠지는 부록 D에서 정한다.

1. 도구 표면이 참조 사슬을 층보다 먼저 봐서, 기록 층 메인 노트 아래에서 있는 하위 id는 `WL-409`를, 없는 하위 id는 `WL-404`를 낸다. 응답 번호로 기록 노트 아래 하위 노트가 있는지 알 수 있다. 묶음 밖.
2. 조각의 앞뒤 공백을 떼고, `get_doc`은 id를 안 뗀다(11.9). 묶음 밖.
3. 형제의 차례가 순간이 아니라 적힌 `created` 글자다(9.9의 1번과 같은 성질). 묶음 밖.
4. 단일 파일 메인 노트를 부모로 주면 실패 대신 빈 목록이다. 묶음이 잰다(`list_sub_notes/ndfixture-00000004`, `list_sub_notes/ndfixture-00000007`).
5. `bodies`는 대소문자를 가린다. 묶음 밖.
6. 명령 표면은 층을 안 봐서 기록 층 메인 노트의 하위 노트도 낸다. 앱이 그 표면을 쓰고, 사람이 자기가 굳힌 노트를 못 보는 상태는 손실과 구별되지 않아서 둔 동작이다. 묶음 밖.
7. 메인 노트를 찾을 때 그 HTML 첨부까지 읽어서, 첨부를 읽다 입출력 오류가 나면 9.9의 11번처럼 명령 전체가 예상 밖 실패로 끝난다. 도구 표면은 늘, 명령 표면은 컨테이너가 메인 노트일 때만 이 읽기를 한다. 실행해 보지는 않았다. 묶음 밖.
8. 색인 뒤 같은 경로에 다른 하위 노트의 파일이 들어서면 그 파일의 본문, 토큰, 도장이 색인의 메타와 원소 1개에 섞인다(16.5). 다음 색인이 고친다. 색인 없는 구현은 9.9의 10번처럼 디스크대로 내도 된다. 묶음 밖.
9. 이 명령이 읽는 본문 파일 가운데 프론트매터에 1.8의 안 잡히는 표기(`mins: !!int abc` 같은 것)가 든 파일이 1개라도 있으면 명령 전체가 예상 밖 실패로 끝난다. 읽는 파일은 원소의 본문 파일, 참조 사슬과 컨테이너의 하위 노트 본문 파일, 그리고 7번이 말하는 때의 메인 노트 본문 파일이다. 9.9의 14번과 같은 뿌리다. 코드 읽기로만 확인했다. 묶음 밖.

# 3부 4단계: 메뉴·단축키·딥링크

2026-11-01. 제공된 「withlog 3부 화면 설명서」 4장(38~44쪽)의 진입 계약을 연결했다. [구현 순서](rebuild-p3-plan.md)의 4단계다.

## 메뉴와 키 입력

`wl://menu`는 `getCurrentWebviewWindow().listen`으로 현재 창에 온 것만 받는다. main 창은 메뉴 5개를 처리하고 노트 창은 `wl_close_tab`만 처리한다.

- 폴더 선택 취소는 조용히 끝난다. 선택하면 공통 vault 열기·최근 목록·캘린더 이동을 사용하고, 실패하면 알림과 런처를 보인다.
- 새 워크스페이스 메뉴는 현재 vault를 둔 채 `/launcher?mode=create`로 간다. 시작 화면으로 돌아가기는 떠나기 확인·회고 flush·감시 정리 뒤 노트 창 닫기를 기다리지 않고 보내며 직전 vault를 null로 적는다. 호스트의 vault 자리는 유지한다.
- 터미널과 탭 닫기는 vault가 열린 탭 틀에서만 처리한다. main·세션 셸의 닫기는 호스트 창 닫기 거절을 버리는 기존 동작을 유지한다. 노트 창 닫기는 저장 확인 훅 뒤 `destroy_current_window`로 간다.
- Cmd+K, Cmd+Shift+[·], Cmd+1~9를 연결했다. 다른 운영체제는 Ctrl, Alt 동시 입력은 무시한다. 대괄호·숫자는 물리 코드와 Numpad를 읽고 Shift+숫자는 무시한다. 이미 활성인 탭은 주소 기록을 더하지 않는다.
- 네이티브 Cmd+W는 메뉴만 맡고 브라우저에서만 키로 닫는다. Esc는 검색·하위 페이지·미리보기 차례로 처리하며 안쪽에서 막은 이벤트는 존중한다.

Cmd+K에는 현재 메모리의 노트를 찾는 최소 읽기 화면을 연결했다. 검색의 전체 순위·최근 검색·정규화는 13장, 하위 페이지의 전체 편집 동작은 11장, 터미널 셸 연결은 14장 범위다.

## 공통 링크 판정

대소문자·대상 디코딩·빈 ws·정확한 `window=1`·끝 빗금 거절은 4.4의 정규식을 따른다. 아젠다 링크는 slug를 쓴다. 한 묶음에서는 뒤에서부터 처음 해석되는 주소 하나를 고른다.

main 창에서만 live 플러그인 듣기를 먼저 설치하고 `getCurrent()`를 한 번 읽는다. 늦은 콜드 스타트 결과가 새 live·개발 입력을 덮지 않게 한다. 플러그인 JS는 Rust와 같은 2.4.9로 고정했다. 개발 HMR 다리와 초기 `?deeplink`도 같은 판정을 거친다.

부팅 중 링크는 기다린다. ws가 현재 경로와 글자로 다르면 `is_workspace`를 범위 허용보다 먼저 부르고, 떠나기 확인·허용·공통 열기·최근 목록을 수행한다. 공통 열기 안에서도 허용을 한 번 더 보낸다. 바꾸는 중 새 링크가 와도 vault 갱신은 끝까지 마치며 옛 대상은 열지 않고 최신 대상을 판정한다. 실패는 런처 알림, 떠나기 취소는 현재 화면 유지다.

`file://`는 로컬 Markdown만 받는다. 현재 vault와 방금 다시 읽은 최근 경로를 `resolve_md_target`에 넘긴다. 파일을 받은 순간부터 최신 입력으로 표시해 늦은 비동기 분류가 새 링크를 덮지 않게 한다. 호스트 거절은 조용히 버린다. 외부 파일도 열린 vault가 없으면 런처로 보내는 4.12의 동작을 유지한다.

하위 노트 사슬은 루트 주소로 도착하는 한 번을 허용하며, 이후 주소 전환은 페이지를 닫는다. 두 단계 사슬과 Esc로 한 단계씩 돌아가기를 실제 엔진에서 확인했다. 루트가 별도 창에 있으면 사슬을 만들지 않고 그 창을 앞으로 가져온다.

`window=1`은 이미 열린 창에 title:null을 보내고, 새 창은 노트별 flush·미저장 확인 뒤 제목을 보낸다. 이동 실패는 콘솔에 남기고 탭으로 연다. `withlog.noteWindow.v1`에서 유효한 평면 Geometry만 읽고 나머지는 null이다. 15~16장 본문이 없으므로 저장 형식 전체나 새 geometry 저장을 추측하지 않았다. 편집기·자동저장이 아직 없어 현재 제품의 저장 확인 훅은 빈 구현이며 이후 단계에서 실제 쓰기 상태에 연결한다.

## 개발 서버 다리

`POST /__deeplink`는 POST 이외 405, 4,096바이트 초과 413, 빈 본문·잘못된 withlog 주소·file 주소 400, 연결 페이지 없음 503, 전송 성공 200이다. UTF-8 바이트 수로 제한한다. HMR에 붙은 화면 모두에 보내고 main만 받는다. 생산 빌드 JS에서 `__deeplink`와 `withlog:deeplink`가 제외된 것도 확인했다.

## 검증과 남은 손 확인

- `pnpm test:interaction`: 메뉴·키·파싱·최신 입력·콜드 스타트 경합·창 이동·HTTP 경계 30개 통과.
- `pnpm test:interaction:acceptance`: 실제 WKWebView·Java 엔진에서 창별 메뉴, 새 창 닫기 격리, live 링크, 두 단계 하위 노트, 외부 md, 경로 글자 차이, 잘못된 vault, 런처 동작 10개와 디스크 점검 1개, 총 11개 통과.
- 기존 workspace 9개와 navigation 11개의 WKWebView 회귀 점검 통과.
- `bash test-native.sh`: 화면 빌드 6개, workspace·이관 26개, navigation 25개, interaction 30개, 설정 3개, Rust 65개 통과. Rust 하위 실행용 1개는 원래대로 ignored다.
- `pnpm install --frozen-lockfile` 및 `pnpm tauri build --debug --bundles app` 성공.
- Ego 브라우저에서 개발 초기 쿼리, Cmd+K 검색·Enter·Esc, 탭 순환·번호 키, 실제 HMR POST 전송과 화면 이동을 확인했다. 붙은 페이지가 없을 때의 실제 Vite 503도 확인했다.

테스트 앱은 별도 식별자·임시 HOME·vault·소켓을 사용한다. Tauri 2.11.2의 이벤트 송신 deny는 같은 local origin의 main에도 적용되어 JS 주입을 막았다. interaction 하네스만 두 송신 deny를 제외한 임시 capability를 사용한다. 제품 권한 파일은 유지하고, Rust의 기존 창별 송신 시험과 실제 WebView의 창별 수신 시험을 함께 사용한다.

WKWebView 하네스는 빌드 산출물을 devUrl로 제공한다. 실제 메뉴 클릭·가속키 전달, macOS 파일 연결, 종료된 번들의 콜드 스타트 URL 전달과 실제 번들 프로토콜 CSP는 이번 자동 점검 범위와 구분한다. OS 닫기 요청 전체 처리와 편집 글 flush는 15장 범위이며 메뉴 닫기의 빈 저장 훅만으로 완성했다고 보지 않는다.

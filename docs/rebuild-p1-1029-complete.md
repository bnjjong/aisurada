## 고친 것

### 1. AtomicWriter 2곳

공용 쓰기 도우미 `write/AtomicWriter`가 설명서 7.4와 다른 자리 2곳이다. vault에 쓰는 명령은 모두 이 부품을 지나서, `write_attachment`뿐 아니라 `create_doc`, `update_doc`, 메타 쓰기 3개, 하위 노트 쓰기 3개도 함께 고쳐진다.

| 사례 | 설명서 7.4 | 고치기 전 | 고친 뒤 |
|---|---|---|---|
| `attach/<이름>` 자리가 빈 폴더 | 4번: 원자적 이름 바꾸기가 실패하면 임시 파일을 지우고 `WL-500 파일을 쓰지 못했다: <대상 파일>` | 원자적이 아닌 옮기기로 다시 해서, JDK가 빈 폴더를 지우고 파일을 둠. 종료 코드 0 | 다시 하지 않음. 종료 코드 3, 그 문구. 폴더는 그대로 |
| `attach` 자리가 일반 파일 | 1번: 부모 폴더를 못 만들면 `WL-500 폴더를 만들지 못했다: <대상의 부모 폴더>` | 부모 자리에 무엇이든 있으면 만들기를 건너뛰어 `파일을 쓰지 못했다: <대상 파일>` | 부모가 폴더가 아니면 만들기를 해서 1번 문구 |

- 빈 아닌 폴더와 하위 노트의 `attach`도 같은 문구로 서고, 임시 파일은 안 남는다.
- `attach` 자리의 끊긴 심볼릭 링크는 전에도 지금도 1번 문구다. 폴더를 가리키는 링크는 따라가서 폴더로 본다.

### 2. 시험용 세션 속성

- `withlog.test.session.id`를 엔진(`engine/EngineExecutor`)에서 뺐다.
  - 이 속성은 13장에서 정한 시험용 속성 2개에 없던 것을 단발 시험을 돕자고 더한 것이었다.
  - 주면 세션 표식이 없는 도구 표면 쓰기에도 세션 id를 찍었다. 4.4와 1.10이 정한 동작을 바꾸는 값이라, 지난번처럼 README에 밝히는 것으로는 부족하다고 봤다.
- 세션 표식은 이제 4.4대로 argv 끝 2칸으로만 받는다. 실제로는 `wl-cli`가 소켓 요청에 싣는다.
- 도장의 세션 값을 재는 시험은 표식을 실어 부르게 바꿨다.
  - 운영체제 argv에는 U+0000을 못 싣는다. 그래서 같은 JVM 안에서 표식 2칸을 argv 끝에 붙여 엔진 `Main`을 부르는 작은 실행기를 쓴다. 이 실행기는 엔진 jar에 안 든다.
  - 자가 시험 13·14·15·17장, 검증 `round14`·`round17`이 이 길로 바뀌었다.
  - 소켓으로 오는 표식은 전처럼 `round13`(13.6 예시 1)과 `round15`(15.6 예시 2)가 serve 모드로 잰다.
- `withlog.test.now`, `withlog.test.random`은 둔다. 13장에서 사용자가 정한 것이고, 시각과 무작위 조각만 고정할 뿐 계약 동작을 고르지 않는다. `wl-cli`의 `withlog.launchctl.cmd`도 둔다. 확인 노트의 `cli8.sh`가 이것으로 가짜 launchctl을 넣는다.

## 그대로 둔 것

### E21w

- 이미 색인된 vault에서 코멘트 파일이 깨지면, 지금 엔진은 옛 색인 행으로 계속 쓰고 새 구현은 쓰기를 모두 종료 코드 1로 세운다.
- 색인이 없는 구현은 vault가 이미 색인됐는지 알 수 없어서 늘 새 색인 쪽으로 답할 수밖에 없다.
- 설명서 8.6 표의 코멘트 파일 줄과 표 뒤 문단은 부록 D가 정할 때까지 이 차이를 허용한다. 그래서 코드를 안 바꿨다.
- 확인 노트가 적은 대로, 6번 수정 뒤에는 같은 vault의 읽기에서도 그 노트가 빠진다. 색인 없는 구현은 앞선 맞추기가 남긴 옛 행을 흉내 낼 수 없다고 8.6 표 마지막 줄이 적은 자리다.

### 설명서 고칠 곳 5곳

- 짓는 쪽이 가진 설명서 사본에는 10차(1~3번)와 13차(4·5번)에 모두 들어 있다. 이번에 8.6 표와 표 뒤 문단을 다시 확인했다.
- 의뢰자 쪽 원고와 vault의 설명서 노트에 옮기는 일은 의뢰자 몫이라 하지 않았다. E21w를 계약으로 정할지도 그쪽 부록 D에서 정한다.

## 다시 확인하는 법

```sh
# aisurada를 빈 폴더에 받아 빌드
git clone https://github.com/bnjjong/aisurada.git && cd aisurada && ./build.sh

# V는 .withlog/workspace.json이 있는 vault 사본(실사용 vault 말고)
# 확인 노트의 18장 사례: attach 자리에 빈 폴더를 두고 쓰기
mkdir -p "$V/notes/serving/<노트 폴더>/attach/busy.svg"
java -jar dist/wl-engine.jar write_attachment '{"parent":"<노트 id>","name":"busy.svg","content":"x"}' --withlog.vault="$V"
# → 종료 코드 3, WL-500 파일을 쓰지 못했다: <절대 경로>/attach/busy.svg, 폴더는 그대로

# 시험용 세션 속성은 이제 아무 일도 안 한다
java -Dwithlog.test.session.id=x -jar dist/wl-engine.jar create_doc '{"agenda":"serving","type":"plan","title":"t","body":"b"}' --withlog.vault="$V"
# → 새 note.md에 sessionId 줄이 없다
```

검증 스크립트(`review5.mjs`가 이번 회차)와 기록 `spec-gaps-14차.md`는 설명서 문장이 들어 있어서 이 저장소에 올리지 않았다.

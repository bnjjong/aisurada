# 31장 완료 — vault git과 노트 이력

작성일: 2026-10-30

제공받은 31장 설명서를 기준으로 자동 커밋을 점검하고 `history`, `commit-vault`, 선택적인 옛 스냅숏 저장을 연결했다. 두 명령은 명령 표면에만 있으며 워크스페이스 표식과 노트 색인을 요구하지 않는다.

## 구현

- 기존 `VaultGit`의 시작·종료·유휴·15분 경과·작성자 전환 커밋과 대기 기록, git 잠금과 재시도, 작성자와 꼬리 줄, 훅과 서명 비활성화 및 임시 파일 제외를 유지했다. 잠금의 수정 시각을 읽지 못하는 경우에도 건너뛰도록 보완했다.
- `commit-vault`는 재시도 시각을 기다리지 않고 `restore` 사유로 시도한다. 결과는 `committed`, `nothing`, `skipped`, `disabled`, `failed`와 필요한 `blocked` 값으로 낸다. git 실패는 명령 실패가 아니다.
- `history`는 현재 추적 경로의 `git log --follow`, 커밋의 `Withlog-Notes` 꼬리 줄, 노트별 옛 스냅숏을 모은다. blob 확인 후 시각순으로 정렬하고 이웃한 동일 blob만 접는다. 판 번호와 커밋 선택, 본문 검색, 편집 도장과 세션, 응답 키 순서를 구현했다.
- `WITHLOG_VAULT_SNAPSHOT_ENABLED=true`일 때 노트와 하위 노트 본문을 덮기 직전에 옛 바이트를 `refs/withlog/snapshots/<id>`에 저장한다. 메타 쓰기, 폴더 이동 뒤 본문 쓰기, 코멘트·하위 카드의 파생 쓰기도 포함한다. 기본값은 꺼짐이며 읽기는 설정과 무관하다.
- 일반 git은 vault 환경을 고정하고 출력을 동시에 읽어 60초 뒤 종료를 요청한다. 옛 스냅숏 git은 환경을 상속하고 종료 후 출력을 읽으며 5초 제한을 따른다. `cat-file` 배치는 파일 크기를 바이트로 해석해 LF와 NUL이 본문에 있어도 다음 항목을 정확히 읽는다.

## 검증

`bash test.sh` 전체가 통과했다. 기존 자동 커밋 126개, 이력 배치와 오류·스냅숏 실행 규약 46개, 31장 명령 347개, 실제 serve·wl-cli 왕복 36개를 포함한다. 임시 저장소에서 수동·자동 커밋, 이동과 삭제, 선택과 검색, 작성자·세션 전환, 유휴와 종료 커밋, 잠금과 git 실패, 스냅숏 생성 및 비활성화 후 조회를 확인했다. 잘못된 설정과 실패를 의도적으로 재현한 시험의 경고와 스택 트레이스는 정상이다.

## 유지한 경계

명세의 31.7을 따른다. 이력은 현재 경로가 `note.md`로 끝나는 경우와 꼬리 줄에 실린 판, 스냅숏을 찾는다. 큰 내용 변경과 함께 이동해 git의 이름 바꿈 판정이 끊기고 꼬리 줄도 없는 이전 수동 커밋은 찾지 못할 수 있다. 삭제 커밋 자체는 파일 blob이 없어 판에서 빠진다. git 실패는 빈 이력으로 나타나며, `history`는 앱 도장에도 세션을 실을 수 있다. 유니코드 숫자 검사, 이웃 blob만 접는 규칙, 옛 스냅숏의 환경 상속과 출력 파이프 제한도 유지했다.

실제 git과 엔진을 이용한 독립 검증이며 원본 엔진과의 차등 실행은 아니다. 이 구현의 기존 색인 비영속 차이는 다른 장의 완료 문서에 기록돼 있다.

- 다른 세션의 `9cf4dde`가 그 사이 C112, C110, C188을 먼저 손댔다. 이 증분은 그 코드를 「고치면」과 맞대 보고 모자란 곳을 채웠다.

### 증분이 정한 것

- **C188 짝짓기 함수.** `data/mdInline.ts`의 `plainInline`은 화면 계층이 아니라 데이터 계층에 둔다. 스토어 시험(`node --experimental-strip-types`)이 편집기 모듈을 못 읽기 때문이다. 증분 4(C178)에서 편집기 들여오기의 글자 서식 짝짓기를 이 함수 쪽으로 모아 한 벌로 만든다.
- **C188 맨 앞 인라인 코드.** 헤딩이 인라인 코드로 시작하면 편집기는 그 코드 안의 이스케이프를 푼다(9.5의 「알려진 손실」, 지킨다). 제목 뽑기는 CommonMark대로 코드 안을 안 푼다. 그래서 `# `a\.b` 뒤` 같은 헤딩은 첫 저장에서 본문이 바뀌고, 제목도 그 본문을 따라 바뀐다.
- **C119 2단계 글.** 플랜은 「2단계가 래퍼를 쓰는 명령을 직접 적고, `install`에는 `--cli`와 `--sidecar`로 앱 번들의 jar를 준다(12.12)」로 정했다. 12.12 최신판이 없어서 명령은 이 저장소의 `InstallCommand`가 jar를 까는 자리(`~/Library/Application Support/withlog/bin`)와 번들 자리(`Contents/Resources`)로 썼다.
- **C193 가두는 범위.** 지금 앱은 00:00~(23:00 − 소요 시간)으로 가두는데, 다시 지은 화면은 00:00~23:45로 가둔다. 그 범위는 바꾸지 않았고 방향 규칙만 더했다. 화살표의 15분 격자 반올림은 3부 리뷰 1차가 12.4와 다르다고 적은 자리라서 함께 고쳤다.

### 점검을 짓다가 본 것

- C57 점검은 처음에 기존 템플릿 점검 앞에 뒀다. 그러자 템플릿 편집기에 남은 선택 때문에 뒤의 템플릿 점검과 화면 이동이 멈췄다. 그래서 C57 점검은 views 맨 끝에서 엔진으로 템플릿을 새로 만들어 잰다.
- 그 과정에서 템플릿 저장(`saveTemplate`)이 쓰기 줄을 서지 않는 것을 봤다. 같은 템플릿의 저장 둘이 겹치면, 늦게 끝난 앞 저장이 메모리 값을 덮을 수 있다(코드 읽기로 추정, 재지 않음). 38줄 밖이라 고치지 않았다.
- C112 점검은 소요 시간을 바꾸므로, 끝에서 뒤의 이력 점검이 기대하는 35로 돌려 둔다.

## 3. 그대로 둔 것

- 번호 목록 밑에 들여쓴 글머리 줄은 들여올 때 따로 선 목록이 된다(C72). 증분 3에서 고친다. C190 시험은 같은 종류의 중첩으로 쟀다.

- 일 보기의 가두는 범위(23:45와 23:00 − 소요 시간)는 그대로다.

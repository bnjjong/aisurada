# Rust 엔진 이전 4단계 4e — 노트 잔여 명령 7개

## 요약

**결론:** 노트 잔여 명령 8개 가운데 7개(`write_attachment`, `export_markdown`, `shard_notes`, `verify_shard`, `plan_day`, `check_notes`, `facts_brief`)를 Rust 엔진으로 옮겼다. 마지막 하나 `reindex_paths`(지정한 경로만 다시 훑는 명령)는 앱이 부르지 않고 `ais-cli`만 쓰므로 **5단계에서 `ais-cli`와 함께** 옮긴다. Java 엔진과 합성 vault에서 **응답과 폴더 전체 바이트가 2,488건 모두 같다**(앞 묶음 포함, 1,042단계, 이 가운데 노트 도구는 64단계). 이 명령들은 앱 화면이 직접 부르지 않고 AI 도구와 `ais-cli`가 쓴다. 쓰기 명령은 스위치(`AISURADA_ENGINE_WRITE=rust`)가 켜질 때만 Rust로 가고, `verify_shard`만 읽기다.

전체 계획은 [4단계 계획](rust-engine-step4-plan.md)에 있고, 이 기록은 [4d 세션 읽기 기록](rust-engine-step4d-sessions.md)에 이어진다.

## 1. 하는 일

| 명령 | 하는 일 |
| --- | --- |
| `write_attachment` | 노트나 후속 노트의 `attach/`에 글 첨부 하나를 쓴다(18.8). 글 확장자(`svg`, `html`, `md`, `txt`, `json`, `csv`, `yaml` 따위 12가지)만 받고 같은 이름이면 덮는다. 이름 규칙(길이 120자, 경로 구분자, `..`, 점 시작, 제어 문자, 확장자)은 처음 걸린 하나만 알린다. 폴더로 안 올라간 단일 파일 노트에는 둘 수 없다 |
| `export_markdown` | 읽기 층 메인 노트의 마크다운 본문을 `.aisurada/md-export/`에 내보낸다(27장). 매번 그 폴더를 지우고 새로 쓰고, HTML·JSON 노트와 안전하지 않은 경로는 세어서 건너뛴다 |
| `shard_notes` | 색인에 들지 못한 노트까지 디스크에서 모아 월별 폴더 배치(`notes/<아젠다>/<연-월>/…`)로 옮길 계획을 세운다(28장). 인자 없이 부르면 계획만(`.aisurada/migration/shard-plan.tsv`), `apply=true`면 옮기고 회차마다 `shard-map-<시각>.tsv`를 남긴다. 옮긴 뒤 크기가 다르면 중간에 세운다 |
| `verify_shard` | 이동 전 매핑 파일의 파일 수·바이트 합과 현재 디스크를 대조한다. 어긋나도 오류가 아니라 `ok: false`로 답한다. 기준값 파일이 여럿이면 어느 회차인지 `file=`로 정하게 한다 |
| `plan_day` | 직전 기록일과 오늘의 초안(`# <날짜> 데일리 플랜`)을 짓고, 아젠다를 주면 `create_doc`과 같은 길로 저장한다(29장). `dryRun=true`면 저장하지 않는다 |
| `check_notes` | 마지막 코멘트와 마지막 변경을 각자의 오프셋으로 비교해 「답 없는 코멘트」를 최근 14일 안에서 찾는다(30장) |
| `facts_brief` | 창(`from`~`to`, 기본 최근 7일) 안의 읽기 층 메인 노트를 아젠다별로 세고, 사실층 파일을 붙여 프롬프트 절을 짓는다(22.5, 22.6) |

| 부품 | 자리 |
| --- | --- |
| 명령 | `commands/{write_attachment,export_markdown,shard_notes,facts_brief,daily_notes}.rs` |
| 폴더 크기 | `vault/file_size.rs`(파일 수와 바이트 합. 폴더 링크는 내려가지 않고 파일 링크는 대상 크기로 센다) |
| 사실층 읽기 | `vault/facts.rs`의 `read_facts`(상한 2,000자, 넘으면 안내 문구) |
| 쓰기 범위 공유 | `commands/doc_create.rs`의 `create_doc_in`: 이미 쓰기 범위를 잡은 `plan_day`가 같은 길로 노트를 만든다 |

## 3. Java와 다르게 둔 것

- **`reindex_paths`는 옮기지 않았다.** 지정한 경로만 훑는 부분 훑기는 훑개 안쪽을 더 바꿔야 하고, 앱이 쓰지 않아서 `ais-cli`를 옮기는 5단계에서 같이 한다.
- **사실층 읽기.** Java는 엄격한 UTF-8로 읽다 깨지면 사실층이 없는 것으로 보지만, Rust는 대체 글자로 읽는다(깨진 사실층 파일에서만 다르다).
- **깨진 UTF-8, UTF-16 자르기.** 4d와 같다(대체 글자 수, 경계의 이모지).
- **시각 읽기.** `check_notes`의 `editedAt`, 코멘트 시각, `created`는 흔한 ISO 모양(4자리 연도, `Z`나 `+09:00`)만 읽는다.
- **안내 줄.** Java가 표준 오류로 내는 진단 줄(이동이 중간에 선 까닭, 색인을 못 맞춘 일)은 Rust가 내지 않는다. 응답의 `stoppedAt`은 같다.
- **쓰기 범위.** `facts_brief`, `check_notes`, `plan_day`, `export_markdown`은 Java가 쓰기 명령으로 다뤄서 Rust도 쓰기 범위(잠금과 색인 맞추기)를 잡고 쓰기 스위치를 따른다. `verify_shard`만 읽기다.
- **같은 이름·같은 시각의 플랜을 두 번 저장**하면 Java는 색인 저장 자리 충돌로 실패하고(`create_doc`의 id 꼬리가 같은 드문 경우) Rust는 새 폴더 이름을 골라 저장한다. 시험에서 빼고 넘어갔다.

## 4. 확인하지 못한 것과 남은 일

- **실제 앱 창에서 확인하지 못했다.** 이 명령들은 화면이 아니라 AI 도구와 `ais-cli`가 쓰므로 손 확인 점검표에는 넣지 않았다.
- 큰 vault에서 `shard_notes apply=true`의 속도와 도중 중단(다른 주체가 같은 시각에 고치는 경합)은 시험하지 않았다(이슈 #63).
- 다음은 5단계(JVM 제거)다: `ais-cli`, MCP 서버(`cli/`), 사이드카(`serve/`)를 Rust로 바꾸고 `reindex_paths`를 함께 옮긴다.

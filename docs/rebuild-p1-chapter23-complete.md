# withlog 1부 다시 짜기 23장 완료 — init-workspace

작성일: 2026-10-29

설명서 23장의 `init-workspace`를 지었다. vault 폴더 1개에 골격 폴더를 만들고, 자리가 빈 템플릿만 심고, 맨 마지막에 표식 파일 `.withlog/workspace.json`을 없을 때만 쓴다. 명령 표면에만 있고 `init_workspace`는 모르는 명령이다. 기준 판은 21장 커밋 `62c0d41`이다.

## 지은 것

| 파일 | 하는 일 |
|---|---|
| `cmd/InitWorkspace` (새 파일) | 23.1의 4번부터 7번. `templates` 모양과 `name` 검사, 골격 폴더, 값 검사, 문서 다음 리추얼 차례로 심기, 표식 쓰기 |
| `write/TemplateFileBytes` (새 파일) | 2.4의 템플릿 쓰기 바이트(`---\n`, 1.9의 YAML, `---\n`, 본문)와 파일 자리 |
| `args/ArgsParser`, `cmd/CommandRegistry`, `engine/EngineExecutor` | 옵션 `name`, `templates`와 자리 인자 0칸, 지은 명령 목록, 실행 분기 |

일하는 차례는 이렇다.

1. 인자 가르기(5.2). 모르는 옵션이 자리 인자보다 먼저이고, 같은 옵션은 뒤엣것이 이긴다.
2. 쓰기 파이프라인이 색인 맞추기와 vault git 쓰기 앞 처리를 한다. 표식 확인은 이 명령만 건너뛴다(이미 `WritePipeline`에 있던 갈래).
3. `templates` 모양을 본다. 기존 `JsonReader`가 kotlinx.serialization 1.6.3 기본 설정과 같은 규칙(따옴표 없는 값은 리터럴, 같은 키는 뒤엣것, 키는 큰따옴표, 끝 쉼표와 뒤에 남는 글은 오류)이라 그대로 썼다. 항목 64개 상한, 항목마다 객체인지, `category`, 모르는 키(정렬해서 적음), 칸 차례로 본다. 다음에 공백뿐인 `name`을 본다.
4. 골격 폴더 4개를 차례로 만든다. 자리가 폴더가 아니면 만들려던 골격 폴더의 절대 경로로 `WL-500`이다.
5. 문서 항목 모두, 다음 리추얼 항목 모두의 값을 본다(id 모양, 이름, 포맷, 유형, rev, 아이콘).
6. 문서 항목을 받은 차례로 심는다. 쓰는 차례에 경로 안전 검사를 하고, 다음에 자리가 차 있는지 본다. 다음에 리추얼 항목을 `<rev>.md`에 심는다. 리추얼 id는 경로 안전 검사를 안 받는다.
7. 표식 자리가 비었으면 `{"schemaVersion": 1, "name": …, "createdAt": …}`를 쓴다.

## 설명서가 정하지 않아 짐작한 것

- **「자리가 차 있다」**: `Files.exists`로 묻는다. 링크를 따라가서, 끊긴 링크와 권한 때문에 판정이 실패한 자리는 빈자리다(0.3의 표와 같다). 대소문자나 정규화만 다른 이름은 파일 시스템이 정한다.
- **기본 이름**: 엔진이 뜰 때 정리한 vault 경로(`EngineConfig.normalizedVault`)의 마지막 조각이고, 뿌리가 `/`면 빈 글이다.
- **표식 바이트**: 6.1과 같은 들여쓰기 2칸의 JSON에 끝 줄바꿈 1개다. 이름의 따옴표와 역슬래시는 JSON 탈출로, 짝 없는 서로게이트는 19.8의 파일 규칙(소문자 `\ud83d`)으로 적는다. `createdAt`은 시험용 시계(`withlog.test.now`)를 따른다.
- **템플릿 본문의 짝 없는 서로게이트**: 다른 파일 쓰기처럼 UTF-8로 바꿀 때 `?`가 된다. 이름과 설명은 1.9가 큰따옴표 탈출로 지킨다(24.5가 적은 지금 엔진의 동작과 같다).

## 23.9의 특이점

부록 D가 정하기 전이라 9가지 모두 지금 엔진과 같게 냈고, 자가 시험이 그 동작을 잰다.

| 번호 | 동작 | 이 판 |
|---|---|---|
| 1 | 문서 id의 경로 안전 검사(`..a`, `.x`, 101~128자)는 쓰는 차례에 서서 앞 항목이 이미 심긴다 | 같음 |
| 2 | 값이 틀린 호출도 골격 폴더 4개를 남긴다 | 같음 |
| 3 | 같은 id의 옛 html 옆에 md를 심어 2벌을 만든다 | 같음(픽스처 `t-legacy`로 확인) |
| 4 | 리추얼 `format: json`을 쓰지만 읽을 때 html | 같음 |
| 5 | 워크스페이스 이름을 다듬지 않는다 | 같음 |
| 6 | 색인 맞추기와 git 처리가 검사보다 먼저라 맞추기를 세우는 vault에서는 골격도 못 갖춘다 | 같음. 이 판은 색인이 없어 쓰기 앞 훑기가 같은 자리(같은 slug를 다른 id로 쓰는 아젠다 파일 등)에서 예상 밖 실패(종료 코드 1)로 선다 |
| 7 | 표식은 자리가 차 있는지만 본다. 폴더도 표식이다 | 같음 |
| 8 | 리추얼 id는 경로 안전 검사를 안 받아 심기고, 다음 목록에서 빠진다 | 같음 |
| 9 | 템플릿 이름도 다듬지 않고 쓰고 읽을 때 다듬는다 | 같음 |

## 시험

다른 작업이 같은 작업 트리에서 25~30장을 짓고 있어서, 23장 변경만 든 별도 worktree에서 빌드하고 개발 폴더 사본에 그 jar를 넣어 돌렸다. 쓰기는 모두 임시 폴더·HOME에서 했고, 실제 vault와 launchd는 쓰지 않았다.

| 시험 | 결과 |
|---|---|
| 새 자가 시험 23장 | 91/91 |
| 자가 시험 전체(`run.mjs`, 23장 포함) | 1,127/1,127 |
| 검증 스크립트 21개(`withlog-p1-verify`) | 1,995/1,995 |
| 저장소 `bash test.sh` | 19장 362, reindex-paths 133, 22장 554, vault git 104 |

검증 스크립트 `round3`의 「지은 명령」 목록(C1)에 `init-workspace`를 더했다(60개 → 61개). 더하지 않으면 그 명령이 `WL-409`가 아니라서 어긋남으로 센다.

새 자가 시험 `selftest/test_chapter23_init_workspace.mjs`(개발 폴더 `withlog-p1-rebuild`)가 재는 것은 이렇다.
- 23.2와 23.3의 칸 가르기: 밑줄 이름, 모르는 옵션, 자리 인자(`=x` 포함), 모르는 옵션이 자리 인자보다 먼저, 옵션 이름 다듬기, 같은 옵션은 뒤엣것
- 23.6의 예시 3가지: 빈 폴더(응답과 표식 바이트), 템플릿 2개를 심은 응답과 파일 바이트(리추얼은 픽스처 `morning.md`와 같은 바이트), 픽스처 vault의 `created: false`와 `skipped` 2개. 다시 부르면 표식의 이름과 시각이 안 바뀜
- 템플릿 차례(문서 다음 리추얼, 갈래 안은 받은 차례), html과 json 문서의 확장자와 `---` 울타리, 빈 `desc`의 `''`, 리추얼 키 차례
- 모양 검사: 배열이 아님(빈 글, 객체, 끝 쉼표, 뒤에 남는 글, 따옴표 없는 키), 64개와 65개, 객체가 아님, `category`의 없음·리터럴·모름, 모르는 키 정렬, 칸 차례, 숫자 리터럴, `builtin`의 `"true"`·`True`·없음, 배열 차례, `templates`가 `name`보다 먼저, 서면 vault가 그대로임, 같은 키는 뒤엣것
- 값 검사와 차례: 문서 항목이 리추얼보다 먼저, 골격만 남고 앞의 바른 항목도 안 씀, id(한글, 빈 글, 129자, 끝 LF), 이름, 포맷 대소문자, 유형을 안 다듬음, rev, 아이콘
- 23.9의 1번(쓰는 차례의 경로 안전 검사, 차 있어도 `WL-400`, 고쳐서 다시 부르면 마저 끝남), 3번, 4번, 5번, 6번, 7번, 8번, 9번
- 23.5와 23.7: 같은 자리 항목 2개, 끊긴 링크 자리, 표식 자리가 폴더, 골격 자리가 일반 파일(`.withlog/templates`, `notes`), 노트가 있는 옛 vault, 이름의 JSON 탈출

받아들임 묶음과 쓰기 축은 이 명령을 부르지 않아서(23.9), 이 시험은 모두 설명서 값과 맞댄 것이다. 지금 엔진(Kotlin 사이드카)과 맞대지는 않았다.

## 그대로 둔 것과 정할 것

- 설명서 23.9 끝의 「정할 것」(1번·2번·6번의 차례를 고쳐 모든 검사를 첫 쓰기 앞으로 모을지, 3번에서 같은 id의 다른 확장자를 차 있는 자리로 볼지, 8번에서 리추얼 id에도 경로 안전 검사를 걸지)은 의뢰자 몫이라 손대지 않았다.
- 24장(템플릿 명령 5개)은 이번 요청에서 빠졌다. `write/TemplateFileBytes`는 2.4의 쓰기 바이트를 1.9 쓰개로 짓는다. 그래서 빈 설명은 `desc: ''`, 앞뒤 공백이 든 이름은 `name: ' a '`이다(설명서 2.4와 24.5, 24.9의 15번이 적은 바이트).

기록은 개발 폴더의 `spec-gaps-17차.md`에 있다.

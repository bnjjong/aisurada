# 2부 7장 완료 — 파일 커맨드 두 개

작성일: 2026-10-30

제공받은 PDF 35~37쪽을 기준으로 `write_attachment_bytes`와 `open_in_default_app`을 구현하고 Tauri invoke 처리기에 등록했다.

첨부 쓰기는 헤더와 바이트 본문을 읽은 뒤 현재 vault를 확인하며, 파일 처리는 main 밖 일꾼에서 수행한다. vault와 note-dir를 canonicalize하고 파일 이름 마디·숨김 이름·그림 확장자·notes/ 경계·attach/ 경계·크기 순서로 검사한다. SVG, PNG, JPG, JPEG, GIF, WebP, AVIF, BMP를 대소문자 구분 없이 받으며 실제 그림 형식은 해석하지 않는다. 5,000,000바이트까지 받고 초과하면 attach 폴더도 만들지 않는다. 같은 파일은 직접 덮어쓰고 vault 상대 경로를 반환한다.

기본 앱 열기는 실재 경로가 현재 vault 안인지 검사한 뒤 `.app` 디렉터리, 실행 권한이 하나라도 있는 파일, command/tool/terminal/jar/py 확장자 파일을 거절한다. 심볼릭 링크는 실재 경로를 기준으로 판단한다. 나머지는 opener 플러그인의 경로 열기에 넘긴다. HTML·SVG 확인 대화 상자는 화면 몫으로 남긴다.

Rust 테스트 44개와 설정 테스트 3개가 통과했다. 테스트에는 실제 Tauri IPC를 통한 main·노트 창 호출, raw/JSON 바이트, 한글 헤더, 헤더·본문 검사 순서, 8개 확장자, 빈 파일과 정확한 크기 경계, 덮어쓰기, attach 생성·쓰기 실패, 휴지통·형제 경로·노트 폴더의 바깥 심볼릭 링크 거절, 실행 파일 종류와 권한 비트가 포함된다. 기본 앱을 실제로 띄우지는 않고 허용 경로 판정과 거절을 검사했다. macOS `.app` 빌드도 확인했다.

문서의 경계를 유지한다. note-dir가 실제 노트인지 검사하지 않아 notes/ 자체와 아젠다 폴더에도 쓸 수 있다. 임시 파일을 거치지 않아 쓰기는 원자적이지 않다. note-dir까지는 실재 경로를 확인하지만 그 뒤 구성한 attach/와 대상 파일을 다시 canonicalize하지는 않는다. 따라서 기존 대상 심볼릭 링크는 직접 쓰기가 따라간다. 이 경계는 테스트 소유 임시 파일로 확인했다.

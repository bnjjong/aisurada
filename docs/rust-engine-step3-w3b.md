# Rust 엔진 이전 3단계 W3b — `create_doc`(새 노트 만들기)

## 요약

**결론:** 새 노트를 만드는 `create_doc`을 Rust 엔진으로 옮겼다. 아젠다 찾기·만들기, 날짜와 시각 배정, 노트 폴더 쓰기, 경고를 한 번에 하는 명령이다. Java 엔진과 합성 vault에서 **응답과 폴더 전체 바이트가 694건 모두 같다**(앞 묶음 포함, 347단계, 이 가운데 `create_doc`은 72단계). 쓰기 스위치(`AISURADA_ENGINE_WRITE=rust`)는 기본 꺼짐이라 앱의 동작은 그대로다. 실제 창 확인은 아직 못 했다([손 확인 안내](rust-engine-hand-check.md)).

[W3a 기록](rust-engine-step3-w3a.md)에 이어진다. 남은 W3은 후속 노트 쓰기 3개(`create_sub_note`, `update_sub_note`, `delete_sub_note`)다.

## 1. 하는 일

```
인자 검사 → 아젠다 찾기(없으면 만들기) → 날짜·시각 배정 → 경고 모으기 → 폴더 자리 계산 → 머리 짓기 → 쓰기 → 응답
```

| 단계 | 규칙 |
| --- | --- |
| 인자 검사 차례 | `format`(markdown뿐) → `agenda`·`type`·`title`·`body`가 있는지 → `type`(대소문자 무시) → `date` → `time` → `links` → `tags` → `tier` → 제목이 공백인지 → 템플릿 → 아젠다 이름이 공백인지. 오류 글은 Java와 같다 |
| 아젠다 찾기 | slug가 같은 것 → 이름이 같은(대소문자 무시) 것 → 이름을 slug로 만든 것과 같은 것 → 없으면 **아젠다 파일을 새로 만든다**(색은 가장 적게 쓰인 것, 저장소·프로젝트 없음, 요약 비움). 응답의 `agendaCreated`가 이를 알린다 |
| 날짜와 시각 | `date`를 안 주면 이 프로세스의 시간대로 본 오늘, `time`을 안 주면 지금 시각(분)에서 시작해 **같은 날 읽기 층 노트가 이미 쓰는 시각이면 5분씩 미룬다**(23:55 앞까지). `created`의 오프셋은 늘 `+09:00`이다 |
| 폴더 자리 | W3a와 같다: `notes/<아젠다>/<yyyy-MM>/<날짜>-<HHmm>-<제목 slug>-<id 꼬리 4자>`(월별 배치가 아니면 월 폴더 없음). 새 노트 id는 시각(36진수)과 난수 8자리로 만든다 |
| 머리 | `id, agenda, type, title, created, (세션), (tier: record), tags, template, links` 차례. 편집 도장은 없다 |
| 경고 | 같은 제목이 이미 있다 → 들여쓴 블록 → 제목과 첫 헤딩이 다르다 → 깨진 글자 → (AI 호출만) `## 원본 요청` 절이 없다 |
| 응답 | `id, agenda, agendaCreated, date, path, precondition, deepLink, warning?` |

**쓰는 순서가 중요하다.** 새 아젠다 파일은 노트 검사(경로, 저장 상한)보다 **먼저** 써진다. 그래서 노트가 저장 상한을 넘어 실패해도 아젠다 파일은 남는다. Java가 그렇고 Rust도 같게 했다(맞대기에 이 사례가 있다).

| 부품 | 자리 | 하는 일 |
| --- | --- | --- |
| 명령 | `commands/doc_create.rs` | 위 차례 전체와 `links` 읽기(`to`와 `kind`만 허용, 200자 상한, 같은 쌍은 하나만) |
| 시간대 | `write/local_time.rs` | `TZ` 환경 변수나 시스템 시간대로 본 날짜와 시각. C 라이브러리의 `localtime_r`를 부른다(`libc` 크레이트를 더했다). Java의 `ZoneId.systemDefault()`에 해당한다 |
| 경고 | `write/warnings.rs` | 같은 제목 경고(앞뒤 공백, 연속 공백, 대소문자를 무시하고 견줌), 원본 요청 절 경고, 한꺼번에 모으는 `detect_warnings` |
| 화면 | `data/commands.ts`의 `write.createDoc` | 호출 객체가 됐다. 옛 길로 풀면 예전 인자 목록과 같다 |

## 3. Java와 다르게 둔 것

- **시간대는 `TZ` 환경 변수나 운영체제의 것을 따른다.** JVM은 자체 시간대 자료로 같은 일을 하므로 두 자료가 어긋난 드문 날짜(규칙이 바뀐 지역)에서는 갈릴 수 있다. 한국 시간대에서는 같다.
- **`links`·`tags`를 배열로 받는다**(앱이 호출 객체로 보낼 때의 꼴). 명령줄 꼴(JSON 글)도 받고 오류 글은 Java의 명령줄 표면과 같다.
- **AI 호출(`caller: ai`)은 층을 받지 않고**(늘 `reading`), 세션과 에이전트 이름을 머리에 적고, 본문에 `## 원본 요청` 절이 없으면 경고를 붙인다. 이 부분은 Java 명령줄로는 견줄 수 없어서 Rust 통합 시험으로만 확인했다. AI 표면은 아직 Java 엔진이다.
- 같은 id의 노트가 이미 있는 자리에 쓰는 경우(`Storage path conflict`)는 만들지 않았다. id는 시각과 난수로 만들어서 겹치지 않는다.
- 스냅숏 쓰기는 안 옮겼다(스냅숏 설정이 켜지면 호스트가 쓰기를 Java로 보낸다).

## 4. 확인하지 못한 것과 남은 일

- **실제 앱 창에서 확인하지 못했다.** 손 확인 점검표에 「새 노트 만들기」를 더했다(이슈 #54, #61).
- 같은 분에 두 프로세스가 동시에 새 노트를 만들 때의 시각 경합은 쓰기 잠금이 막지만, 경합 시험은 하지 않았다(이슈 #63).

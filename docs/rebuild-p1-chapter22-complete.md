# withlog 1부 22장 완료 — 사실층 명령 3개

작성일: 2026-10-29

`get-agenda-facts`, `update-agenda-facts`, `facts-brief`의 실행부를 구현했다. 세 명령은 하이픈 이름의 명령 표면에만 있고, `get_agenda_facts`, `update_agenda_facts`, `facts_brief`는 종료 코드 2의 모르는 명령이다. 기준은 이번 요청에 붙인 22장이다.

## 구현

| 파일 | 변경 |
|---|---|
| `src/withlog/cmd/AgendaFacts.java` | 편집용 읽기와 저장·삭제. 응답 키는 id, slug, path, limit, editLimit, 선택적 facts 또는 tooLargeToEdit 순서 |
| `src/withlog/cmd/FactsBrief.java` | 날짜 창과 문턱 검증, 읽기 층 루트 노트 집계, 후보 선택, 정렬, section과 items 생성 |
| `src/withlog/vault/FactsReader.java` | 2,000단위와 10,000단위 읽기 공용화. AI의 초과 안내 문장과 편집용 tooLarge 판정을 분리하고 읽기 실패를 경고 로그로 남김 |
| `src/withlog/cmd/AgendaArgs.java` | 노트 전체를 훑지 않고 아젠다 표에서 id를 찾는 공용 경로 |
| `src/withlog/args/ArgsParser.java` | 세 명령의 허용 옵션·자리 인자 수·사용법 등록 |
| `src/withlog/cmd/CommandRegistry.java`, `src/withlog/engine/EngineExecutor.java` | 지원 명령과 실행 분기 연결 |
| `test/withlog/AgendaFactsTest.java`, `test/withlog/git/VaultGitTest.java`, `test.sh` | 사실층 시험과 자동 커밋 작성자 검증을 기본 시험에 포함 |

저장은 공통 쓰기 단계의 워크스페이스 검사와 훑기 뒤에 id, facts 있음, 다듬은 길이, 아젠다 찾기를 차례로 검사한다. 길이가 2,000 UTF-16 단위를 넘으면 파일을 건드리지 않고 WL-400이다. 빈 글은 링크를 따라가지 않는 `Files.deleteIfExists`로 지우고, 나머지는 LF 1개를 더해 기존 `AtomicWriter`로 쓴다. 링크 자리에는 일반 파일을 새로 두고 링크 대상은 그대로 남긴다. 폴더 생성·쓰기·삭제의 WL-500 문구와 절대 경로도 계약대로 낸다.

브리핑은 `from`과 `to`를 `LocalDate.parse`, 문턱을 `Integer.parseInt`로 읽는다. 기본 창은 엔진 프로세스 시간대의 오늘까지 7일이다. 읽기 층 루트 노트만 세고, 실을 사실층이 있으면 1건부터, 없으면 기본 5건부터 남긴다. 노트 수 내림차순, 동률이면 slug UTF-16 순서다. `section`에서만 첫 `# ` 제목 줄과 이어지는 빈 줄을 걷고 줄 끝을 LF로 바꾼다. 항목의 `facts`는 제목과 CRLF를 포함한 다듬은 원문이다. `count`와 `section`은 각각 JSON 한 줄에 둔다.

`update-agenda-facts`와 `facts-brief`는 이미 선언된 쓰기 깃발을 통해 공통 쓰기 단계에 연결된다. 브리핑은 vault 파일을 바꾸지 않아도 serve의 자동 커밋 대기 기록에 `app`으로 남는다. 편집용 읽기는 쓰기 기록을 남기지 않는다.

## 유지한 호환 동작과 색인 차이

22.9의 미결정 특이점은 고치지 않았다. 특히 다음 동작을 실제 JDK 21에서 확인했다.

- 한도+1단위를 담은 뒤 다듬는다. 경계의 공백 때문에 긴 파일이 잘린 글로 나오는 동작도 유지한다.
- 엄격한 UTF-8을 `Files.newBufferedReader`로 읽는다. 8,192단위의 앞선 해독, 다음 글자 머리 검사, 파일 끝의 잘린 글자 확인 여부를 별도 구현으로 바꾸지 않았다.
- 담은 조각이 서로게이트 쌍을 가르면 앞 반쪽을 그대로 남긴다. stdout에서는 기존 JSON 쓰기 규칙에 따라 `?`가 된다.
- BOM·프론트매터·CRLF를 일반 글로 센다. 제목만 있는 사실층의 section은 머리줄과 빈 몸글로 끝난다.
- 뒤집힌 날짜 창은 WL-400으로 거절하고, 노트 날짜와 창의 경계는 UTF-8 바이트로 맞댄다. 확장 연도의 날짜 정렬 특이점도 유지한다.

이 저장소는 8.6에서 허용한 색인 없는 구현을 이어간다. `get-agenda-facts`는 id 검사 뒤 아젠다 파일만 읽으며 노트 전체를 훑지 않는다. 손으로 막 둔 아젠다는 즉시 찾고, 아젠다 파일을 지우면 옛 색인 행 대신 WL-404다. 쓰기·브리핑도 방금 훑은 파일을 바탕으로 하므로, 지운 아젠다의 옛 행으로 읽고 쓰거나 노트를 세는 동작은 재현하지 않는다. 사실층 파일 자체는 아젠다 삭제 뒤에도 남는 기존 동작을 유지한다.

격리된 HOME·임시 vault·소켓에서 실제 `serve`와 `wl-cli`로 읽기·쓰기·브리핑·삭제를 왕복했다. git 시험은 임시 저장소에서 브리핑의 무변경 커밋, 다음 도구 쓰기 전 작성자 전환, 편집용 읽기의 비쓰기, 저장된 사실층 바이트와 `app` 기록을 확인했다. 기존 git 시험의 잠금·재시도·깨진 YAML 로그는 의도한 실패 경로의 출력이다. 사용자 vault와 launchd는 사용하지 않았다.

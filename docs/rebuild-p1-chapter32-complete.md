# 32장 완료 — 4부 이음매

작성일: 2026-10-30

제공받은 32장 설명서를 기준으로 4부가 없는 1부 엔진의 명령 처리와 파일 보존 경계를 점검했다. 이 저장소에서 만드는 엔진과 `wl-cli`는 1부만 포함한다.

## 구현과 점검

- 일곱 명령의 이름, 허용 옵션, 자리 인자 상한과 두 쓰기 깃발을 확인했다. `append-ask-turn`과 `append-chat-turn`의 사용법에서 `images` 예시는 설명서 원문 32장과 부록 A.3대로 줄임표 1글자(`…`)다. 이 판은 처음에 붙여 준 32장 사본의 ASCII `...`를 따랐다가 34장 판 확인 후속에서 바로잡았다([34장 판 확인 후속](rebuild-p1-chapter34-review-fixes.md)).
- 문법 검사 후 쓰기 명령은 워크스페이스 표식과 색인 맞추기를 거치고, 4부가 없다는 `WL-409`를 낸다. 필수 자리 인자의 유무는 이 판에서 검사하지 않는다. 명령 표면의 세션 표식은 버린다.
- 훑기와 경로 한정 훑기에서 `ask.json`과 `chats/`를 노트로 취급하지 않는다. 노트·하위 노트 폴더 이동, 휴지통, 샤드 이동에서는 이 파일들을 폴더와 함께 보존하며, 내보내기에는 싣지 않는다. 샤드 크기에는 포함한다.
- 1부 전용 `wl-cli doctor`는 4부의 `wl-agent` 소켓과 로그 줄을 출력하지 않는다. 4부의 명령 구현과 이 줄을 제공하는 4부 조각은 이 저장소의 범위 밖이다.

## 검증

`bash test.sh` 전체 2,932개 검증이 통과했다. 32장 전용 검증 353개와 실제 serve·wl-cli 소켓 왕복을 포함한다. 일곱 명령의 허용 옵션, 모르는 옵션, 자리 인자 상한과 검사 순서, 표식과 색인 실패, 세션 표식 및 쓰기 대기 기록을 검사했다. 임시 vault에서 읽을 수 없는 4부 파일이 색인·내보내기에 끼지 않는지, 이동·휴지통 복원·영구 삭제·샤드 이동에서 어떻게 처리되는지 확인했다. 1부 전용 doctor의 출력도 별도 프로세스로 검사했다.

실제 엔진과 임시 파일을 이용한 독립 검증이다. 4부가 포함된 원본 엔진이나 4부의 파일 형식과 차등 실행한 결과는 아니다. 영속 색인의 낡음은 기존 1부 구현과 마찬가지로 재현하지 않는다.

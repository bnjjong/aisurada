# Rust 엔진 이전 3단계 W3c — 후속 노트 쓰기(`create_sub_note`, `update_sub_note`, `delete_sub_note`)

## 요약

**결론:** 후속 노트(노트 아래에 달리는 하위 노트)를 만들고, 고치고, 지우는 쓰기 3개를 Rust 엔진으로 옮겼다. 이것으로 **W3(노트 본문 쓰기)이 끝났다.** Java 엔진과 합성 vault에서 **응답과 폴더 전체 바이트가 810건 모두 같다**(앞 묶음 포함, 405단계, 이 가운데 후속 노트는 57단계). 쓰기 스위치(`AISURADA_ENGINE_WRITE=rust`)는 기본 꺼짐이라 앱의 동작은 그대로다. 실제 창 확인은 아직 못 했다([손 확인 안내](rust-engine-hand-check.md)).

[W3b 기록](rust-engine-step3-w3b.md)에 이어진다. 다음은 W4(코멘트 쓰기 3개와 휴지통 4개)다.

## 1. 하는 일

후속 노트는 부모 노트의 폴더 안 `sub/` 아래에 놓인다. 부모는 메인 노트 id이거나 `메인 id/후속 id/…` 사슬이다. 읽기 명령은 후속 노트 id 하나로도 부모를 찾아 주지만, **쓰기 명령은 그것을 받지 않는다**(Java가 그렇다).

| 명령 | 하는 일 |
| --- | --- |
| `create_sub_note` | 부모 아래에 새 후속 노트 폴더(`sub/<오늘 날짜>-<HHmm>-<제목 slug>-<id 꼬리>/note.md`)를 만든다. 유형은 안 주면 `free`. 부모가 단일 파일 노트나 확장자 폴더 노트면 둘 수 없다(500). 제목과 첫 헤딩이 다르거나 들여쓴 블록, 깨진 글자가 있으면 경고 |
| `update_sub_note` | 제목, 본문, 태그를 고친다. **본문만 주면 제목은 본문의 첫 헤딩을 따른다.** 고치고 나서 만든 시각과 새 제목으로 정식 폴더 이름을 다시 계산해 폴더째 옮긴다(아래 후속 노트가 따라온다). 편집 도장 판정은 W3a의 `judge`를 쓴다 |
| `delete_sub_note` | 부모 본문에서 이 노트를 가리키는 하위 페이지 카드 줄(`[제목](#sub:<id>)`만 있는 줄)을 걷어내고, 그 노트의 폴더(아래 후속 노트와 첨부까지)를 지운다. 부모가 후속 노트면 부모 폴더도 정식 이름으로 옮겨질 수 있고, 그러면 응답의 `path`는 옮긴 뒤의 자리다 |

| 부품 | 자리 | 하는 일 |
| --- | --- | --- |
| 명령 | `commands/sub_note_write.rs` | 위 세 명령과 부모 사슬 풀기(오류 문구와 검사 차례가 Java와 같다) |
| 공통 부품 | `write/sub_note.rs` | 메인 노트의 아젠다 읽기, 후속 노트 파일 글 짓기, 정식 폴더로 옮기며 쓰기, 부모 본문만 다시 쓰기(메인 노트는 자리를 안 옮기고 후속 노트는 옮긴다), 카드 줄 걷어내기, 폴더 지우기 |
| 도장 판정 | `write/meta_writer.rs`의 `Draft` | 후속 노트는 머리에 층(`tier`)을 안 적는 값을 주려고 `tier`를 따로 받게 했다 |
| 화면 | `data/commands.ts`의 `write.createSub`, `updateSub`, `deleteSub` | 호출 객체가 됐다. 옛 길로 풀면 부모와 id가 자리 인자(`update-sub-note <부모> <id> …`)로 풀린다 |

**부모 본문을 다시 쓰는 일은 편집 도장을 새로 찍지 않는다.** 카드 줄을 걷어내는 것은 사용자가 고친 것이 아니라 지우기의 부산물이라, 부모 머리를 색인의 값과 옛 도장 그대로 다시 짓고 본문만 바꾼다. 이 점은 Java와 같게 두었고 맞대기로 확인했다.

## 3. Java와 다르게 둔 것

- **`tags`를 배열로 받는다.** 앱이 호출 객체로 보낼 때의 꼴이다. 명령줄 꼴(JSON 글)도 받고 오류 글은 같다.
- **AI 호출(`caller: ai`)의 도장**(`editedBy: tool`, 세션, 에이전트 이름)은 Java 명령줄로 견줄 수 없어서 Rust 통합 시험으로만 확인했다. AI 표면은 아직 Java 엔진이다.
- 지울 폴더가 심볼릭 링크면 링크만 지운다(Java의 `Files.walk`도 링크를 따라가지 않는다). 지우다 실패하면 둘 다 `지우지 못했다`(500)로 끝난다. Rust는 폴더를 통째로 지우는 표준 함수를 써서 중간에 실패했을 때 어디까지 지워졌는지는 같지 않을 수 있다.
- 스냅숏 쓰기는 안 옮겼다(스냅숏 설정이 켜지면 호스트가 쓰기를 Java로 보낸다).

## 4. 확인하지 못한 것과 남은 일

- **실제 앱 창에서 확인하지 못했다.** 손 확인 점검표에 후속 노트 만들기·제목 바꾸기·지우기를 더했다(이슈 #54, #61).
- 같은 노트의 후속 노트를 두 프로세스가 동시에 쓰는 경합 시험은 하지 않았다(이슈 #63).
- **W3 전체 정리:** `update_doc`(W3a), `create_doc`(W3b), 후속 노트 3개(W3c)를 옮겨 쓰기 명령이 19개가 됐다(메타 3개 포함, `commit_vault` 제외). Java에서만 되는 것(스냅숏 쓰기, AI 표면의 추가 기능, 설정 읽기 경로)은 이슈 #56에 모았다.
- 다음은 W4: 코멘트 쓰기 3개(`create_comment`, `update_comment`, `delete_comment`)와 휴지통(`delete_doc`, `restore_doc`, `purge_doc`, `empty_trash`).

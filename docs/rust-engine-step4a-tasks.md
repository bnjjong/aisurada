# Rust 엔진 이전 4단계 4a — 태스크 명령 9개와 SnakeYAML 방출기

## 요약

**결론:** 태스크(티켓) 명령 9개(읽기 2개, 쓰기 7개)를 Rust 엔진으로 옮겼다. 태스크 파일은 노트 머리와 달리 **진짜 SnakeYAML**이 쓰므로, 먼저 SnakeYAML의 YAML 방출기를 Rust로 옮기고 진짜 SnakeYAML 2.4가 쓴 **약 91만 건**과 글자 하나까지 같음을 확인했다. Java 엔진과 합성 vault에서 **응답과 폴더 전체 바이트가 1,258건 모두 같다**(앞 묶음 포함, 629단계, 이 가운데 태스크는 141단계). 쓰기 스위치는 기본 꺼짐이고, 읽기 2개는 앱이 바로 Rust로 읽는다. 실제 창 확인은 아직 못 했다([손 확인 안내](rust-engine-hand-check.md)).

전체 계획은 [4단계 계획](rust-engine-step4-plan.md)에 있고, 이 기록은 [3단계 W4b 기록](rust-engine-step3-w4b.md)에 이어진다.

## 1. 하는 일

태스크는 `.aisurada/tasks/TSK-14.md`(머리말 YAML + 설명)와 `TSK-14/activity.jsonl`(활동, 최근 500줄)로 있고, 지운 것은 `.aisurada/tasks/.trash/<id>/`로 간다. 이 영역은 노트 훑기가 보지 않는다.

| 명령 | 하는 일 |
| --- | --- |
| `create_task` | Draft 태스크를 만든다. 요약·저장소·**완료 기준 1개 이상이 필수**다. 번호는 있는 것과 휴지통의 가장 큰 번호 + 1이다 |
| `get_task`, `list_tasks` | 읽기. 상세는 설명, 완료 기준, 자원, 연결(건 쪽과 받은 쪽 이름), Ready 조건, 사람이 바꿀 수 있는 상태와 막힌 까닭, 활동, 고칠 때 넘길 토큰을 모두 싣는다. 목록은 상태·유형·저장소·라벨·글·막힘으로 거른다 |
| `update_task` | 확인 값(`f1`)이 맞아야 고친다. 바뀐 것이 없으면 파일도 활동도 안 바꾼다. 상태와 연결은 못 바꾼다 |
| `transition_task` | 상태 전이. 규칙은 한 곳(`task/transitions.rs`)에서 검사한다: 누가(사람·러너), Ready 조건, 막은 태스크가 Done 이 되기 전엔 시작 금지, 기대한 지금 상태(`from`) |
| `link_tasks` | `blocks`·`relates`·`duplicates`를 건 쪽 파일에만 적는다. 자기 자신, 서로 막기, 50개 초과는 거절한다 |
| `add_task_comment` | 활동에 댓글을 남긴다 |
| `delete_task`, `restore_task` | 휴지통으로 보내고(활동 포함) 되살린다. 번호는 다시 쓰지 않는다 |

| 부품 | 자리 | 하는 일 |
| --- | --- | --- |
| SnakeYAML 방출기 | `write/snake_dump.rs` | SnakeYAML 2.4 `Yaml.dump`(블록, 유니코드 허용, 줄 나누기 끔, 들여쓰기 2, 목록 표시 들여쓰기 2)와 같은 글을 쓴다. 스칼라 분석과 스타일 선택, 따옴표 규칙, 리터럴 블록(`\|`, `\|-`, `\|+`), 복잡한 키, 이진 태그를 옮겼다 |
| 태스크 모양 | `task/format.rs` | 파일 읽기·쓰기와 인자 검사. 모르는 머리말 칸은 `extra`로 보존하고 고쳐 써도 남는다 |
| 상태 전이 | `task/transitions.rs` | 규칙표와 조건 |
| 저장소 | `task/store.rs` | 훑기, 만들기·고치기·상태·연결, 활동 파일(최근 500줄), 휴지통 |
| 명령 | `commands/task_commands.rs` | 9개 명령과 응답 모양 |
| 화면 | `data/commands.ts`의 `fromArgv`, `ui/tasksClient.ts` | 태스크 화면이 만드는 옛 인자 목록을 호출 객체로 바꿔 보낸다. 스위치가 꺼져 있으면 예전과 같은 인자 목록으로 Java에 간다 |

**왜 노트 머리 쓰기 부품을 못 썼나.** `write/note_front.rs`의 `dump_string`은 설명서 1.9 규칙을 모방한 것이라 SnakeYAML과 다르다. 실측으로 380건 가운데 146건이 어긋났다(예: `:a`는 SnakeYAML이 따옴표 없이 쓰고 모방은 따옴표를 붙인다. 키 `n`도 다르다). 그래서 방출기를 따로 옮겼다.

## 3. Java와 다르게 둔 것

- **AI 세션 도장**(`editedSession`, 에이전트 이름)은 Java 단발 실행에는 세션 표식을 넘길 길이 없어서 맞대기로 견주지 못했다. Rust 통합 시험으로만 확인했다.
- **글을 읽는 규칙의 아주 드문 차이**: 머리말 값이 YAML 목록·맵이어야 할 자리에 다른 형이 오면 Java는 `String.valueOf`로 글을 만든다. Rust는 같은 모양(`[a, b]`, `{k=v}`)으로 맞췄지만 실수 표기 등 극단 사례는 견주지 않았다.
- 활동 파일의 줄 가르기는 `\n`, `\r`, `\r\n`(Java `readAllLines`)을 따른다.
- 러너와 승인 알림이 부르는 태스크 명령은 아직 `ais-cli`(Java)로 간다([4단계 계획](rust-engine-step4-plan.md) §4).

## 4. 확인하지 못한 것과 남은 일

- **실제 앱 창에서 확인하지 못했다.** 손 확인 점검표에 태스크 항목을 더했다(이슈 #54, #61). 태스크 목록과 상세 읽기는 스위치 없이 바로 Rust로 간다.
- 같은 태스크를 두 프로세스가 동시에 고치는 경합 시험은 하지 않았다(이슈 #63).

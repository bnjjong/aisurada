# Rust 엔진 이전 4단계 4c — 문답과 레일 대화 명령 4개

## 요약

**결론:** 노트 옆 문답(`ask.json`)과 세션 레일 대화(`chats/<대화 id>.json`)를 읽고 붙이는 명령 4개(읽기 2개, 쓰기 2개)를 Rust 엔진으로 옮겼다. 파일은 Java 엔진과 **바이트까지 같게** 쓰고, 손으로 쓴 파일(모르는 칸, 틀린 모양, 깨진 JSON, 너무 큰 파일)도 두 엔진이 같은 글로 읽는다. Java 엔진과 합성 vault에서 **응답과 폴더 전체 바이트가 2,136건 모두 같다**(앞 묶음 포함, 928단계, 이 가운데 문답·대화는 112단계). 쓰기 스위치는 기본 꺼짐이고, 읽기 2개는 앱이 바로 Rust로 읽는다. 실제 창 확인은 아직 못 했다([손 확인 안내](rust-engine-hand-check.md)).

전체 계획은 [4단계 계획](rust-engine-step4-plan.md)에 있고, 이 기록은 [4b 자원 기록](rust-engine-step4b-resources.md)에 이어진다.

## 1. 하는 일

두 파일은 노트(또는 후속 노트) 폴더 안에 있다. 폴더로 안 올라간 단일 파일 노트에는 둘 수 없다(`AIS-500`).

| 명령 | 하는 일 |
| --- | --- |
| `get_ask` | 노트의 문답을 읽는다. 파일이 없으면 `null`이다. 모르는 칸은 버리고, 틀린 모양의 칸은 기본값으로 읽고, 깨진 UTF-8은 대체 글자로 읽는다 |
| `append_ask_turn` | 문답에 회차 하나를 붙인다. 필수 인자(`session-id`, `turn-id`, `mark-id`, `asked-at`, `question`, `answer`, `model`, `effort`, `elapsed-ms`)를 모두 검사한 뒤에야 노트를 찾는다. 질문·답변은 20,000자, 인용은 2,000자, 그림은 8장까지고, 파일이 1,000,000바이트를 넘게 되면 붙이지 않는다. 문답 파일의 `sessionId`는 처음 만들 때의 것을 지킨다 |
| `list_chats` | 노트의 레일 대화 목록. 만든 시각 오름차순(같으면 대화 id 순)이고 읽을 수 없는 시각은 뒤로 간다. 못 읽는 파일(1MB 초과, 깨진 JSON, 최상위가 객체가 아님)은 `unreadable`에 이름만 담고, 대화 id 모양이 아닌 파일 이름과 심볼릭 링크는 건너뛴다 |
| `append_chat_turn` | 레일 대화에 회차 하나를 붙인다(대화 파일이 없으면 만든다). 만든 시각과 원본 세션은 처음 만들 때의 것을 지킨다 |

인자 이름은 명령줄과 같다(`session-id`, `elapsed-ms`, `chat-id`, `source-session` …). 호출 객체에서는 `sessionId`처럼 camelCase 이름도 받고, `images`는 배열이나 쉼표로 이은 글을 받는다. 화면은 후속 노트 id 같은 **선택 자리 인자**를 이름 칸과 헷갈리지 않게 `fromArgv`를 고쳤다.

| 부품 | 자리 | 하는 일 |
| --- | --- | --- |
| 명령 | `commands/ask_chat_commands.rs` | 4개 명령, 두 파일의 너그러운 읽기와 쓰기, 시각 차례 |
| 옵션 글 | `commands/option_text.rs` | 호출 객체의 값을 명령줄 글로 바꾼다(자원 명령과 같이 쓴다) |
| 화면 | `workspace/engine.ts`의 `engineReply`, `plugs/claude/askHost.ts` | Claude 연동은 `sidecar_call`처럼 `{status, stdout, stderr}`를 기대하므로, 호스트가 Rust로 처리한다고 알린 명령이면 Rust 엔진으로 보내고 결과를 옛 응답 모양으로 되돌린다. 알리지 않으면 Java 응답을 그대로 둔다 |

## 3. Java와 다르게 둔 것

- **시각 읽기.** 레일 대화 목록의 정렬이 쓰는 만든 시각은 흔한 ISO 모양(4자리 연도, 초와 소수는 있어도 없어도, 끝은 `Z`나 `+09:00`)만 읽는다. Java의 `Instant.parse`·`OffsetDateTime.parse`가 받는 드문 모양(확장 연도 등)은 읽을 수 없는 시각으로 보아 뒤로 간다.
- **정수 읽기.** `elapsedMs`와 `sessionLines`는 ASCII 숫자만 정수로 읽는다(Java `Long.parseLong`은 다른 문자 체계의 숫자도 받는다).
- **옵션 값의 종류.** Rust는 숫자와 참거짓도 명령줄 글처럼 받고(`elapsed-ms: 5`), `null`은 안 준 것으로 본다. 모르는 옵션은 무시한다.
- **입출력 오류 설명.** 파일을 읽다가 운영체제 오류가 났을 때의 설명은 JVM이 만든 글이라 같게 맞추지 못했다. 같은 JSON 읽기 오류 글(`Unterminated array` 등)은 맞췄다.
- 문답·대화를 앱 밖(러너, 호스트 Rust 코드)이 직접 부르는 곳은 없다. 호스트 `ask.rs`는 질문 실행만 하고 저장은 화면이 이 명령으로 한다.

## 4. 확인하지 못한 것과 남은 일

- **실제 앱 창에서 확인하지 못했다.** 손 확인 점검표에 문답·레일 대화 항목을 더했다(이슈 #54, #61). AI에게 묻는 일(`ask_claude`)은 Claude 실행 환경이 있어야 해서, 점검표는 읽기(손으로 만든 파일을 노트에서 열기)와 붙이기를 가능한 만큼만 적었다.
- 같은 문답 파일을 두 프로세스가 동시에 붙이는 경합 시험은 하지 않았다(이슈 #63). 붙이기는 vault 쓰기 잠금 안에서 한다.
- 다음은 4d(세션 읽기 `read_session`, `session_titles`, `recent_sessions`)다. Claude·Codex·Gemini·Antigravity 형식 가운데 어디까지 옮길지는 시작 전에 정한다.

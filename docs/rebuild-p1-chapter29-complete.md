# 29장 완료 — 하루 플랜 초안과 저장

작성일: 2026-10-29

기준은 제공된 PDF 68~77쪽이다. `plan_day`와 `plan-day`를 `cmd/PlanDay.java`에 연결했다.

## 구현

공통 쓰기 전 준비 뒤 날짜와 dryRun을 검사한다. 날짜는 엄격한 ISO 달력 날짜이고 빈 값은 프로세스 시간대의 오늘이다. 읽기 층 루트 노트 전체에서 노트가 있는 직전 날짜와 기준 날짜를 모으며 100건으로 자르지 않는다. 직전 날은 아젠다 slug·벽시각·제목, 오늘은 벽시각·slug·제목 순으로 안정 정렬한다. 동점의 바탕 순서는 만든 시각 글자 내림차순과 경로 바이트 순서다.

초안은 정해진 제목, 어제 한 일, 오늘의 세 부분과 끝 LF를 가진다. 아젠다가 비지 않고 dryRun이 참이 아닐 때만 `CreateDoc.execute`를 공유해 plan 노트로 저장한다. 09:00, mins 0, 읽기 층, 세션 id 없음이 고정값이다. 저장한 응답에서는 date를 빼고 새 노트 id·agenda·agendaCreated·path를 싣는다. 같은 제목 경고는 JSON에 더하지 않고 요청의 stderr로 보낸다.

`cmd/DailyNotes.java`가 29/30장에 같은 날짜 읽기, 읽기 층 목록, 바탕 순서와 HTML 첨부 읽기 경로를 제공한다. 기존 아젠다 찾기·생성, id 발급, 경로 계산, 원자적 쓰기를 복제하지 않았다.

## 검증

`test/withlog/Chapter29Test.java` 58개 검증: 빈 vault의 정확한 초안, 주말을 건넌 직전 기록일, 두 절의 다른 정렬, 기록 층·하위 노트 제외, 101건의 무상한 목록, dryRun과 빈 값, 새 아젠다, 도구 세션 생략, 저장 프론트매터와 본문, 반복 저장의 경고·기존 플랜 포함, ISO 날짜의 경계와 실패 순서를 확인했다. 실제 wl-cli에서 반복 저장의 경고가 소켓 stderr로 돌아오는 것도 검증했다.

## 유지한 경계

29.9대로 초안만 내는 호출도 표식과 쓰기 전 훑기·작성자 기록을 거친다. 오늘의 기본 시간대와 저장 created의 +09:00 규칙은 서로 다르다. 제목을 탈출하지 않고, 반복 호출은 기존 노트를 고치지 않고 새 노트를 만든다. 영속 색인의 낡은 행은 기존 8.6 차이대로 재현하지 않는다.

# 3부 5단계: 엔진 다리·vault 재조정·파일 감시

2026-11-01. 제공된 「withlog 3부 화면 설명서」 5~7장(45~73쪽)을 기준으로 데이터 계층을 연결했다. [구현 순서](rebuild-p3-plan.md)의 5단계다. 편집기 UI는 다음 8~9장, 자동저장·충돌 선택 UI는 10장이다.

## 엔진 명령과 쓰기

`src/data/commands.ts`가 읽기 14개와 schedule·session-titles, 쓰기 27개의 argv를 짓는다. 명령·자리 인자·이름=값·맨 끝 f1 칸을 배열로 넘기며 셸 인용이나 글자 탈출을 하지 않는다. 빈 본문, 빈 태그 목록, 숫자 0과 칸 생략을 구분한다. 하위 노트는 부모 사슬, 하위 코멘트는 루트와 하위 id 두 칸을 쓴다. 태그·분·평가·폼 공백·코멘트 id·회고 id 규칙을 반영했다.

`SidecarCommandError`는 명령·종료 코드·앞뒤 공백을 뗀 stderr를 보존한다. 판정은 stderr의 WL 번호가 아닌 종료 코드로 한다. 아젠다·프로젝트 삭제만 모든 0 아닌 종료를 원문 stderr의 거절로 받는다. JSON 파싱 실패와 호스트 거절은 실패다. commit-vault의 알 수 없는 결과는 성공으로 읽지 않는다.

`VaultData`는 본문·제목·태그·시각·소요 시간, 별·카테고리·평가·연결, 노트·하위 노트·코멘트, 휴지통, 아젠다·프로젝트, 템플릿·리추얼·회고·사실층의 데이터 연산을 제공한다. 생성 실패의 아젠다·프로젝트 유지, 본문 실패의 미저장 표시, 메타 실패의 되돌리기, 삭제 실패의 원래 자리 복원을 나눈다. 삭제 복원은 그사이 들어온 코멘트를 지우지 않는다.

본문 쓰기 큐는 노트별, 하위 노트는 부모와 하위 id의 짝별, 코멘트는 칸별이다. 메모리 값과 토큰은 차례가 왔을 때 읽는다. 응답에 precondition이 없으면 옛 값을 지킨다. 본문이 종료 코드 5를 받으면 토큰만 갈아 다시 쓰지 않고 미저장·충돌 표시와 보관본을 든다. 메타 5는 편집 중·미저장·깨끗함을 나누며 깨끗한 노트만 큐가 끝난 뒤 다시 읽는다. main 제목만 헤딩이 그대로인 경우 한 번 더 시도한다. 편집기와 같은 제목 추출기를 연결하는 것은 8~10장 범위다.

하위 카드·코멘트 표식을 걷는 삭제는 해당 본문 큐에 선다. containerBefore/bodyBefore가 현재 토큰과 맞을 때만 새 토큰과 본문 변경을 받는다. 맞지 않는 삭제는 쓰기 회수도 올리지 않아 바깥 편집을 가리지 않는다.

## 재조정과 그때그때 읽기

- reindex·회고·템플릿·휴지통 4개 뒤 아젠다·프로젝트·전체 본문 노트 3개를 보낸다. 노트를 못 읽으면 메모리 전체를 유지한다. 다른 읽기 실패는 그 칸을 유지하고 reindex 실패의 진단 목록은 빈 값이다.
- 회차는 하나씩 돌고 도중 호출은 다음 한 회차로 합친다. 모든 호출자는 예약 회차까지 기다린다. vault가 바뀌거나 닫히면 늦은 결과를 버린다.
- 읽기 시작의 쓰기 상태와 회수를 떠 둔다. 겹친 노트는 디스크 값을 받지 않는다. 편집 중·미저장 노트는 본문과 토큰을 지키고 main 경로만 디스크를 따른다. 본문과 토큰 대조로 바깥 충돌을 세운다.
- 연결은 합친 노트에서 다시 짓고 자기 연결·같은 출발/대상/종류의 중복을 뺀다. 날짜와 시각은 created에서 읽는다. 회고의 HTML은 DOMPurify 3.4.17로 정화하고 공백뿐인 값은 빈 값으로 둔다.
- 하위 목록은 떠 있는 부모의 참조 수와 지킬 글이 있는 부모만 재조정 끝에 다시 읽는다. created 오름차순이다. 부모 사슬은 읽어 둔 메모리에서 20단까지 찾고 못 찾으면 엔진을 안 부른다.
- 하위 목록·코멘트·사실층은 키별 읽기 번호로 늦은 응답을 버린다. 읽기 실패는 캐시를 지키며, 재조정은 코멘트와 사실층을 다시 읽지 않는다. 기존 하위 페이지와 아젠다 사실층 UI를 이 읽기에 연결했다.

쓰기 실패 줄은 같은 문구를 중복 없이 최근 10개까지 보인다. 성공한 쓰기는 일반 실패 줄을 걷고, 활성 충돌 줄은 남긴다. banner는 충돌·디스크 재읽기·일반 실패를 구분한다.

회고는 마지막 입력 후 400ms에 당시 메모리를 보내고 vault를 떠나기 전 즉시 flush한다. 사실층은 저장 바로 전에 다시 읽어 편집 시작 글과 다르면 쓰지 않는다. 샘플의 본문·메타는 엔진을 부르지 않으며 회고 두 저장 키를 읽고 쓴다. 이 샘플 저장은 id→문자열 맵을 사용한다. 16장 본문이 없어 원본의 전체 저장 포장 형식까지 확인한 것으로 보지 않는다.

## 감시와 직접 파일 다루기

감시는 vault 뿌리에 recursive:true, delayMs:400으로 건다. .tmp 끝, .withlog/cache/ 아래와 .git 마디를 거르고 .gitignore는 받는다. 늦게 설치된 옛 감시는 즉시 해제한다. 샘플·런처·창 닫기·다른 vault로 전환할 때 감시와 자기 쓰기 기록을 정리한다. 감시 실패 시에도 포커스 재조정은 남는다. 숨겨진 문서의 focus는 재조정하지 않는다.

자기 쓰기는 응답의 상대 경로를 vault 글자 뒤에 이어 2,000ms 동안 기록한다. 정확한 경로와 그 자식만 거른다. 이름이 바뀐 노트의 옛 경로, 삭제가 실제로 바꾼 부모 본문, 휴지통 매니페스트 등 6.7의 경로를 기록한다. restore-doc·이관·첨부 바이트 쓰기는 기록하지 않는다.

기록할 때 announce_self_write를 보내고 모든 창의 wl://self-write를 듣는다. 자기 창 이름표와 다른 root는 버리며 수신은 재방송이나 즉시 재조정을 하지 않는다. 노트 창은 이후 포커스 재조정으로 본문을 따라온다.

이관의 원자 쓰기와 폴더 읽기를 `fsPrimitives.ts`로 모았다. 같은 폴더의 UUID.tmp→rename, 실패한 임시 파일 정리, 폴더 읽기 실패의 빈 목록 규칙을 유지한다. 백업의 UTF-8 재인코딩, 실패 뒤 원본 유지와 다음 열기의 -2 중복도 독립 검사했다. 선택 사항인 개발용 vaultseed와 운영에서 부르지 않는 직접 스캐너는 만들지 않았다.

## 실제 점검에서 보완한 경합

1. 생성 응답을 기다리는 사이 옛 목록 읽기가 임시 id를 지울 수 있었다. 성공 응답은 임시 항목의 유무와 관계없이 실제 id를 한 번 등록한다. 응답 뒤 옛 읽기가 끝나는 반대 순서도 실제 id의 쓰기 회수로 보호한다.
2. 샘플 전환 때 옛 재조정이 뒤 묶음 3개를 뒤늦게 보낼 수 있었다. 세대를 무효화하고 이미 보낸 읽기를 마친 뒤 샘플을 표시하며, 무효화된 회차는 다음 묶음을 보내지 않는다. 전환 중 focus·감시 요청은 전환 뒤 판정한다.
3. 옛 vault의 하위 페이지 해제 함수가 새 vault의 같은 부모 구독을 거두지 않게 세대를 대조한다.

## 남은 범위와 호환 동작

현재 제품의 노트 본문은 읽기 화면이다. 27개 쓰기의 데이터 이음매를 만들었으며 편집기 버퍼 flush 등록, 600ms 자동저장·4초 재시도, 충돌 선택·미러·이력 되돌리기와 각 폼의 전체 조작은 8~13장에 연결한다. 샘플의 해당 화면 조작도 그때 검증한다. 원본 83개 argv 골든과 71사례 실행기는 제공되지 않았으므로 이번 독립 검사를 원본 통과로 표현하지 않는다.

3부 고치기 증분 1([기록](rebuild-p3-fix-01-complete.md))에서 부록 C의 C32, C45, C95, C175를 고쳤다. 노트 만들기는 엔진이 받은 뒤에만 메모리에 넣는다. 지키는 하위 노트도 자리는 디스크를 따른다. 저장이 실패한 템플릿은 재조정이 덮지 않는다. 읽는 사이 휴지통에 간 노트는 되살리지 않는다.

6.10의 경로 글자 차이에 따른 자기 쓰기 미검출, 2초 안의 같은 폴더 바깥 편집 지연, 편집 중이 아닌 미저장 main 노트와 외부에서 지운 하위 노트의 목록 탈락은 설명서대로 유지했다. 전체 충돌 보관·복구 UI는 10장이다. 120초 상한 뒤 엔진에서 이미 끝난 쓰기, 아주 큰 stdout·argv 한계와 여러 동기화 프로그램의 실제 파일 경합은 이번 점검 범위 밖이다.

## 추천: 실제 연결 전 1단계 — 단발 프로세스 전송 시제품

기존에는 엔진 실행 파일을 확보하지 못한다고 보았으나, 재구현 JAR이 확인됐다. 다음 작업은 **임시 환경에서 재구현 엔진을 호출하는 호스트 측 단발 프로세스 전송 시제품**으로 잡는다. 이 단위는 실제 앱 완성이나 배포용 런타임 선택이 아니다. 기존 브라우저 번들에서 Node API를 직접 import하지 않고, 별도 호스트/테스트 경계에 둔다. Tauri 도입 및 배포 패키징은 별도 결정한다.

### 범위와 계약

1. 기존 `Transport.execute({ command, args })`를 수용하는 호스트 측 구현과 독립 실행 가능한 통합 시험을 준비한다. 실행 파일·JAR·vault·작업 디렉터리·환경·타임아웃을 명시적으로 주입한다. 발견된 형제 프로젝트 경로를 제품 기본값이나 필수 경로로 박지 않는다.
2. 명령·인자를 각각 argv 칸으로 전달한다. 셸 문자열을 만들지 않고 query의 공백·등호·한글·따옴표 등을 보존한다. 설정 인자는 명령 표면 문법과 충돌하지 않는 위치에 명시적으로 둔다. 환경 변수를 무분별하게 출력하지 않는다.
3. stdout/stderr는 텍스트로 미리 다듬지 않고 바이트로 모은다. 종료 코드가 있는 정상 종료는 `ProcessTransportResponse`의 CLI 원본으로, OS 신호는 `SignalTermination`으로, 생성 실패·타임아웃·읽기 실패 등은 적절한 로컬 실패로 보존한다. 로컬 오류에 엔진 종료 코드나 WL을 만들지 않는다.
4. 요청이 실행되기 전 실패와 실행된 뒤 실패를 보수적으로 구분한다. 프로세스 시작 후 응답 유실·시간 초과는 쓰기가 반영됐을 수 있으므로 `in_flight` 또는 근거가 부족하면 `unknown`으로 표시한다. 자동 재시도하지 않고, 종료 요청이 자식과 후손까지 완료됐다고 단정하지 않는다. timeout에 따른 정리 정책과 수집 제한을 문서화한다. 출력 수집 제한은 명시적 로컬 정책이며 소켓 프레임의 64 MiB 상한을 단발 모드의 엔진 계약으로 오인하지 않는다.
5. `decodeResponse`, 회고 및 태그 클라이언트와 결합해 기존 진단·실패·계약 위반 결과가 그대로 전달되는지 확인한다. 새 전송부가 JSON이나 WL 문구를 별도로 해석하지 않는다.

### 필수 검증

- 주입 가능한 가짜 자식 프로세스 또는 격리된 시험용 프로세스로 argv 정확성, 분리 수집된 바이너리 stdout/stderr, 성공·WL 실패, 비정상 종료, spawn 실패, 신호 종료, 시간 초과, 종료·수집 경합, 자원 정리 및 출력 상한을 검증한다.
- 실제 통합 시험은 명시적으로 지정한 JAR이 있을 때만 실행하고 임시 vault/HOME/TMPDIR/state를 사용한다. 최소한 `list_tags`, `list_reports`, 잘못된 limit 호출의 성공·WL 실패를 클라이언트→전송→디코더 경로 전체에서 검증한다. 없으면 그 시험은 건너뛰었다고 보고한다.
- `npm test`와 `npm run build`가 통과하고 Vite 브라우저 번들에 Node 전용 모듈이 섞이지 않아야 한다. 실제 엔진의 데이터 정확성이나 공식 수용 묶음 통과를 이 시험의 결과로 주장하지 않는다.

## 그다음 작업

1. 호스트 런타임과 실행 파일 배포·선택 정책을 결정하고, 앱에서 실제 전송을 사용할 수 있는 연결 계층을 구현한다. CLI/직접 소켓·장기 프로세스 수명은 별도 단계로 결정한다. 재구현 JAR을 원본 엔진으로 표시하지 않는다.
2. 회고 목록·단건 화면을 기존 클라이언트와 연결하고 빈 목록·불완전 목록·로딩·실패·진단 및 요청 경합을 검증한다. mock을 사용할 때는 실제 연결처럼 표시하지 않는다.
3. 7-2 초안 상태 전이는 실제 전송과 독립적으로 병행 가능하다. 8-3 파일 감시와 12-2 태그 화면은 실제 호스트·갱신 경로에 맞춰 연결하며, 태그 저장은 별도 쓰기 계약이 필요하다.

이번 검토는 실행 가능성 확인과 계획만 포함한다. 애플리케이션 소스와 실제 vault는 변경하지 않았다.

## 1. 토큰 필드와 요청 결합

- 응답의 선택적 precondition을 검사하는 순수 타입 가드를 기존 ResponseValidator/base validator와 조합할 수 있게 만들어 줘.
- 키 없음과 문자열을 구분하고 null/숫자 등 잘못된 타입은 거절해 줘. 키가 없으면 undefined/null 키를 추가하지 마.
- 토큰은 불투명 문자열이야. 앱에서 해시 생성, f1: 문법 검사, trim, 대소문자 변환, 정규화를 하지 마. 받은 문자열 그대로 사용해 줘.
- 요청 인자 객체에 f1을 결합하는 순수 API를 구현해 줘. 응답 키 precondition을 요청 인자로 보내지 마.
- 토큰이 없으면 f1을 생략해 줘. 토큰 없는 모든 호출을 앱에서 거절하면 JSON 메타 쓰기 면제와 set_favorite/link_docs no-op을 막게 되므로 그렇게 구현하지 마.
- 입력 인자 객체에 이미 f1이 있는 경우와 별도 토큰 인자의 중복 소유권은 타입/API에서 막거나 명확히 거절해 줘. 조용히 덮어쓰지 마.
- 원래 인자 객체·본문·추가 키를 변경하지 마. 이 헬퍼는 이미 알려진 명령 인자에 토큰을 결합할 뿐, 임의의 모든 명령 인자가 유효함을 보장하지 않아.
- vault와 대상의 문맥을 표현해 토큰이 서로 다른 vault, 루트/하위 노트, 서로 다른 대상에 섞이지 않게 해 줘. 식별자 형식이나 파일 경로는 추측하지 마.
- link_docs에서 토큰이 from의 본문에 속한다는 문맥을 반영해 줘. 전체 link_docs 클라이언트는 만들지 마.

## 2. 파생 쓰기 before/after 쌍

- delete_sub_note의 containerBefore/containerAfter와 delete_comment의 bodyBefore/bodyAfter를 각각 검사하는 순수 validator를 만들어 줘.
- 두 키가 모두 없거나 모두 문자열이어야 해. 한쪽 누락이나 null/숫자는 계약 오류로 연결해 줘.
- 두 종류 쌍의 이름과 영향받는 대상을 혼동하지 않는 API로 만들어 줘. 대상은 자식 삭제의 직계 컨테이너 또는 코멘트가 달린 노트야.
- 보유 토큰이 before와 정확히 같을 때만 after를 이어받을 수 있어. 다르거나 보유 토큰이 없으면 재조회가 필요해.
- 쌍이 없으면 컨테이너 본문을 다시 쓰지 않았다는 의미야. 삭제 명령 전체가 no-op이었다고 판단하지 마.
- before가 같아도 캐시 본문에는 삭제된 카드/마커가 남아 있을 수 있어. after 토큰만 붙여 옛 전체 본문을 재저장할 수 없도록, 토큰 갱신과 본문 갱신 필요성을 함께 표현해 줘.
- 결과는 unchanged/advance_and_refresh_body/reload_required 같은 앱 내부 판단 데이터로 제공해 줘. 엔진 응답에 키를 추가하거나 원격 변경을 직접 적용하지 마.

## 3. 쓰기 결과 정책

- 기존 DecodedResponse와 이미 검증한 토큰/쓰기 부가정보를 사용해, 성공·충돌·실패 이후의 토큰 사용 및 재조회 필요성을 판단하는 순수 함수를 만들어 줘.
- 성공이 새 토큰을 주면 해당 대상의 다음 쓰기에 이어 쓸 수 있다는 정보를 제공해 줘. 부가정보 없는 성공을 모두 무변경 또는 오류로 단정하지 마.
- 알려진 no-op의 경우에만 그 의미를 반영하고, 전체 응답 스키마가 없는 명령의 no-op 판별 필드를 추측하지 마. 필요한 명령별 사실은 검증된 입력으로 받도록 해 줘.
- WL-412는 보호 대상 본문의 쓰기가 거절됐다는 뜻이야. 그 전에 색인·git 커밋·쓴 쪽 기록이 발생할 수 있으므로 vault 전체가 무변경이었다고 표현하지 마.
- WL-412에서 초안 보존과 최신 본문 재읽기·재적용을 안내해 줘. 새 토큰만 교체해 같은 옛 본문을 다시 보내는 경로는 만들지 마.
- WL-500에는 폴더 이동 후 상한 거절 등 부분 반영이 있어. 파일/폴더 상태 확인이 필요하다는 판단을 남겨 줘.
- 예상 밖 실패, in_flight/unknown 전송 실패, 신호 종료, 응답 스키마 오류는 이미 쓰기가 반영됐을 가능성을 고려해 줘. pre_dispatch와 구분해 줘.
- stderr 문구로 MISSING/MALFORMED/STALE를 자동 판별하거나 토큰을 추출하지 마.
- 실제 재조회, 자동 재시도, 자동 생성, 쓰기 재전송은 실행하지 마. 행동 지침만 데이터로 제공해 줘.
- 기존 실패 분류·원본 바이트·진단·경고·복구 정보를 잃지 않게 해 줘.

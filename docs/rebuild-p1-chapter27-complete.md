# 27장 완료 — 마크다운 내보내기

작성일: 2026-10-29

기준은 제공된 PDF 39~46쪽이다. `export_markdown`과 `export-markdown`을 같은 `cmd/ExportMarkdown.java`에 연결했다.

## 구현

읽기 층 루트 노트를 만든 시각과 경로 순서로 읽고 HTML 첨부 읽기 경로를 거친다. html/json은 건너뛰고, markdown은 고정 목적지 `.withlog/md-export`를 지운 뒤 기존 노트 경로와 본문으로 원자적으로 쓴다. 프론트매터를 빼고 글을 다듬거나 끝 LF를 더하지 않는다. 샤드 층과 손으로 바꾼 폴더 이름은 그대로 유지한다.

기록 층과 하위 노트는 내보내거나 세지 않는다. 상대 경로의 공백·절대 경로·`..`·역슬래시·제어 문자는 건너뛰고 `skippedUnsafe`에 센다. JSON 응답은 dest, exported, totalNotes, skippedHtml, 선택적 skippedUnsafe와 skippedJson 순서다. 목적지가 링크면 링크만 지우고 새 폴더를 만든다.

## 검증

`test/withlog/Chapter27Test.java` 24개 검증이 기본 시험에 포함된다. CRLF와 끝 줄바꿈 없는 본문, 하위 노트·기록 층 제외, html/json/unsafe 집계, 옛 파일 삭제, 같은 결과 경로의 덮어쓰기와 exported 수, 폴더 이름의 확장자 오판정, 목적지 링크 대상 보존을 확인했다. 실제 wl-cli로도 내보내기를 호출했다.

## 유지한 경계

27.9대로 목적지를 먼저 지우므로 중간 실패는 부분 내보내기를 남긴다. 같은 결과 경로의 두 노트는 뒤쪽이 덮고 두 건으로 센다. 이름이 `.md` 등으로 끝나는 폴더는 본문 파일을 잘못 짚어 빈 파일을 낸다. 엔진의 카드·첨부 참조·코멘트 마커는 본문 글 그대로 남는다.

영속 색인의 옛 행은 없는 구현이다. 파일을 못 읽게 바꾼 뒤에도 옛 행을 남기는 경우는 기존 8.6의 차이대로 재현하지 않는다. 이 명령을 완전한 포맷 변환이나 첨부를 포함한 백업으로 넓히지 않았다.

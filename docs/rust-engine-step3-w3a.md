# Rust 엔진 이전 3단계 W3a — `update_doc`(노트 제목·본문·태그·날짜 고치기)

## 요약

**결론:** 노트를 고치는 쓰기 중 가장 자주 불리는 `update_doc`을 Rust 엔진으로 옮겼다. 자동 저장이 본문을 쓸 때마다 부르는 명령이다. Java 엔진과 합성 vault에서 **응답과 폴더 전체 바이트가 550건 모두 같다**(앞 묶음 포함, 275단계, 이 가운데 `update_doc`은 83단계). 쓰기 스위치(`AISURADA_ENGINE_WRITE=rust`)는 기본 꺼짐이라 앱의 동작은 그대로다. 실제 창 확인은 아직 못 했다([손 확인 안내](rust-engine-hand-check.md)).

W3은 `update_doc` → `create_doc` → 후속 노트 3개 차례로 나눠 올린다. 이 기록은 첫 조각이고, [W2 기록](rust-engine-step3-w2.md)에 이어진다.

## 1. 하는 일

`update_doc`은 노트 한 건의 제목, 본문, 태그, 템플릿, 날짜, 시각 가운데 **준 것만** 갈아 끼우고, 그 값으로 다시 계산한 정식 자리로 노트를 옮긴다.

```
f1 검사 → 머리·본문 읽기 → 값 갈아 끼우기 → 편집 도장 판정 → 새 자리 계산 → 쓰기(옮기기) → 경고 모으기
```

| 부품 | 자리 | 하는 일 |
| --- | --- | --- |
| 명령 | `commands/doc_write.rs`의 `update_doc` | 위 차례 전체. 검사 차례는 id → 태그 → 날짜 → 시각 → 제목 공백 → 노트 찾기 → JSON 본문 → `f1`이고, 오류 글은 Java와 같다 |
| 도장 판정 일반화 | `write/meta_writer.rs`의 `judge` | W2는 본문이 그대로라고 보고 머리만 견줬다. 이제 새 본문(`body`)과 파일의 옛 본문(`old_body`)을 따로 받아서, 본문만 바꿔도 도장이 새로 찍힌다. `write_meta`도 이 함수를 쓴다 |
| 자리 계산 | `write/doc_place.rs` | `date`·`time` 인자 읽기, 부모 폴더, 폴더 이름(`<날짜>-<HHmm>-<제목 slug>-<id 꼬리 4자>`), 폴더 옮기기와 빈자리 고르기(`-2`~`-99`) |
| 첫 헤딩 | `write/first_heading.rs` | 본문의 첫 `#` 헤딩(없으면 HTML `<h1>`~`<h6>`)을 뽑는다. 제목과 달라졌다는 경고에 쓴다 |
| 경고 | `write/warnings.rs` | 제목과 첫 헤딩이 다르다, 깨진 글자(U+FFFD)가 늘었다 경고를 더했다(들여쓴 블록 경고는 W1에서 옴) |
| 화면 | `data/commands.ts`의 `write.updateDoc` | 호출 객체가 됐다. `tags`는 배열 그대로 가고, Java 길로 풀면 `tags=["a","b"]` 글이다. 확인 값(`f1`)은 맨 끝이다 |

**노트 종류별로 쓰는 자리가 다르다.**

| 노트 | 쓰는 곳 |
| --- | --- |
| 폴더 노트(후속 노트·첨부가 든 것 포함) | 경로 검사 → 정식 폴더로 **폴더째 옮기기**(이미 있으면 `-2`…) → 상한 검사 → `note.md` 쓰기 |
| 단일 `.html` | `<부모>/<폴더 이름>.html`에 쓰고 이름이 바뀌었으면 옛 파일을 지운다 |
| 단일 `.md`·`.json` | `<부모>/<폴더 이름>/note.md`(또는 `note.json`)에 새로 쓰고 옛 파일을 지운다 |

옛 파일을 못 지우면 응답을 실패로 바꾸지 않고 「같은 id가 둘 남았을 수 있어요」 경고를 붙인다.

**부모 폴더**는 월별 배치(`notes/<아젠다>/<yyyy-MM>`)인지에 달렸다. vault 어딘가에 `YYYY-MM` 폴더 아래 바로 노트가 있으면 월별 배치로 본다. 환경 변수 `AISURADA_NOTES_SHARD_BY_MONTH`(`true`·`on`·`yes`·`1` / `false`·`off`·`no`·`0`)가 있으면 그 값을 따른다. 이 판정은 읽기 쪽 스캐너(`vault/scanner.rs`)와 같은 함수를 쓴다.

맞대기를 처음 돌렸을 때 어긋남이 3건 나왔고 모두 **시험 쪽 문제**였다. Java가 오류 글 끝의 공백을 잘라서 보여 주는 것(2건), Java가 월별 배치 값이 이상할 때(`maybe`) 엔진을 조립하지 못하는 것(1건)이다. 앞의 둘은 Rust 단위·통합 시험으로 옮겼고, 뒤의 것은 아래 「차이」에 적었다. 또 이상한 연도(`+12345-03-04` 따위)로 날짜를 바꾸면 노트가 읽을 수 없게 되어 색인에서 사라진다(Java와 Rust가 똑같다). 그 뒤 단계가 「노트 없음」으로 헛돌지 않게 이런 날짜는 버릴 노트에서 시험한다.

## 3. Java와 다르게 둔 것

- **`AISURADA_NOTES_SHARD_BY_MONTH`는 환경 변수만 본다.** Java는 같은 설정을 명령줄 옵션, `spring.application.json`, 시스템 속성에서도 읽는다. 값이 `true` 계열도 `false` 계열도 아니면 Java는 엔진을 조립하지 못하고 멈추는데, Rust는 그 값을 없는 것으로 보고 디스크를 본다(이슈 #56에 더할 것).
- **`tags`를 배열로 받는다.** 앱이 호출 객체로 보낼 때의 꼴이다. 명령줄 꼴(`"[\"a\"]"` 글)도 받고, 같은 오류 글을 낸다. 배열 안의 숫자가 아닌 값이 문자열이 아니라고 오류가 날 때의 글(`tags 항목이 문자열이 아니다: …`)은 숫자를 `serde_json`이 다시 찍은 모양으로 적는다(`1.0e3`은 `1000.0`). 앱은 문자열 배열만 보내므로 닿지 않는다.
- **AI 호출(`caller: ai`)은 `date`·`time`을 받지 않는다.** Java의 도구 표면이 그렇다. Rust에도 같은 규칙을 넣었지만 AI 표면은 아직 Java 엔진이라 앱 호출만 이 길을 탄다.
- `created`를 읽지 못하는 노트는 Java가 예상 밖 예외로 끝나고, Rust는 `created 를 읽지 못해 고치지 않았다` 오류(`AIS-500`)로 끝난다. 색인에 오른 노트의 `created`는 늘 읽히므로 실제로는 닿지 않는다.
- 스냅숏 쓰기는 안 옮겼다(스냅숏 설정이 켜지면 호스트가 쓰기를 Java로 보낸다).

## 4. 확인하지 못한 것과 남은 일

- **실제 앱 창에서 확인하지 못했다.** 손 확인 점검표에 「제목을 바꾸면 폴더가 옮겨지고 후속 노트가 따라온다」와 자동 저장 항목을 더했다(이슈 #54, #61).
- 두 프로세스가 같은 노트를 번갈아 고치는 경합 시험은 하지 않았다(이슈 #63).
- 다음은 `create_doc`(새 노트 만들기: 아젠다 찾기·만들기, 시각 배정, 같은 제목 경고), 그다음 후속 노트 쓰기 3개다.

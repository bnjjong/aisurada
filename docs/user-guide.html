CHAPTER 01

처음 10분

샘플을 둘러본 다음, 내 폴더에 첫 기록을 남겨 보세요.

이미 앱이 준비되어 있나요?

바로 아래 순서로 시작하세요. 소스에서 직접 실행하려면 설치와 실행을 먼저 확인하세요.

  1. 샘플로 화면을 익힙니다.

    시작 화면에서 샘플로 둘러보기를 누릅니다. 캘린더의 문서를 눌러 미리보기를 열고, 탭으로 띄우기로 편집 화면을 확인합니다. 샘플은 실제 vault 파일을 바꾸지 않습니다.

  2. 내 워크스페이스를 만듭니다.

    시작 화면 → 새 워크스페이스에서 이름과 저장 위치를 정하고 만들기를 누릅니다. 이미 기록 폴더가 있다면 폴더 열기를 선택합니다.

  3. 아젠다를 하나 만듭니다.

    왼쪽 아젠다 ＋에서 예를 들어 ‘제품 개발’을 만듭니다. 프로젝트는 아젠다가 여러 개로 늘었을 때 추가해도 됩니다.

  4. 첫 문서를 씁니다.

    캘린더 → 새 문서에서 아젠다·유형·제목을 정합니다. 본문에 오늘 할 일을 적고 문서를 만듭니다.

  5. 저장과 찾기를 확인합니다.

    본문을 수정한 뒤 저장됨을 확인합니다. ⌘ + K로 제목을 검색하면 방금 쓴 노트를 다시 열 수 있습니다.

첫 노트 예시

오늘의 작업 계획

목표: 검색 결과의 빈 화면을 개선한다.

  • 현재 화면에서 막히는 지점 정리
  • 작은 수정 하나 구현
  • 확인한 결과와 다음 작업 기록

샘플은 연습용입니다. 실제 작업 기록은 본인이 만든 워크스페이스에 남기세요.

CHAPTER 02

워크스페이스와 화면

기록은 컴퓨터의 폴더에, 탐색은 앱 안에 모입니다.

WORKSPACE

워크스페이스

노트·첨부·아젠다·리포트를 모아 두는 폴더입니다. 이 가이드에서는 같은 폴더를 vault라고도 부릅니다.

PROJECT → AGENDA

프로젝트와 아젠다

프로젝트는 아젠다의 묶음이고, 아젠다는 노트가 속하는 작업 주제입니다.

NOTE

노트

제목·날짜·유형·본문을 가진 기록입니다. 필요하면 하위 페이지와 첨부를 함께 둡니다.

열기와 전환

  • 새 워크스페이스: 부모 폴더 아래에 입력한 이름의 폴더를 만듭니다.
  • 폴더 열기: 사용할 작업 폴더를 선택합니다. 기존 파일이 있는 폴더라면 먼저 사본을 보관해 두는 편이 좋습니다.
  • 최근 워크스페이스: 지난 폴더를 다시 엽니다. 최근 목록의 ×는 목록에서만 제거합니다.
  • 다른 폴더로 전환: 저장 상태를 확인하고 따로 열린 노트 창을 닫은 다음 전환합니다.

미리보기, 탭, 별도 창

목록에서 노트를 누르면 미리보기를 열 수 있습니다. 탭으로 띄우기는 메인 창의 탭으로, 새 창으로는 별도 노트 창으로 옮깁니다. 새 창은 데스크톱 앱에서 사용합니다. 본문 복사와 이력은 노트 머리의 메뉴에서 찾을 수 있습니다.

CHAPTER 03

프로젝트·아젠다로 정리

프로젝트는 큰 묶음, 아젠다는 계속 기록할 주제입니다.

  1. 왼쪽의 프로젝트 ＋로 큰 작업 묶음을 만듭니다. 이름·색·설명을 정합니다.
  2. 아젠다 ＋로 주제를 만들고, 필요하면 프로젝트에 넣습니다.
  3. 아젠다 옆 ⋯에서 이름·색·프로젝트·저장소·설명을 바꿉니다.
정리 예시

프로젝트: 고객 포털 → 아젠다: 화면 개선 / API 정리 / 운영 이슈 → 각 주제의 계획·리서치·구현 노트

저장소 경로와 Claude 세션

아젠다의 저장소에 /Users/me/projects/customer-portal처럼 로컬 작업 폴더의 절대 경로를 적으면, 그 폴더에서 실행한 Claude 세션을 PROJECTS 영역에 연결하는 데 쓰입니다. URL로 자동 Git 동기화를 켜는 설정은 아닙니다.

사실층: 다음 작업에도 필요한 배경

아젠다 화면의 사실층에는 매번 반복해 설명하는 내용을 짧게 적습니다. 프로젝트의 목적, 현재 운영 환경, 확정된 제약 같은 내용이 적합합니다. 적기 / 고치기로 편집한 뒤 저장합니다. 저장 한도는 다듬은 글 기준 2,000자이며 화면에 글자 수가 표시됩니다.

편집 중 다른 곳에서 사실층이 바뀌면 차이를 확인한 뒤 저장 방향을 결정합니다.

묶음을 지울 때

프로젝트 삭제는 소속 아젠다를 미분류로 옮깁니다. 아젠다 삭제는 소속 노트도 휴지통으로 옮기는 흐름이므로 확인 창의 내용을 읽고 진행하세요.

CHAPTER 04

노트 만들기와 저장

적고, 저장 상태를 확인하고, 태그와 연결을 붙입니다.

새 문서

캘린더 → 새 문서 또는 아젠다 화면의 문서 만들기에서 시작합니다. 아젠다가 하나 이상 필요합니다.

문서의 기본 정보
항목사용 방법
아젠다어느 주제의 기록인지 고릅니다.
유형계획, 리서치, 구현, 회의, 보고, 자유 중에서 고릅니다.
템플릿선택한 유형에 맞는 문서 템플릿을 적용합니다.
제목·날짜·시각찾기 쉬운 제목과 기록 시점을 정합니다.
태그새 문서에서는 쉼표로 나눠 입력합니다. 만든 뒤에도 태그를 추가·제거할 수 있습니다.

자동 저장 읽는 법

본문 입력이 잠시 멈추면 약 0.6초 뒤 저장합니다. 제목은 첫 헤딩과 본문 편집 흐름에 맞춰 반영됩니다. 파일 이름을 직접 바꾸기보다 앱 안에서 수정하세요.

저장됨

현재 편집 내용의 저장이 끝났습니다.

저장 중…

전송 또는 저장이 진행 중입니다. 이동하거나 닫기 전에 결과를 확인하세요.

저장 실패 — 다시 시도 중

글은 편집 상태에 남고 재시도합니다. 경로·권한·엔진 상태와 상단 알림을 확인하세요.

외부 변경됨

다른 앱이나 창이 파일을 먼저 바꿨습니다. 차이를 보고 어느 글을 유지할지 결정해야 합니다.

노트 머리의 도구

  • ☆: 즐겨찾기에 넣거나 뺍니다. 즐겨찾기 화면에서는 카테고리도 관리합니다.
  • 평가: 평가와 메모를 남깁니다. 필요하면 평가를 지울 수 있습니다.
  • 본문 복사: 현재 편집 본문을 복사합니다. 문답·코멘트의 내부 표식은 복사에서 제외합니다.
  • ID / 경로: CLI나 링크에서 사용할 식별자를 확인합니다. 루트 노트에는 새 창 링크 복사가 있습니다.
  • 이력: 저장된 이전 판과 현재 글을 비교합니다.
CHAPTER 05

본문 편집과 하위 페이지

글, 표, 코드, 그림을 하나의 기록으로 묶습니다.

편집기에서 자주 하는 작업
하고 싶은 일방법
글 강조본문의 대목을 선택해 뜨는 도구 줄에서 굵게·기울임·취소선·인라인 코드를 고릅니다.
블록 추가문단에서 /를 입력해 페이지·노트 링크·표·콜아웃·코드 블록 메뉴를 엽니다. 빈 줄에 커서를 두면 줄 왼쪽에 +가 보이고, 눌러도 같은 메뉴가 열립니다. 해당 문맥에서 가능한 항목이 표시됩니다.
표 편집표의 줄에 마우스를 올리면 그 줄 왼쪽 가장자리에 점 여섯 개 모양의 줄 손잡이가 뜹니다(칸마다 뜨지 않고, 같은 줄에서 마우스가 열을 옮겨 다녀도 제자리에 있습니다). 손잡이를 누르면 그 줄에 파란 테두리가 생기고 메뉴가 열립니다. 메뉴에는 이 줄을 AI에게 묻기·이 줄에 코멘트 달기, 행 추가/삭제, 열 추가/삭제, 표 너비 맞춤, 표 복사, 표 삭제가 있습니다. 열 추가/삭제는 커서가 있는 칸의 열을 기준으로 하므로 먼저 그 열의 칸을 눌러 커서를 둡니다(표 안에 커서가 없으면 꺼져 있습니다). 경계 손잡이로 열 또는 표 전체 너비를 조절합니다.
시트나 Slack으로 표 복사표 메뉴의 표 복사 — Slack과 시트를 씁니다. 마크다운 표 복사도 별도로 있습니다.
코드와 다이어그램코드 블록 안에 커서를 두면 그 블록 오른쪽 위에 언어 선택이 뜹니다. 콜아웃 안에서는 같은 자리에 정보·성공·주의·위험 선택이 뜹니다. Mermaid는 다이어그램 표시 설정과 함께 사용합니다.
그림 첨부노트 편집기에 클립보드 그림을 붙여 넣습니다. 실제 폴더와 파일 저장이 가능한 데스크톱 앱에서 사용합니다.
목차 이동헤딩이 여러 개면 노트 옆 목차로 해당 대목에 이동합니다.

하위 페이지

노트 안의 / → 페이지 또는 아래 후속 노트 → 추가로 작은 페이지를 만듭니다. 본문의 하위 페이지 카드나 후속 노트 목록을 누르면 열립니다. 하위 페이지 안에서도 다음 하위 페이지를 만들 수 있습니다.

하위 페이지 삭제는 바로 반영됩니다.

루트 노트 삭제와 달리 하위 페이지는 휴지통을 거치지 않습니다. 남길 내용이 있다면 먼저 본문을 복사하거나 상위 기록에 옮기세요.

코멘트와 노트 연결

대목을 선택해 코멘트를 달거나 노트 아래 코멘트 목록에서 글을 남깁니다. 본문에서 노트 링크를 삽입하거나 아래 연결 추가를 눌러 다른 노트와 관계를 만듭니다. 연결 화면에서는 이 관계를 지도 또는 목록으로 봅니다.

HTML 첨부와 외부 Markdown

노트에 넣은 HTML 첨부는 상자로 표시할 수 있습니다. 파일 연결이나 파일 링크로 연 vault 밖의 Markdown은 읽기 전용입니다. 외부 파일을 열었다고 작업 노트로 자동 편입되지는 않습니다. 외부 Markdown 읽기는 UTF-8, 2 MiB 이하 파일을 대상으로 합니다.

CHAPTER 06

찾기·캘린더·즐겨찾기

기록을 다시 찾는 방법을 작업 상황에 맞게 고릅니다.

빠른 검색

  1. ⌘ + K 또는 Ctrl + K를 누릅니다.
  2. 제목, 아젠다 이름, 태그, 본문 내용, 노트 ID로 찾습니다. 읽어 둔 첨부 텍스트도 검색에 쓰입니다.
  3. 위·아래 방향키로 결과를 고르고 Enter로 탭을 엽니다. Esc로 닫습니다.

검색어가 비어 있으면 최근 연 노트와 최근 만든 노트가 표시됩니다. 결과는 최대 20개입니다. 빠른 검색의 본문은 읽기용으로 정리한 텍스트이므로 코드 블록 안의 문자열을 찾을 때는 본문이나 CLI 검색도 함께 확인하세요.

캘린더

월 / 주 / 일로 보기 범위를 바꾸고, 이전 / 다음 / 오늘 또는 기준 날짜로 이동합니다. 아젠다 필터로 특정 주제만 보세요. 일 보기에서는 노트 블록을 끌어 시각을 조정할 수 있으며 15분 단위 이동이 적용됩니다.

즐겨찾기

노트의 별을 켠 뒤 즐겨찾기에서 제목 검색·정렬·묶음별 보기를 이용합니다. 카테고리 이름을 정하면 여러 아젠다에 흩어진 중요 기록도 한데 모아 볼 수 있습니다.

연결

지도 / 목록으로 노트 관계를 살펴보고 선택한 기록을 엽니다. 관계는 노트의 연결 추가에서 만듭니다. 단순히 같은 태그를 가진 노트가 자동으로 연결되는 것은 아닙니다.

분명 저장했는데 목록에 없나요?

터미널이나 세션에서 굳힌 노트는 기록 노트로 저장됩니다. 설정에서 기록 노트를 켜면 목록과 검색에 포함됩니다.

CHAPTER 07

템플릿과 데일리 리포트

자주 쓰는 문서 틀과 하루의 정리 화면을 활용합니다.

내 문서 템플릿 만들기

  1. 템플릿 → 새 템플릿을 누릅니다.
  2. 이름·유형·설명·본문을 고칩니다. 편집은 자동 저장됩니다.
  3. 새 문서에서 같은 유형을 선택하고 해당 템플릿을 고릅니다.

본문에 [제목]을 넣으면 새 문서를 만들 때 입력한 제목으로 바뀝니다. 새 문서의 선택 목록에는 유형이 맞는 Markdown 문서 템플릿이 나옵니다. 기본 템플릿과 데일리 리포트 템플릿은 삭제할 수 없습니다.

데일리 리포트

데일리 리포트에서 모닝·마무리 회고·주간 리포트를 펼쳐 읽습니다. 캘린더의 리포트 막대에서도 열 수 있습니다. 표시된 기록을 편집 → 저장하거나 별도 메모를 남깁니다.

저장된 리포트 본문이 없으면 해당 기간의 노트 링크를 모은 기본 내용이 표시됩니다. ‘AI 원본’은 사용자 편집 본문을 비워 원본/기본 표시로 돌아가는 버튼입니다. 이 버튼이 새 Claude 요청을 보내지는 않습니다. 사용자 편집본이 필요하다면 먼저 복사해 두세요.

CHAPTER 08

노트의 대목을 AI에게 묻기

선택한 글과 노트 맥락을 함께 보내고, 답을 노트 곁에 남깁니다.

사용 조건

Claude 연동이 포함된 데스크톱 앱, 실제로 열린 워크스페이스, 실행 가능한 Claude Code CLI가 필요합니다. 브라우저 미리보기와 샘플에서는 실제 노트 문답을 보낼 수 없습니다. 준비 방법은 Claude 연결 준비에 있습니다.

  1. 대목을 선택합니다.

    본문 글을 드래그하고 AI에게 묻기를 누릅니다. 표에서는 줄 옆 AI 단추, HTML 첨부에서는 상자 머리의 묻기 단추로 시작합니다.

  2. 질문과 옵션을 정합니다.

    질문을 적고 모델·effort를 고릅니다. 이 개발판 고르개의 기본값은 sonnet 5.5 / low입니다. 실제 실행 가능 여부는 설치한 Claude CLI와 계정에 따라 확인하세요.

  3. 묻기를 보냅니다.

    묻기 또는 ⌘/Ctrl + Enter를 누릅니다. 같은 노트에 여러 물음을 보내면 앞 물음이 끝날 때까지 차례를 기다립니다.

  4. 답을 읽고 이어 묻습니다.

    노트 아래 AI 문답 또는 밑줄 카드에서 답을 봅니다. 이 대목에 이어 묻기로 같은 맥락을 이어 갑니다.

어떤 맥락이 함께 가나요?

질문에 선택한 대목, 노트의 식별자와 읽기 안내, 아젠다의 저장소 정보가 붙습니다. 기록을 만든 Claude 세션이 확인되면 관련 대화의 일부도 첫 물음에 실릴 수 있습니다. HTML 질문과 붙인 그림은 파일을 읽으라는 안내와 경로가 함께 갑니다.

카드와 그림

  • 본문 밑줄에 마우스를 올리면 카드가 열립니다. 카드 안을 누르면 고정되어 이어 묻는 글을 쓸 수 있습니다.
  • 고정 카드 밖을 누르거나 카드 안에서 Esc를 누르면 닫습니다. 크기 손잡이로 폭·높이를 조절할 수 있습니다.
  • 질문 그림은 클립보드 붙여넣기로 추가합니다. 한 물음에 8장, 한 장에 5,000,000바이트까지입니다.
  • PNG, JPEG, GIF, WebP, AVIF, BMP, SVG를 받습니다. 그림을 저장할 노트 폴더가 없거나 현재 실행 경로가 그림을 받지 않으면 이유를 표시합니다.

응답을 기다리는 동안

다른 탭으로 이동할 수 있습니다. 답이 오면 해당 노트 탭에 알림 점이 나타납니다. 저장하지 못한 답에는 안내가 붙습니다. 메모리에만 남은 답은 앱을 닫으면 사라질 수 있으므로 필요한 내용은 복사하고 저장 문제를 해결하세요.

앱을 닫는 사이에 끝나지 않은 물음은 다음 실행 때 안내가 나옵니다. 표시된 claude --resume … 명령으로 대화를 확인하거나, 아직 전송되지 않은 질문은 같은 대목에서 다시 물으세요.

CHAPTER 09

Claude 세션 읽고 이어 가기

원래 세션에 이어 쓰는 일과, 세션을 참고해 새로 묻는 일을 구분합니다.

PROJECTS에서 세션 찾기

왼쪽 PROJECTS에서 Claude 세션 목록을 읽고 새로고침합니다. 아젠다의 로컬 저장소 경로와 세션의 작업 폴더가 맞으면 주제별로 묶입니다. 세션 줄을 누르면 대화 화면으로 이동합니다. 실행 상태와 프로세스 생존 여부는 서로 다른 정보이므로 실제 입력창의 안내를 따르세요.

노트 옆 세션 레일

노트에 세션 칩이 있을 때 열 수 있습니다. 원래 세션의 최근 대화를 읽고, 새 질문에는 노트와 세션 맥락을 함께 보냅니다. 새 대화 열기는 앞 대화에서 벗어나 새 문답을 시작합니다. 세션 화면에서 보기로 전체 세션 화면에 이동할 수 있습니다.

레일 경계로 폭을 조절합니다. 레일을 닫거나 탭을 바꿔도 작성 중인 내용과 요청 상태를 유지하지만, 이는 앱 실행 중의 창 메모리입니다. 앱 재시작까지 모든 초안을 보존한다는 뜻은 아닙니다.

세션 화면

머리에서 상태·작업 폴더·모델 관련 정보를 보고 가운데에서 사람 말, Claude 답, 도구 호출을 읽습니다. 관련 노트 / 링크 / CLI 탭으로 결과를 살펴봅니다. 도구 결과 본문 전체를 보여 주는 화면은 아닙니다.

  • 이어 가기 명령 복사: claude --resume <세션 id>를 복사합니다.
  • 하단 입력: 질문을 적고 보냅니다. 파일을 끌어 놓으면 경로를 입력에 넣고, 클립보드 그림도 붙일 수 있습니다. 받아쓰기는 시스템에서 지원할 때 사용합니다.
  • 터미널 열기 / CLI: 실제 셸에서 해당 세션을 이어 갑니다. CLI 칸을 처음 보여 줄 때 시작하며, 오른쪽 레일을 접는 것만으로 칸을 해제하지 않습니다.
  • 좁은 창: 1,100px 이하에서는 오른쪽 레일을 숨깁니다. 필요한 탭이 안 보이면 창을 넓히세요.

세션 대화를 노트로 굳히기

  1. 노트로 굳히기를 누릅니다.
  2. 최근 100 / 200 / 500건 중 범위를 정하고 실제 회차 수와 모양 검사 결과를 봅니다.
  3. 제목과 아젠다를 정하고 굳히기를 누릅니다. 본문은 300,000바이트 이하여야 합니다.

태그 세션전사가 붙은 기록 노트가 만들어집니다. 도구 결과 본문은 담지 않고, 사람 말과 답·도구 호출 요약을 남깁니다. 모양 검사는 값을 자동으로 가리는 작업이 아니므로 표시된 결과를 검토하세요.

CHAPTER 10

터미널과 작업 기록 남기기

앱 안에서 셸을 쓰고, 필요한 출력만 노트로 옮깁니다.

앱의 파일 → 터미널 열기 또는 ⌘ + Shift + T로 터미널 탭을 엽니다. 데스크톱 앱의 실제 로그인 zsh 셸이므로 입력한 명령은 컴퓨터에서 실행됩니다.

터미널 닫기와 세션 유지

터미널 탭을 닫으면 연결을 분리하고 호스트가 약 5분의 재연결 유예를 둡니다. 그 안에 같은 터미널로 돌아오면 출력 기록을 재생할 수 있습니다. 레일을 접는 것과 화면을 떠나는 것은 동작이 다르므로, 오래 실행할 명령은 상태를 확인하며 사용하세요.

출력을 노트로 굳히기

  1. 터미널 하단의 굳히기를 누릅니다.
  2. 마지막 100 / 500 / 2,000 / 10,000줄 또는 고른 부분을 선택합니다. TUI 화면이 떠 있거나 선택 범위를 복원할 수 없으면 ‘고른 부분’을 쓰지 못할 수 있습니다.
  3. 값 가림 결과, 못 읽은 이름, 모양 검사 안내를 확인합니다.
  4. 제목·아젠다를 정하고 기록 노트로 저장합니다.
가림 표가 없으면 굳히기가 막힐 수 있습니다.

‘표 다시 뜨기’로 재확인합니다. 비밀 이름 분류표가 없는 견본 빌드나 값을 읽지 못한 환경에서는 기능이 제한될 수 있습니다. 화면의 안내를 확인하세요. ‘모양 검사 0건’은 모든 비밀이 제거됐다는 보증이 아닙니다.

세션 대화 굳히기는 도구 결과 본문을 제외하고 모양을 검사합니다. 터미널 스크롤백 굳히기는 선택한 출력에 값 일치 가림을 적용합니다. 서로 다른 두 기능입니다.

  2. 과거 판을 고르고 지금 글과 / 바로 앞 판과로 본문 차이를 비교합니다.

이력은 vault에 Git 커밋 또는 사용 가능한 이전 스냅숏이 있을 때 나타납니다. 파일 저장 자체가 매번 즉시 새 이력을 만드는 것은 아닙니다. 자동 커밋은 Git 저장소의 main 브랜치 등 조건이 맞을 때 동작하며, 기본 유휴 커밋 시간은 5분입니다.

Git이 잠겨 있거나 병합·리베이스 중이거나 자동 커밋이 꺼져 있으면 복원을 진행하지 못할 수 있습니다. 화면의 이유를 확인하고 해당 Git 작업을 마친 뒤 다시 시도하세요.

휴지통

루트 노트에서 삭제 → 휴지통으로를 선택하면 휴지통으로 이동합니다. 휴지통 → 복구로 되돌립니다. 완전 삭제와 휴지통 비우기는 확인 후 영구 삭제하므로, 복구할 자료가 없는지 먼저 확인하세요.

복구 범위가 다릅니다.

하위 페이지 삭제는 휴지통을 거치지 않습니다. 폴더 백업은 notes/만이 아니라 숨김 폴더 .aisurada/와 첨부·대화 파일을 포함한 워크스페이스 전체를 보관하세요.

CHAPTER 14

Claude 연결 준비

노트 AI 문답은 설치된 Claude Code CLI를 통해 실행됩니다.

Claude Code에서 노트를 도구로 쓰려면

설정(톱니바퀴)의 Claude 연결에서 Claude Code에 연결을 누르면 Claude Code가 지금 연 워크스페이스의 노트를 도구로 찾고 읽을 수 있습니다. 기본은 읽기만 허용합니다. 노트를 만들고 고치는 것도 허용을 켜면 쓰기도 됩니다. 영구 삭제는 어느 쪽이든 할 수 없습니다. 연결은 워크스페이스 하나에 묶이므로 다른 워크스페이스에서 다시 연결하면 그쪽으로 바뀝니다. 같은 영역에서 Claude Desktop용 설정 조각을 복사할 수 있지만, Claude Desktop과의 연결은 아직 확인하지 못했습니다.

일반 묻기 경로는 claude -p입니다. 별도 ais-agent 데몬을 먼저 설치해야 하는 구조가 아닙니다. 노트와 그림 내용이 질문 맥락으로 사용되므로, 보내려는 자료를 확인하고 이용 중인 Claude 계정의 사용 조건에 맞게 사용하세요.

CHAPTER 16

CLI로 기록 읽고 내보내기

자동화나 터미널 작업이 필요할 때 사용하는 선택 기능입니다.

아래 예시는 저장소 루트에서 실행합니다. /absolute/path/to/vault를 자신의 워크스페이스 경로로 바꾸세요. 폴더의 절대 경로를 따옴표로 감싸면 공백이 있는 경로도 사용할 수 있습니다.

엔진으로 직접 읽기 · launchd 기동 없이
export AISURADA_VAULT="/absolute/path/to/vault"
java -jar dist/ais-engine.jar list-docs limit=20
java -jar dist/ais-engine.jar search-docs "검색어"
java -jar dist/ais-engine.jar get-doc "노트-id"
java -jar dist/ais-engine.jar export-markdown

export-markdown은 내보낸 위치 등 결과를 JSON으로 알려 줍니다. 노트의 원래 폴더 전체 백업과는 별개이며 문답·대화 파일을 모두 복사하는 명령은 아닙니다.

계속 떠 있는 엔진에 연결하기

터미널 1 · 워크스페이스 경로 설정 후
java -jar dist/ais-engine.jar serve
터미널 2 · 같은 AISURADA_VAULT 설정 후
java -jar dist/ais-cli.jar list-docs limit=20
java -jar dist/ais-cli.jar doctor
java -jar dist/ais-cli.jar --help

직접 띄운 serve가 있으면 클라이언트가 그 소켓으로 연결합니다. 엔진이 없을 때 클라이언트는 설치된 사이드카를 launchd로 띄울 수 있습니다. 이때 사용자 LaunchAgent를 등록할 수 있습니다.

ais-cli 설치와 쓰기 명령의 토큰

앱 안의 연동 가이드에서 셸 래퍼와 PATH 설정 예시를 확인합니다. 소스 빌드의 두 jar만 설치하려면 아래 명령을 사용할 수 있습니다. 설치만으로 ais-cli라는 셸 명령이 생기는 것은 아니므로 래퍼와 PATH 설정을 별도로 합니다.

저장소 루트에서
java -jar dist/ais-cli.jar install   --cli "$PWD/dist/ais-cli.jar"   --sidecar "$PWD/dist/ais-sidecar.jar"

설치 위치는 ~/Library/Application Support/aisurada/bin/입니다. 기존 노트를 고치는 명령에는 직전에 읽은 precondition 값을 f1=…로 함께 보냅니다. 이는 다른 곳에서 바뀐 글을 덮지 않기 위한 검사입니다. AIS-412가 나오면 다시 읽고 차이를 반영한 뒤 쓰세요.

CHAPTER 17

막혔을 때 확인할 것

증상에서 시작해 필요한 화면으로 돌아가세요.

‘AI에게 묻기’가 보이지 않거나 실제 전송이 안 됩니다.

Claude 기능을 포함한 데스크톱 앱인지, 샘플 대신 실제 워크스페이스를 열었는지 먼저 확인합니다. 대상이 없는 단일 파일 하위 페이지에는 묻기 기능이 표시되지 않을 수 있습니다. CLI를 찾지 못하거나 로그인/실행 오류가 표시되면 Claude 연결 준비를 확인하세요.

‘다른 터미널에서 열려 있어요’라며 세션 입력을 막습니다.

같은 Claude 세션에 두 실행이 이어 쓰면 대화가 갈라질 수 있어 막는 안내입니다. 원래 터미널에서 이어 가거나 그 실행을 끝낸 뒤 목록을 다시 읽으세요. 세션 목록을 읽지 못한 상태와 다른 기기에만 기록이 있는 상태도 구분해서 확인합니다.

굳힌 노트가 목록이나 검색에 없습니다.

설정 → 기록 노트를 켭니다. 날짜와 아젠다 필터도 확인하세요. 생성된 노트가 현재 보고 있는 날과 다른 날짜에 있을 수 있습니다.

저장 실패 또는 외부 변경 알림이 계속 나옵니다.

편집 내용부터 복사하고 폴더 접근 권한·디스크 상태·엔진 연결을 확인합니다. 충돌이라면 차이 보기로 디스크 글과 비교합니다. 알림의 ‘닫기’는 실패 원인 자체를 해결하지 않습니다. 복구 절차를 참고하세요.

이력 목록이 비어 있거나 되돌리기를 못 합니다.

vault의 Git 저장소와 커밋이 있는지 확인합니다. 기본 자동 커밋에는 유휴 시간이 필요합니다. Git의 main 브랜치 여부, 진행 중인 병합·리베이스, 잠금, 자동 커밋 설정에 따라 복원이 제한될 수 있습니다. 원인을 확인하지 않은 채 잠금 파일을 지우는 방식으로 해결하지 마세요.

세션의 관련 노트·링크·CLI 탭이 안 보입니다.

창을 1,100px보다 넓게 하고 레일 펴기를 누릅니다. 노트 옆 레일을 찾는 경우에는 작성/편집 세션 칩이 있는 노트인지 확인하세요.

터미널 출력 굳히기에서 ‘표가 없어 굳힐 수 없어요’가 나옵니다.

표 다시 뜨기를 누르고 표시된 원인을 확인합니다. 이름 분류표가 없는 견본 빌드라면 앱 배포자에게 필요한 설정을 문의하세요. 세션 전사를 노트로 굳히는 기능과 터미널 출력 굳히기는 검사 방식이 다릅니다.

시작 화면의 GitHub 연동 버튼으로 연결이 되지 않습니다.

현재 시작 화면의 해당 버튼은 안내를 표시하는 단계입니다. GitHub 로그인이나 원격 저장소 동기화를 완료하는 흐름은 구현되어 있지 않습니다. 필요하면 별도로 Git 저장소와 원격 백업을 관리하세요.

개발 서버가 1420 포트 충돌로 시작하지 않습니다.

이미 실행 중인 개발 서버가 있는지 확인합니다. 필요 없는 기존 개발 실행을 종료한 뒤 다시 시작하세요. 다른 프로그램의 프로세스를 이름만 보고 종료하지 마세요.

폴더는 있는데 열 수 없거나 일부 파일을 읽지 못합니다.

워크스페이스 경로와 읽기 권한을 확인합니다. 앱 상단의 읽지 못한 파일 또는 충돌 사본을 펼쳐 파일별 이유를 봅니다. 원본을 보관한 뒤 해당 파일 형식이나 메타데이터를 점검하세요.

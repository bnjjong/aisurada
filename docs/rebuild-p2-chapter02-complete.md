# 2부 2장 구현 — 기동과 종료

작성일: 2026-10-30

제공받은 2부 PDF 18~19쪽을 기준으로 환경 정리 → 네 플러그인 → wlframe 등록 → 공유 상태 → 시작 걸음 → 메뉴·페이지·창 이벤트 → 이벤트 루프 순서의 호스트를 추가했다. 시작 걸음은 main 창, 메뉴, 딥링크 핸들러 순서다.

환경 정리는 Claude와 cmux 표식이 있을 때만 주입된 변수들을 제거하고 사용자 설정을 남긴다. main 화면 읽기의 시작과 끝을 구별하지 않고 터미널 표에 등록된 자식들을 모두 회수하며 노트 창 읽기는 제외한다. main 닫기에서는 자식 회수, 종료 플래그, 노트 창 닫기 요청을 처리한다. 노트 창 없어짐에서는 남은 노트 id 목록을 정렬해 이벤트로 알리고, 종료 중에는 복원용 목록을 유지한다. Cmd+Q와 종료 신호에 창 닫기 처리를 인위적으로 추가하지 않았다.

메뉴 다섯 항목과 창별 이벤트 전달을 연결했다. main의 마지막 위치·크기는 앱 데이터의 개발/일반 파일로 구분해 원자적으로 쓰고 복구하며, 모니터 밖이면 기본 위치로 돌아간다. 모니터 환경별 레이아웃과 노트 창 복원 파일은 12~13장 범위로 남긴다.

vault·터미널·비밀 표의 초기 상태와 환경 정리, 실제 자식 프로세스 회수를 Rust 테스트 6개로 검증했다. 터미널 표는 준비했으나 PTY 생성과 커맨드 등록은 후속 장에서 연결한다. wlframe도 10장 전까지 404를 반환한다. 따라서 29개 커맨드나 완성된 앱의 받아들임 검사가 통과했다는 뜻은 아니다. GUI의 포커스·Cmd+Q·외부 딥링크 전달은 이번 자동 검증에서 측정하지 않았다.

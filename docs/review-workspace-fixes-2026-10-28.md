# 전반 재검토 네 문제 보완 결과 — 2026-10-28

[전반 재검토](./review-workspace-2026-10-28.md)의 P2 네 건을 수정하고 재현 경로를 회귀 검증했다.

## 1. 중복 색인 실행

- `src/lib/engineRuntime.ts`의 앱 수명 공유 ReindexCoordinator를 화면에서 구독한다. 본문 옵션·부모·vault·컴포넌트의 수명과 색인 실행 수명을 분리했다. 진행 중 같은 앱의 동일 vault 수동 요청은 추가 등록하지 않는다.
- 완료 시점에 보고 있는 vault·부모·본문 모드의 목록을 무효화하고 다시 읽는다. 화면이 폐기되면 해당 탐색 모델/구독만 정리하며, 코디네이터의 진행 중 작업은 추적을 유지한다.
- 호스트 인스턴스에서도 실제 vault 경로(realpath, 없는 경로는 절대 경로)를 키로 동일 인자의 진행/대기 요청을 병합하고 다른 인자는 직렬화한다. 같은 디렉터리의 alias도 병합하며 다른 vault는 독립 실행한다.
- HTTP 클라이언트 4개의 동일 요청을 한 프로세스로 실행하고 완료 후 새로운 요청은 다시 실행하는지 검증했다. alias·다른 vault, 서로 다른 인자와 실패 뒤 후속 요청도 확인했다.
- 브라우저 두 화면에서 12초 지연 시험 프로세스를 사용했다. A 갱신 중 본문 옵션 변경과 B→A 왕복 후에도 버튼은 비활성 상태를 유지했고, 두 번째 화면의 요청도 같은 호스트 실행을 공유했다. 실제 reindex 시작은 1회였다. 완료 뒤 `bodies=true`로 목록을 다시 읽었다. 별도 두 번째 의도적 갱신에서 캘린더로 나갔다 돌아와도 상태를 유지했다. [브라우저 근거](./review-repros/2026-10-28-fixed-browser-evidence.json)를 남겼다.

## 2. 토큰 문맥 참조 공유

`createScopedToken`이 target의 독립 사본을 보관하고 사본·반환 객체를 동결한다. 원본 target은 동결하지 않는다. 원본의 vault·루트 id·하위 id가 바뀌어도 기존 토큰의 소유권은 유지되며, 다른 대상 결합은 TargetMismatchError다. 토큰 문자열의 공백·형식은 보정하지 않는다.

루트/하위 문맥 변경, 원본의 변경 가능성, 반환 객체/문맥의 변경 차단과 원문 토큰 전달을 회귀 검증했다.

## 3. 폐기·재진입 경계

running 통지 뒤, 경로 예산·클라이언트 팩토리·시계·예약 취소 등 주입 콜백 뒤에서 폐기 여부와 실행 식별자를 다시 확인한다. 각 구독자 호출 사이에도 폐기를 확인하고, 폐기 중 뒤늦게 반환된 예약 취소 함수도 정리한다. 폐기 후 새 구독은 등록하지 않는다.

vault/global running 구독자의 dispose, getClient/예산/시계/예약 콜백의 dispose를 검증했다. 원래 재현은 이제 `dispatched=0`, `notifiedAfterDispose=0`이다. 이미 실행 중인 네이티브 프로세스를 취소했다는 보장은 추가하지 않았다.

## 4. 성공 stdout의 UTF-8

성공 stdout은 엄격한 UTF-8로 해석한다. 잘못된 바이트는 새 `contract_violation/invalid_utf8`로 분리하며 원본 stdout/stderr·오류 원인을 유지한다. 유효하게 인코딩된 U+FFFD는 정상 본문이고 stderr의 기존 진단 표시 정책은 유지한다.

CLI/소켓에서 잘못된 바이트·연속 바이트·과잉 인코딩·서로게이트 인코딩·다중 바이트 중간 절단과 정상 한글/보충 문자/U+FFFD를 구분했다. UTF-8 계약 오류에서 validator를 실행하지 않고, 쓰기 결과 정책이 초안 보존·다음 토큰 연결 금지를 유지하는지 확인했다.

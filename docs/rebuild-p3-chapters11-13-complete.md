# 3부 8단계: 11~13장

기준은 제공된 「withlog 3부 화면 설명서」의 11~13장(116~147쪽)이다. 4부 없는 React 화면을 기존 Java 엔진과 Tauri 호스트에 연결했다. 원본 소스나 원본 조종 실행기는 가져오지 않았다.

## 구현

- 노트 탭·노트 창·아젠다 페인·미리보기·하위 페이지가 같은 본문과 저장 세션을 쓴다. 별, 평가, blur 시 소요 시간, ID/경로·세션 복사, MD 본문 복사·이력, 태그, 추천/수동 연결, 후속 노트, Markdown 코멘트를 연결했다. HTML 노트는 정화한 읽기 화면으로 열며 편집기·저장 상태·복사·이력·목차를 보이지 않는다.
- 하위 페이지의 경로 이동·전체 닫기, 삭제 확인, 부모 편집기의 하위 카드 제거, 코멘트 위치 이동·수정·삭제, 첫 헤딩을 뺀 목차를 구현했다. 모달·빠른 검색·하위 페이지의 Esc 우선순위를 capture 단계의 모달 수로 지킨다.
- 새 창 이동은 이 창의 편집기 전체를 flush하고 큐를 기다린 뒤 해당 노트와 자식의 미저장 상태를 확인한다. 중복 이동 요청을 합치고, 현재 제목과 저장된 창 위치를 호스트에 넘긴다.
- 레일의 7개 메뉴, 프로젝트별 아젠다와 편집 폼, 표시 필터, 프로젝트 접기, 테마·설정을 구현했다. 캘린더의 월/주/일·주 레이아웃·15분 시각 이동과 카드 맞바꾸기, 아젠다 페인과 개요·사실층, 즐겨찾기 묶음·카테고리, 연결 지도·목록, 리포트 편집·메모, 템플릿 2초 저장·떠날 때 저장, 휴지통과 가이드를 연결했다.
- 검색은 엔진 없이 메모리에서 ID→제목→아젠다/태그→본문 순으로 찾는다. 포맷별 평문·첨부 글 캐시, UTF-16 대목, 결과 20개, vault별 최근 50개와 10초 문턱, 열린 화면의 참조 수를 적용했다.
- 이력은 현재 편집 버퍼를 떠 두고 판 본문을 commit별로 한 번 읽는다. 찾기가 선택을 바꾸지 않으며 두 비교 모드와 같은 줄 접기를 지원한다. 복원은 10장의 flush→선행 커밋→본문 교체 포트를 쓰고, 성공 뒤 커밋·목록 갱신을 한다. 7가지 결과와 Git 거절 이유를 구분한다.
- 외부 Markdown은 호스트로 읽고 원문 HTML 허용→원격 그림 칩→정화→상대 그림 허용 요청→DOM 삽입 순서로 연다. 상대 MD 링크, 읽기 전용 화면, 테마별 Mermaid를 연결했다. Mermaid는 편집기와 읽기 화면이 같은 직렬 렌더 큐를 쓴다.
- 설정은 제목 날짜·기록 노트·다이어그램 3개이며 즉시 로컬 저장한다. 날짜는 같은 날짜의 접두어만 정리한다. 기록 숨김은 그리는 목록에만 적용하여 쓰기 조회표인 전체 노트 메모리를 보존한다.

## 지킨 특이점

미리보기의 유형·아젠다·날짜·시각·소요 시간·템플릿은 열 때의 값을 쓰고 본문·제목·별·평가는 현재 값을 쓴다. 소요 시간 입력은 같은 노트의 외부 변경을 따라가지 않으며 blur에서만 쓴다. 태그는 blur로 추가하지 않는다. 하위 페이지 삭제가 실패해도 한 단계 뒤로 간다. 아젠다 페인 순서는 URL이 아닌 메모리 목록 차례다. 연결 지도의 검색은 대소문자를 가리고 목록 모드는 앞뒤 공백을 보존한다. 사실층 읽기 실패는 읽는 중으로 남긴다. 샘플에서도 이력은 엔진을 부른다. 도구 판이 있으면 4부 없는 판에서도 `session-titles`를 보내고 실패를 버린다.

## 자료가 없어 별도 재구성한 범위

- PDF는 리포트 생성 규칙을 의도적으로 적지 않았다. 현재는 해당 날짜/주간의 노트 링크로 기본 글을 만든다. 원본 생성 결과와 같다고 보장하지 않는다. 저장된 글·메모·편집·원본으로 되돌리는 쓰기 계약은 구현했다.
- 가이드에 통째로 실을 원본 `skills/withlog/SKILL.md`가 제공되지 않았다. 1단계는 이 저장소의 CLI 사용 요약으로 구성했다. 2단계의 과거 Node MCP 설정 예시는 설명서에 적힌 특이점을 구분해 유지했다. 그 Node 서버를 설치·생성하지 않는다.
- 16장 본문이 없어서 `withlog.prefs.v1`의 전체 필드 모양을 확인할 수 없다. 이 단계는 명시된 저장 키와 기본 동작을 쓰되 `titleDate`, `showRecords`, `diagrams`, `weekLayout`, `agendaSort`, `agendaDesc`, `collapsedProjects`, `previewSize`를 자체 필드로 쓴다. 기존 알 수 없는 필드는 보존한다. 전체 16장과의 호환 판정은 남겨 둔다.
- 14~18장과 부록, 원본 검색 골든·조종 실행기가 없다. 이 기록의 독립 검증을 원본 18장 통과로 표현하지 않는다. 물리 IME·시스템 선택 대화 상자·실제 메뉴 클릭과 OS 파일/URL 연결 전달은 손 확인 범위다.

`test:views`는 검색·최근 기록·날짜 제목·아젠다 차례·추천과 연결 후보·경로·시간 배치·리포트·Esc·시각 실패 복구를 독립 검사한다. `test:views:acceptance`는 실제 제품 React 화면과 Java·Git·Tauri·WKWebView를 함께 사용한다. 테스트가 직접 만든 HOME·vault·앱 식별자·소켓에서만 쓴다. 이력 검사는 실제 판을 만들기 위해 파일 이동 후 테스트가 명시적으로 커밋한 뒤 시작한다. 가상 DOM 이벤트는 실제 포인터·물리 키보드·IME 조작과 구분한다.

브라우저 점검에서는 샘플의 캘린더, 설정, 미리보기, 문서 생성과 아젠다 페인, 본문 검색, 템플릿 생성·편집·떠날 때 저장, 가이드 배치를 확인했다. `pnpm tauri build --debug --bundles app`을 수행하여 `native-host/src-tauri/target/debug/bundle/macos/withlog.app` 번들 생성을 검증 완료했다. 번들 생성과 실제 번들 실행은 별도 판정이다.

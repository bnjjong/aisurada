# 3부 고치기 증분 3: markdown 왕복 11줄

[3부 고치기 플랜](rebuild-p3-fix-plan.md)의 증분 3이다. 부록 C에서 「고친다」로 정한 markdown 왕복 줄을 다시 지은 편집기(`native-host/src/editor`)에 넣었다.

- 고친 줄은 C69, C72, C73, C74, C88, C179, C181, C182, C186, C187이다. 플랜에서 증분 4였던 C196도 목록 규칙을 새로 짓는 김에 함께 고쳤다.
- C183은 이미 새 규칙대로라 사례만 더했다.
- 기준은 설명서 부록 C.3의 「고치면」과 「3부 설명서 고친다 30줄」 플랜의 「증분이 정할 것」이다. 기준 판은 aisurada `26afcab`이다.
- 사용자가 「있는 자료로 진행」을 골랐다. 그래서 11-02 판 9장과 원본의 왕복 묶음 없이 지었다. 자료가 없어 짐작한 자리는 4절에 따로 적었다.

## 4. 짐작한 자리

11-02 판 9장(9.8, 9.9)과 원본 왕복 묶음이 없어서, 아래는 「고치면」 글에서 짐작했다. 자료를 받으면 다시 맞댄다.

1. **코드 안 빈 줄.** 9.9의 「첫 빈 줄 버림, 끝 빈 줄 버림」은 그대로 뒀다. C73의 「고치면」은 첫 줄 공백만 적었고, 원본의 바뀐 I3은 이 묶음의 I5(`c++`)와 같은 꼴이기 때문이다.
2. **목록 들여쓰기 단계.** 2배 뒤 4칸마다 1단계, 탭 1개도 1단계로 센다. 라이브러리 규칙을 그대로 옮겼다.
3. **중첩 줄로 시작한 목록의 종류.** 바깥 줄이 오기 전 목록의 종류는 첫 줄의 종류다. 첫 바깥 줄이 다른 종류면 그 종류로 바꾼다. 그래서 C190이 만드는 `  - b1` 다음 `3. c`가 다시 열어도 번호 목록으로 남는다.
4. **목록 안 펜스.** 목록 항목 밑에 들여쓴 펜스는 맨 위 코드 블록이 되고, 코드 줄은 들여쓰기를 지닌다(`C179a`). 목록 항목 안 코드는 이 편집기에 없다.
5. **사례 id.** 원본이 더한 새 사례 10개는 없다. 새 사례는 줄 번호로 붙였다.

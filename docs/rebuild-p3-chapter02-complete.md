# 3부 2단계: 부팅과 워크스페이스

2026-11-01. 제공된 「withlog 3부 화면 설명서」의 2장에 따라 부팅, 만들기·열기·최근 목록·샘플, 옛 노트 이관과 노트 창의 읽기 부팅을 연결했다. [전체 구현 순서](rebuild-p3-plan.md)의 2단계다.

## 구현

main 창은 `withlog.lastWorkspace.v1`의 경로 글자를 그대로 `allow_workspace`에 넘긴다. 노트 창은 처음 읽은 `/note-window/<한 마디>`로 판별하며 퍼센트 디코딩 실패 시 main 경로로 다룬다. 부팅은 한 번만 실행한다. 기록이 없으면 `/launcher`, `/`의 열기에 성공하면 `/calendar`로 간다. `/launcher?mode=create` 직접 진입도 지원한다.

공통 열기는 회고 쓰기 훅 → 노트 창 정리 → `allow_workspace` → `init-workspace name=<이름> templates=[]` → 옛 노트 이관 → 첫 읽기 4개 → 다음 읽기 3개 → 메모리 교체 → 직전 기록 → 감시의 순서다. 노트 창 정리는 100ms 간격으로 최대 40회 확인한다.

첫 읽기는 `reindex`, `list-reports bodies=true`, `list-templates bodies=true`, `list-trash`다. 모두 끝난 뒤 `list-agendas`, `list-projects`, `list-docs limit=0 bodies=true`를 보낸다. 각 묶음 안에서는 병렬이다. 노트 읽기 실패는 빈 목록과 닫을 수 없는 배너로 알린다. 호스트의 경로 변경 거절은 삼키지 않는다. 겹친 열기는 직렬화하여 호스트 경로와 화면 데이터가 섞이지 않게 했다.

만들기는 `create_workspace_dir`로 받은 경로를 허용하고 먼저 초기화한다. 첫 초기화 실패를 표시하며 성공 뒤 공통 열기를 다시 실행하므로 `allow_workspace`와 `init-workspace`는 각각 두 번이다. 기본 문서 폴더의 늦은 응답은 사용자가 먼저 입력한 저장 위치를 덮지 않는다. 「찾아보기」는 폴더 선택 플러그인을 쓰며 만들기 쪽에서 고르면 즉시 저장 위치 키를 적는다.

만들기의 첫 초기화 실패 시 호스트는 이미 새 경로를 가진다. 이때 이전 workspace 화면과 감시를 남기지 않고 런처로 돌아가며 이전 직전 기록은 보존한다. 실패 뒤 화면 상태는 2장에 명시되지 않은 경계라 데이터와 호스트가 어긋나지 않도록 정하고 회귀 검사에 넣었다.

최근 목록은 경로 중복을 제거하여 최대 6개다. 추가·삭제할 때마다 저장소를 다시 읽는다. 최근 줄 열기는 순서를 바꾸지 않으며 삭제는 목록만 바꾼다. `opened`는 항상 `방금 전`이다. `withlog.workspaceHome.v1`은 끝 빗금을 뗀 절대 경로만 저장한다.

샘플은 메모리에만 열어 감시를 멈추고 직전 실제 vault와 호스트 경로를 바꾸지 않는다. 날짜는 `2026-06-04`다. 원본 샘플 자산이 없어 새 본문을 가진 아젠다 3개와 markdown 노트 3개를 넣었다. 계약인 `md1`, markdown 형식과 문단, 「샘플로 둘러보기」 글자를 지킨다. 원본의 노트 27개·링크 39개를 재현했다고 표시하지 않는다.

노트 창은 `vault_root`를 읽고 `reindex`를 제외한 목록 6개로 붙는다. 초기화·이관·workspace 허용을 하지 않고 main 전용 동작도 거절한다. 설정은 테마만 읽으며 storage·포커스 이벤트로 갱신한다. 첫 실제 vault를 열면 저장된 노트 창 중 현재 vault에 있고 main 탭에 없는 노트만 한 번 복원한다.

## 이관과 감시

이관은 fs 플러그인으로 직접 수행한다. 원본을 `.withlog/backup/notes-<시각>/`에 글자로 백업하고 YAML의 id를 확인한 뒤 새 폴더에 원자적으로 쓴다. HTML 본문은 `attach/index.html`에 두고 안내 markdown을 만든다. 다 쓴 뒤에만 원본을 지우며 파일 하나의 실패가 다음 파일을 막지 않는다.

한글 slug, 연월 폴더 보존과 다른 중첩 펼치기, 이름 충돌 번호, 예약 폴더·충돌 사본·링크 제외, 8단 깊이, BOM·잘못된 UTF-8 처리, 따옴표 없는 YAML 시각의 Date 변환을 검사했다. 머리 없는 파일의 반복 백업 등 문서의 미결정 호환 동작은 유지한다. 다만 머리 없는 파일의 반복 백업(C10)과 이름 겹침을 글자 그대로 맞대기(C176)는 3부 고치기 증분 1에서 고쳤다. 지금은 머리와 `id`를 먼저 보고 옮길 수 있는 파일만 백업하며, 폴더 이름은 NFC와 소문자로 맞댄다([기록](rebuild-p3-fix-01-complete.md)).

감시는 `recursive: true, delayMs: 400`으로 걸고 임시 파일·`.withlog/cache/`·`.git`을 거른다. 샘플·런처·다른 vault 전환 때 멈추고 늦게 설치된 옛 감시도 회수한다. 포커스와 재표시에도 다시 읽으며 노트 읽기 실패 시 기존 데이터를 보존한다. 현재는 읽기 화면이므로 전체 읽기 교체를 사용한다. 편집 버퍼 보호와 자기 쓰기 기록은 5단계에서 보완한다.

## 검증

- `pnpm test:workspace`: 상태·부팅·전환 18개와 실제 임시 파일 이관 8개, 총 26개 통과.
- `pnpm test:workspace:acceptance`: 새 React 산출물의 실제 WKWebView·Java 엔진 점검 8개와 디스크 확인 1개, 총 9개 통과. 전역 `window.__TAURI__` 없이 실행했다.
- 실제 창에서 경로의 `/.` 글자 보존, 초기 명령 묶음, 이관 본문, 노트 창의 본문·테마·저장 금지, 샘플 전환, 폴더 열기·최근 목록, 만들기의 초기화 두 번을 확인했다.
- native 만들기 UI는 격리된 기존 테스트 폴더에 대한 멱등 생성으로 점검했다. 새 폴더 생성 자체의 IPC·파일 동작은 기존 Rust 검사 범위다. 실제 폴더 선택 대화 상자의 조작은 자동 점검하지 않았다.
- Ego 브라우저에서 번들 CSP를 적용한 시작 화면, 샘플 열기·본문, `mode=create`를 확인했다. 390px 폭에서 가로 넘침이 없었다.
- `bash test-native.sh`: 화면 빌드, 위 26개, 산출물 검사 6개, 기존 설정 검사 3개, Rust 65개 통과. Rust의 격리된 하위 실행용 검사 1개는 원래대로 ignored다.
- `pnpm tauri build --debug --bundles app`: 현재 화면과 Java jar를 담은 macOS 앱 생성 성공.

native 점검은 별도 식별자·임시 HOME·vault·소켓·빈 ZDOTDIR를 사용하며 실사용 vault와 launchd를 건드리지 않는다. Tauri의 읽기 전용 `invoke`를 재정의하지 않고 Java 래퍼의 argv 기록을 수집한다. 원본 `screen.mjs`·합치기 검사 통과와 구분한다. WKWebView 회차는 devUrl에서 빌드 산출물을 제공하므로 실제 번들 프로토콜의 CSP 검증으로 표현하지 않는다.

## 다음 범위

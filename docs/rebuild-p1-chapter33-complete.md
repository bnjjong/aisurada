# 33장 완료 — 설정과 기기 위 파일

작성일: 2026-10-30

제공받은 33장 설명서를 기준으로 엔진의 설정 읽기, `wl-cli` 환경변수, vault 키와 기기 위 경로를 점검했다.

## 구현과 점검

- 설정 키 일곱 개의 명령줄·시스템 속성·환경변수 우선순위와 값 검사를 확인했다. 명령줄의 같은 키는 `=`가 있는 칸의 값만 순서대로 쉼표로 잇고, `=` 없는 칸은 값을 보태지 않는다(3.1). `=` 없는 칸뿐이면 빈 글이다. 이 판은 처음에 `=` 없는 칸도 빈 값으로 이었다가 34장 판 확인 후속에서 바로잡았다([34장 판 확인 후속](rebuild-p1-chapter34-review-fixes.md)). 다시 짓는 판은 명세대로 정확한 설정 이름을 받는다.
- 공백뿐인 `withlog.db.home`은 유니코드 공백 판정으로 기본 위치를 사용하고, 그 밖의 값은 받은 글 그대로 보존한다. 정수 읽기는 64비트 최소값과 그 음수 16진수 표현을 포함한다.
- `dev` 프로파일의 유휴 기본값과 `SPRING_APPLICATION_JSON`, `--spring.application.json`에서 7개 설정을 읽는 우선순위를 추가했다. 일반 설정 명령줄이 JSON을 이기고, JSON이 JVM 속성과 환경변수를 이긴다.
- vault 키의 SHA-256과 경로 이름 처리, 유니코드 소문자 변환 및 경로 정규화를 확인했다. serve와 `wl-cli`는 기기 위 파일의 홈으로 JVM `user.home`을 사용한다.

## 검증

`bash test.sh` 전체 3,085개 검증이 통과했고, `HOME`과 JVM `user.home`이 다른 경우를 추가한 뒤 33장 전용 검증 156개를 다시 통과했다. 격리 프로세스에서 기본값, 우선순위, `dev`, JSON, 반복 옵션, 공백과 불리언·정수 경계, 세 숫자 환경변수의 기본값, 명세의 vault 키 예시, 실제 엔진 vault 문턱을 검사했다. 기존 serve·wl-cli 소켓 테스트는 지정한 홈과 소켓에서 실행한다.

이 엔진은 영속 SQLite 색인을 만들지 않고 매 요청에 vault를 훑는다. 따라서 색인 설정은 읽고 보존하지만 `meta.db`나 WAL 파일은 만들지 않는다. 4부 런타임의 파일과 doctor 조각도 포함하지 않는다. Spring 전체 기능을 재현하는 것이 아니라 이 장의 설정 입력을 처리한다. 검증은 독립 Java 구현에서 실행했으며 원본 엔진과 차등 실행하지 않았다.

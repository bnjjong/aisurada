# 3부 고치기 증분 7: vault 바꾸기(C202, C174)

[3부 고치기 플랜](rebuild-p3-fix-plan.md)의 증분 7이다. 기준 판은 aisurada `daa6561`이다.

- C202는 새 vault 만들기의 초기화가 실패한 뒤의 상태이고, 고치기 플랜의 「호스트를 옛 vault로 되돌린다」(사용자 결정 「A로 가자」)를 따랐다.
- C174는 이미 새 규칙이라 시험만 더했다.

---

## 1. 고친 것

| 줄 | 고치기 전 | 고친 뒤 | 자리 |
|---|---|---|---|
| C202 | 새 vault 만들기가 초기화(`init-workspace`)에서 실패하면, 호스트의 vault는 이미 새 폴더로 바뀐 채 화면 vault를 비우고 시작 화면으로 갔다 | 만들기를 시작할 때 `vault_root`로 호스트의 vault를 읽어 두었다가, 초기화가 실패하면 그 경로로 `allow_workspace`를 다시 부른다. 화면은 옛 vault와 그 감시를 그대로 두고, 처음 오류를 던져 「워크스페이스 생성 실패」를 알린다. 되돌리기 호출이 거절돼도 처음 오류가 보인다 | `workspace/controller.ts`의 `create` |
| C174 | (이미 새 규칙) 열기, 만들기, 딥링크, 시작 화면 모두 모아 둔 회고 쓰기를 보내고 기다린 뒤 호스트를 바꾼다 | 시험만 더했다 | — |

## 4. 그대로 둔 것

- 되돌리기 호출(`allow_workspace`)까지 실패하면 호스트는 새 폴더에 남는다. 그때도 화면은 옛 vault이고, 사용자는 생성 실패 알림만 본다. 2장이 이 겹실패를 정하지 않아서 더 손대지 않았다.
- 개발 폴더의 문서와 3부 설명서 2장 2.5, 2.12의 12번, 2.13은 의뢰자 몫이다.

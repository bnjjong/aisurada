# 3부 3단계: 화면 주소와 탭

2026-11-01. 제공된 「withlog 3부 화면 설명서」 3장의 주소·탭·스크롤 계약을 연결했다. [구현 순서](rebuild-p3-plan.md)의 3단계이며, 메뉴와 전체 단축키는 다음 4장 범위다.

## 주소와 화면 진입

시작 화면, 노트, 외부 md, 캘린더, 즐겨찾기, 아젠다, 연결, 데일리 리포트, 템플릿, 휴지통, 가이드, 세션, 터미널의 주소 13종을 해석한다. `history.pushState` 뒤 `popstate`를 보내도 화면과 탭이 함께 바뀐다. id와 파일 경로는 퍼센트 인코딩해 왕복한다.

- `/`는 `/calendar`로, 알 수 없는 주소는 `/launcher`로 replace한다. vault가 없을 때도 런처 밖 주소는 런처로 보낸다. 알 수 없는 주소로 런처에 가는 것은 메모리의 vault와 직전 기록을 지우지 않는다.
- 없는 노트는 탭 목록에서 처음 만나는 살아 있는 다른 노트 탭으로, 없으면 `/calendar`로 보낸다. 이 규칙은 탭 닫기의 이웃 선택과 구분한다.
- 아젠다는 id를 먼저 찾고 그다음 slug를 찾는다. 없는 아젠다는 주소를 유지한다. `open=a,b`는 오른쪽 노트 칸으로 읽고, 노트 창에 뜬 id는 쿼리에서 빼고 그 창을 앞으로 가져온다.
- 캘린더의 보기·날짜·주 시작은 실행 중 메모리에 남는다. 기본은 일 보기와 오늘이며 주 시작은 월요일이다. 템플릿 `open`은 페이지에 들어올 때 한 번만 읽는다.
- `/file`의 경로가 없으면 파일 탭을 만들지 않는다. 경로가 있으면 `read_external_md`와 `allow_external_images`로 읽는다. 세션 화면은 계약 문구 「이 판에는 Claude 연동이 없어요」를 보인다.
- 노트·외부 파일에는 레일이 없고 나머지 작업 화면에는 있다. 런처와 노트 창에는 탭 바가 없다. 화면 단위 오류는 탭 틀과 레일을 남기고 새로고침·캘린더·런처 이동을 제공한다.

목록 화면은 주소와 쿼리를 확인할 수 있는 읽기 진입부다. 실제 캘린더 배치·연결 그래프·리포트 편집·템플릿 편집·휴지통 조작·외부 md의 전체 렌더러는 12~13장에 남긴다. 노트 본문은 현재 원문 읽기 표시다.

## 탭

탭 목록은 문자열 배열이다. 노트 id, `ext:<경로>`, `term:main`, `term:<세션 id>`로 구분한다. main 탭은 항상 맨 왼쪽이며 닫거나 끌 수 없다. 활성은 주소에서 계산한다. main 탭은 쿼리까지 포함한 마지막 탭 아닌 주소로 돌아간다.

주소 진입은 탭을 끝에 한 번만 더한다. 목록의 노트를 누르면 미리보기, 아젠다에서는 오른쪽 칸을 열고 「탭으로 띄우기」가 노트 탭을 만든다. 활성 탭을 닫으면 오른쪽 이웃, 왼쪽 이웃, 마지막 main 주소의 순서로 간다. 비활성 탭을 닫으면 주소를 바꾸지 않는다. 터미널 탭 닫기는 정확한 탭 id를 key로 `pty_detach`에 보낸다.

포커스된 탭에서 좌우 화살표는 감아 돌며 선택하고 Home·End는 양 끝으로 간다. Delete·Backspace는 해당 탭을 닫는다. 드래그는 가로 이동 5px 초과부터 시작하며 시작 때 잰 다른 탭의 가운데 선으로 놓을 자리를 정한다. 닫기 단추는 손잡이가 아니고 드래그로 끝난 클릭은 탭을 선택하지 않는다.

`withlog.tabs.v1`은 아래 형태를 그대로 쓴다. note 창은 읽기만 한다.

```json
{"state":{"workspaceRoot":"/vault","openIds":["노트 id"]},"version":1}
```

잘못된 판·꼴, 객체, 빈 id, 중복, `term:`·`ext:`·`sess:`를 복원에서 거른다. 외부 파일·터미널·활성 탭·마지막 main 주소·캘린더 보기는 저장하지 않는다. 다른 실제 vault를 열면 탭을 비우고, 사라진 노트 탭은 정리한다. `wl://note-windows`와 최초 창 목록을 받아 별도 창으로 옮겨 간 노트 탭도 닫는다.

## 스크롤과 유지되는 칸

노트 탭과 노트 창은 노트 id별 스크롤을 창 메모리에만 기억한다. 아젠다 칸과 미리보기는 이 기억을 사용하지 않는다. 기억이 없으면 건드리지 않고 0도 유효한 위치로 복원한다. 복원 후 1,500ms 동안 레이아웃 변동에 맞서 위치를 다시 잡고 휠·포인터·키 입력 즉시 해제한다. 붙드는 동안의 스크롤은 기록하지 않는다.

실제 WebKit에서 기억한 위치를 복원할 때 `requestAnimationFrame`의 Window 바인딩이 필요한 오류를 찾아 콜백 래퍼로 수정했다. native 점검은 복원·레이아웃 이동·사용자 입력 해제까지 재현한다.

터미널 칸은 열린 key마다 유지하고 현재 주소에 해당하는 칸만 보인다. 이 단계는 칸의 수명과 detach까지이며 실제 셸·스크롤백 연결은 14장이다. 포커스·재표시에 실제 vault의 오늘을 다시 계산하고 샘플 날짜는 고정한다.

## 문서의 미결정 호환 동작

3.8의 다음 동작을 그대로 두고 검사했다.

1. 처음 노트를 못 읽은 회차는 저장된 노트 탭도 정리한다.
2. 샘플도 실제 vault의 노트 탭을 정리하며 저장된 vault 경로는 유지한다.
3. 알 수 없는 경로는 열린 vault가 있어도 런처로 간다.
4. `/terminal/<세션 id>`는 탭을 만들지만 활성 판정은 main이다. 해당 비활성 탭을 닫아도 주소는 유지하며 같은 상태 갱신에서 바로 탭을 다시 만들지 않는다.
5. 없는 노트의 즉시 이동은 닫기 이웃 규칙과 다르다.

## 검증

- `pnpm test:navigation`: 주소·저장·정리·이웃 선택·창 연동·스크롤 검사 25개 통과.
- `pnpm test:navigation:acceptance`: 실제 WKWebView·Java 엔진의 주소·탭·외부 md·쿼리·노트 창·스크롤·전체 새로고침 점검 10개와 디스크 점검 1개, 총 11개 통과. 원본 하네스 통과로 표현하지 않는다.
- 기존 `test:workspace:acceptance`의 실제 창 점검 9개도 통과했다.
- `bash test-native.sh`: 위 25개, workspace·이관 26개, 빌드 산출물 6개, 설정 3개, Rust 65개 통과. Rust 하위 실행용 1개는 원래대로 ignored다.
- `pnpm tauri build --debug --bundles app`: macOS 앱 생성 성공.
- Ego 브라우저에서 실제 포인터로 마지막 탭을 첫 자리로 옮겨 순서 저장과 활성 노트 유지를 확인했다. 4px 이동은 순서를 바꾸지 않고 클릭으로 처리했다. 실제 키 입력으로 ArrowRight·Home·End·Backspace를 확인했고 390px 폭에서 문서 가로 넘침이 없었다.

브라우저 점검은 번들 CSP를 적용한 preview를 사용했다. 실제 포인터 드래그는 Chromium에서 확인했으며 WKWebView에서의 물리 포인터 조작은 별도 손 확인 범위다. WKWebView 자동 점검은 devUrl에 빌드 산출물을 제공하는 방식이므로 실제 번들 프로토콜 CSP 검증과 구분한다.

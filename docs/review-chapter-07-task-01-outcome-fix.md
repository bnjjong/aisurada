# 7-1 쓰기 결과 정책 보완

작성일: 2026-10-28

`determineWriteOutcome`가 공통 분류기의 `precondition_conflict` 및 `file_processing_error`만 해당 결과로 해석하도록 수정했다. 종료 코드 5나 WL 번호 412·500 하나만으로 다시 분류하지 않는다. 미분류 실행 실패는 초안을 보존하고 부분 쓰기 가능성과 파일 상태 확인 필요를 기록한다. 원본 및 분류 정보는 유지하며 자동 재시도를 실행하지 않는다.

알려진 no-op 결과의 `vaultState`는 `unchanged`에서 `target_body_not_written`으로 변경했다. 이 값은 대상 본문 미재작성만 뜻하며, vault 전체 또는 기존 토큰의 최신성을 보증하지 않는다. 이 문자열을 소비하는 외부 호출자는 새 값으로 전환해야 한다. pre-dispatch 실패도 다른 작업에 의한 디스크 변경 여부를 주장하지 않으며, 파일 재확인이 필요 없다는 플래그와 모순되지 않도록 안내를 `check_transport`로 바꿨다.

실제 공통 디코더·분류기를 거치는 회귀 테스트는 5/412, 3/500, 5/500, 3/412, 5/400, 5/0, 종료 1 및 미지 종료, CLI 로그에 섞인 WL 코드, 소켓 3/0, 전송 단계·신호·계약 위반을 다룬다. CLI stderr의 WL 코드는 정규식 추출이라는 기존 한계를 그대로 가진다. 17개 파일·290개 테스트와 `npm run build`가 통과했다. mock/합성 응답 기반이며 실제 엔진, 실제 파일 쓰기, 공식 수용 묶음은 실행하지 않았다.

# 26장 완료 — 휴지통 명령 5개

작성일: 2026-10-29

기준은 제공된 PDF 16~38쪽이다. 기존 `list_trash`/`list-trash`에 `delete_doc`/`delete-doc`, `restore_doc`/`restore-doc`, `purge_doc`/`purge-doc`, 명령 전용 `empty-trash`를 연결했다.

## 구현

`cmd/TrashCommands.java`가 쓰기 4개를 맡는다. 보내기는 노트를 폴더 또는 단일 파일째 원자적으로 옮기고, 새 항목을 맨 앞에 둔 매니페스트를 쓴다. 되살리기는 아젠다 slug로 목적지를 찾고 필요하면 정해진 바이트의 복구함 아젠다를 만든다. 충돌 이름에는 확장자 앞에 `-restored-<id 끝 6자>`를 넣고, 현재 샤드 설정의 부모 폴더로 옮긴다. 갈 아젠다가 달라질 때만 프론트매터를 다시 쓰며 본문·다른 메타·원래 노트 id를 보존한다.

영구 삭제는 보관물을 먼저 지운 뒤 항목을 뺀다. 비우기는 경로 검사와 지우기 실패를 항목별로 모으고 실패한 항목만 남긴다. 고아는 숨김 파일과 끊어진 링크도 세되 지우지 않는다. 쓰기는 매번 읽혀 선 항목만 파일 차례로 다시 쓰고, 같은 trashId의 항목은 복원·영구 삭제에서 모두 뺀다.

`vault/TrashReader.java`는 프론트매터와 같은 시각 해석을 끈 YAML 읽개를 쓰도록 맞췄고, 음수 1시간 미만 오프셋의 부호도 보존한다. 목록은 계속 버린 순간 내림차순이며, 매니페스트 저장 순서와는 분리한다. 파일 JSON은 기존 `JsonWriter.toFileBytes`로 키 11개와 LF를 고정한다.

## 검증

`test/withlog/Chapter26Test.java` 130개 검증: 기록 층의 도구 보내기, 폴더·첨부·코멘트 왕복, 같은 아젠다의 본문 바이트 보존, 복구함과 프론트매터 수정, 이름 충돌, 사라진 보관물의 목록 정리, 경로 탈출, 실패 수집, 중복 id, 링크와 끊어진 링크, 고아, 깨진 항목, 매니페스트 쓰기 실패 뒤 남는 보관물을 확인했다. HTML과 JSON의 폴더·단일 파일 모두 복구함 복원을 확인했고, `.md`로 끝나는 폴더의 단일 파일 오판정과 복원 경고도 재현했다. 실제 wl-cli에서 보내기·목록·복원을 왕복했다.

## 유지한 경계

26.9를 임의로 고치지 않았다. 못 읽은 매니페스트 항목은 다음 쓰기에서 빠지고, 복구함은 뒤 단계 실패보다 먼저 만들어질 수 있으며, 원래 아젠다가 없는 보관물에 다시 찍을 수 없는 YAML 값이 있으면 복원이 선다. `file=.`에 해당하는 매니페스트 값도 명세처럼 files 폴더 자체를 가리킬 수 있다.

색인을 저장하지 않는 기존 구조(8.6)를 따른다. 이동·복원 뒤 다음 호출은 디스크를 다시 훑는다. 이전 색인 행의 낡음이나 같은 노트 id를 복원 직후 어느 경로로 덮는지는 영속 색인처럼 재현하지 않는다.

# aisurada 1~20장 누락 기능 개발 완료

작성일: 2026-10-29. 구현 위치: `/Users/df/github/aisurada` Java 엔진.

1~20장 점검에서 찾은 필수 미구현 두 가지, `reindex-paths`와 공통 쓰기의 vault git 자동 커밋·작성자 기록을 구현했다. 앱 저장소에만 넣은 변경이 아니라 aisurada의 엔진·serve·실제 파일 처리에 반영했다.

## 구현

### 경로별 재색인 — 8.5, 8.6

- 명령 표면의 `reindex-paths`를 인자 읽기·지원 명령·실행기에 연결했다. 옵션 없이 자리 인자를 받고, `--`로 시작하는 설정 칸은 기존 문법대로 버린다.
- 앞뒤 공백과 `/`, `notes/` 접두어, 빈 경로 조각, 경로 이탈 검사, 중간 경로 없음, 폴더 깊이·링크·예약 이름·충돌 사본 규칙을 처리한다. 두 번째 조각의 `..` 허용과 이후 조각의 이탈 거절도 유지한다.
- 노트 내부 경로는 루트 노트로 접고 같은 노트는 한 번만 연다. 모든 경로를 모은 뒤 노트를 열어, 뒤 경로의 검증 실패가 앞 노트의 파싱보다 먼저 난다.
- 아젠다는 전부 읽고, 노트는 선택한 범위만 읽는다. 자리 인자 200개 초과는 `mode: full`로 노트 전체에 전환하지만 템플릿·회고·휴지통은 검사하지 않는다.
- 기존 전체 훑기와 후보 수집기를 공유한다. 훑기 진단 뒤에 열기 진단을 싣고, 샤드 vault의 `unsharded`에는 이번 후보만 정렬해 넣는다. 잘못된 노트 후보도 포함한다.
- 영속 색인이 없는 8.6 방식을 유지한다. `indexed`는 이번에 세운 루트 노트 수이며 `unchanged`와 `removed`는 0이다.

### 자동 커밋·작성자 기록 — 3.2, 7.1, 31.1~31.3

- `WritePipeline`에서 문법 검사 뒤 표식 확인·전체 맞추기·작성자 검사 순서로 준비한다. 기존 쓰기 명령은 준비한 색인을 공유하므로 다시 훑지 않는다.
- 명령의 일에 도달한 호출은 성공·WL 실패·예상 밖 실패 모두 끝에 작성자를 남긴다. 문법·표식·맞추기에서 선 호출은 남기지 않는다. 빠진 4부의 쓰기 두 명령도 같은 공통 단계를 지난다.
- 명령 표면은 `app`, 도구 표면은 `tool`과 받은 세션 값으로 기록한다. 같은 작성자/세션의 연속 쓰기는 git을 부르지 않고, 다른 짝의 쓰기는 이전 변경을 먼저 커밋한다.
- serve 시작은 실행 잠금을 잡은 뒤 소켓을 열기 전에 `startup`, 정비는 상태 파일 갱신 뒤 `idle`/`overdue`, 종료는 연결 대기 뒤 잠금 해제 전에 `shutdown` 커밋을 시도한다. 단발 모드의 대기 기록은 공유하지 않고 자동 커밋하지 않는다.
- 자동 커밋 끄기·기본 300초 유휴·15분 경과를 처리한다. git과 대기 기록만 같은 잠금으로 보호하고 실제 쓰기는 줄 세우지 않는다.
- 저장소/브랜치·최근 index.lock·병합 상태를 확인한다. 10분 넘은 잠금은 지우며, 건너뜀은 30초, 실패는 30·60·120·240·480초로 재시도한다. git 실패가 본문 쓰기를 실패로 바꾸지 않는다.
- git은 셸 없이 실행하고 `GIT_DIR`/`GIT_WORK_TREE`를 고정하며 `GIT_INDEX_FILE`을 제거한다. 훅·서명은 끄고 출력을 병렬로 비운다. 프로세스 시간 제한은 60초, TERM 뒤 3초 후 KILL이다.
- `*.tmp`를 제외해 담고, NUL 구분 상태/경로를 읽는다. 지운 `note.md`는 HEAD를 한 번의 `cat-file --batch`로 읽고 다른 파일은 앞 4,096바이트에서 id를 모은다. 저자·커미터와 작성자/까닭/세션/노트 꼬리 줄, 노트 id 200개 상한을 적용한다.

실제 serve와 `wl-cli`로 같은 git vault에 수행한 커밋 수는 다음과 같다.

| 시점 | 최초 점검 | 개발 후 |
|---|---:|---:|
| serve 시작 전 | 1 | 1 |
| startup 뒤 | 1 | 2 |
| 도구 쓰기 뒤 | 1 | 2 |
| 앱으로 작성자 전환 뒤 | 1 | 3 |
| 유휴 정비 뒤 | 1 | 4 |
| 종료 직전 추가 앱 쓰기 뒤 | 검사 안 함 | 4 |
| shutdown 뒤 | 1 | 5 |

개발 후 git status는 비어 있다. 테스트 원본을 수정하지 않은 외부 자가 시험에서 vault와 HOME의 바이트 불변성도 통과했다. 이것은 저장소 밖 자체 시험의 결과이며 원본 Kotlin 엔진이나 제공되지 않은 공식 수용 묶음/golden 파일을 실행했다는 뜻은 아니다.

## 범위와 남은 차이

이번 점검에서 발견한 1~20장 필수 미구현 두 가지는 해소했다. 모든 파일 시스템 경계와 동시 실행 조합이 완전히 증명됐다는 뜻은 아니다. 8.6이 허용한 영속 색인 부재·옛 행과 코멘트 표의 낡음 차이, 부록 D 미결정 특이점은 그대로다. `history`, `commit-vault`, 스냅숏과 21장 이후 변형 명령은 이번 누락 보완 범위에 포함하지 않았다.

이제 기본 설정에서 serve를 시작하면 기존 main 브랜치 git vault의 외부 변경도 자동 커밋된다. 이 동작을 원하지 않는 vault는 `WITHLOG_VAULT_AUTOCOMMIT_ENABLED=false`로 끈다.

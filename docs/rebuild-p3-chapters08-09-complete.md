# 3부 8~9장 — 편집기와 Markdown 왕복

기준은 사용자가 제공한 「withlog 3부 화면 설명서」의 8~9장(74~100쪽)이다. Java 엔진과 Rust 호스트의 기존 IPC 위에 Lexical 0.47.0 편집기를 연결했다. 원본 구현·원본 71사례 파일은 제공되지 않았으므로 이 저장소의 독립 재현 검사와 구분한다.

## 구현

본문 탭, 아젠다 옆 노트, 미리보기, 하위 노트와 노트 창이 같은 편집기를 사용한다. 새 노트·템플릿·회고 등 후속 폼에서도 `Editor`의 기능 인자로 링크·하위 페이지·첨부·코멘트를 켜거나 뺄 수 있다. 해당 폼의 전체 화면은 11~13장에서 연결한다. HTML 본문은 DOMPurify로 정화한 읽기 화면이고 JSON은 정렬된 키와 두 칸 들여쓰기를 쓴다. 엔진이 JSON 본문 쓰기를 거절하는 기존 동작은 바꾸지 않았다.

열 때 자동 포커스·선택을 만들지 않으며, 초기 들여오기·플러그인 정리·선택 이동·미러를 사용자 편집으로 내보내지 않는다. 변경 시에는 전체 본문과 첫 헤딩/나머지 위치의 커서 신호를 내보낸다. 미러는 번호·본문 대조, 외부 미러의 undo 기록 비우기, 조합 중 연기와 그동안 편집한 경우 충돌 알림을 갖는다. 목차용 헤딩·절 신호, 헤딩·코멘트로 가기와 표식·하위 카드 제거 인터페이스를 제공한다.

굵게·기울임·취소선·인라인 코드·하이라이트·밑줄, 1~6단계 헤딩, 인용·목록·4상태 할 일·코드·콜아웃·표·이미지·노트 칩·하위 카드를 지원한다. 기울임은 파란 바로 선 글자이고 밑줄과 문단 들여쓰기는 Markdown에 저장하지 않는다. 가로줄 노드는 없다. Cmd+E 조건과 목록·코드·표의 Tab 경로는 분리한다. 콜아웃의 원래 종류는 유지하다가 네 종류 버튼을 누를 때 표준 종류로 바꾼다.

표는 첫 행이 머리인 3×3으로 삽입한다. 칸 메뉴 열 항목, 행·열 삽입/삭제, 표 삭제, 너비 맞춤과 두 복사를 제공한다. 경계 드래그는 옆 두 칸 합을 유지하며 최소 48px, 바깥 경계는 비례 조절이다. 저장은 픽셀 대신 구분선 대시의 비율이다. mounted 정리는 짧은 행 패딩·빠진 폭 반복·인접 링크 합치기·완료와 보류 상태 정리를 한다. 코드 언어가 정확히 mermaid인 경우만 편집기 밖에 SVG 미리보기를 둔다. 250ms 지연·직렬 렌더·strict 보안·테마를 사용하며 SVG의 외부 이미지·HTML·링크 노드는 뺀다.

그림 클립보드는 네이티브에서만 받는다. MIME 허용 목록, 읽기 전 5,000,000바이트 검사, UUID 파일명, 퍼센트 인코딩한 헤더와 raw 바이트 IPC를 사용한다. 쓰기 성공 뒤 당시 선택에 이미지를 넣고 실패를 모아 알린다. 첨부 쓰기를 자기 쓰기 목록에 올리지 않는다. 상대 경로는 한 번만 디코드하며 위험 세그먼트를 거절한다. HTML 첨부는 wlframe, allow-scripts sandbox, no-referrer, lazy와 숨긴 ask 표식을 사용한다. 높이는 source 검사·올림·160~1600 제한·URL별 2,000개 캐시로 처리한다. 상자 링크는 길이·iframe 포커스·최근 입력·간격을 검사하며 부모 쪽 postMessage는 없다.

일반 링크는 수정키를 누른 클릭으로 열고 하위 카드는 그냥 클릭한다. 문서 칩은 삽입 제목을 저장하되 화면에는 현재 제목을 쓴다. `[[` 피커와 슬래시는 변경 갱신에서만 열리며, 키보드 탐색·검색·취소와 포커스의 preventScroll을 지원한다. 코멘트는 선택을 블록/셀별 같은 ID로 감싼 뒤 엔진에 만들고, 인용·작성 상자·호버 카드·고정·스레드 진입·표 줄 점·본문 점프를 연결했다. 문답 표식은 보존하지만 4부 버튼과 카드는 만들지 않는다.

붙여넣기는 이미지 외에는 Lexical 기본 순서(앱 JSON→HTML→평문)를 따른다. 평문 Markdown은 글자로 남는다. 표 선택 복사는 GFM/TSV로 평문을 바꾸고 HTML·앱 형식을 보존한다. 문단과 표를 함께 고른 Cmd+Shift+C는 표만 TSV·HTML·앱 JSON으로 남긴다. 복사용 GFM은 폭 힌트를 빼고 표식을 걷는다.

## Markdown과 저장 연결

들여오기는 표식 자리표→CR/LF·문단 줄 잇기→콜아웃 분리→목록 공백 두 배→라이브러리 변환→콜아웃 복원→주석 감싸기 순서다. 표 셀은 별도 변환 규칙을 쓴다. 헤딩·목록·코드 펜스·표 구분선·폭 힌트·이스케이프·raw HTML·칩·주석의 정규화와 문서에 명시된 손실을 재현한다. 표식은 종류·ID·짝을 검증하고 블록마다 분할하며, 원래 E000 글자도 표식이 있는 문서에서는 정리한다.

이번 왕복 검사를 위해 사용자 변경 뒤 600ms에 `update-doc`/`update-sub-note`를 보내는 최소 저장 연결을 넣었다. 데이터 계층의 기존 큐·토큰·충돌 보호를 사용하고, 화면 해제·vault 이동 전 flush와 세대 무효화를 갖춘다. 저장 중 새 편집을 하고 이동해도 최신 버퍼까지 flush한다. **10장의 제목 커밋, 4초 재시도, 전체 충돌 선택 UI·미러 수명·이력 되돌리기는 다음 단계다.** 이번 연결을 10장 전체 완료로 보지 않는다.

## 검증 범위

`fixtures/editor-roundtrip/README.md`에 독립 71사례의 출처와 한계를 적었다. headless와 mounted의 차이 J1·J4·L4를 별도 기대값으로 둔다. 실제 왕복 하네스는 앱 시작 전 엔진으로 심고, 호스트의 get-doc으로 원문 바이트를 확인하고, 매번 열고 1,500ms 동안 토큰 불변을 확인한다. 마지막 문단에 insertText로 편집하고 전체 본문 바이트를 비교한다. 둘째 저장이 있는 세 사례는 화면을 내렸다 다시 연다. 마지막에 본문 쓰기 횟수도 대조한다.

- `pnpm test:editor`: 독립 headless 71개와 표 정리·경로·폭·높이·열기 정책·주석·복사 형식·저장 연결 11개, 총 82개 통과.
- 브라우저에서 자동 포커스 없음, 본문 입력, 기울임 서식, 표 메뉴·행 추가, 슬래시 콜아웃, Mermaid SVG 글자를 확인했다. 편집기 노드 클래스 변경 후 개발 HMR이 옛 클래스를 유지한 오류는 페이지를 새로 열어 검증했다.
- 실제 WKWebView의 A1 부분 회차 13개 점검 통과. 표 삽입·메뉴·복사·폭 조절, literal 평문 붙여넣기, 실제 이미지 바이트 IPC, 실제 코멘트 생성·스레드, HTML 상자의 source/높이/속성, Mermaid와 하위 본문 저장을 포함한다. 최종 전체 회차는 83개 점검이 통과했다. 독립 왕복 71개, 둘째 저장 3회까지 74번의 본문 쓰기와 바이트 일치를 확인했고 열기/정리 추가 본문 쓰기는 0회였다.

- `bash test-native.sh`: 타입·CSP 번들 검사, 화면 6개, workspace/이관 29개, navigation 25개, interaction 30개, data 48개, editor 82개, 설정 3개, Rust 65개 통과. 기존 Rust 격리 하위 실행용 1개는 ignored다.
- 기존 실제 WKWebView workspace 9개, navigation 11개, interaction 11개도 모두 통과했다.
- 최종 타입 검사·번들 계약 검사와 `pnpm tauri build --debug --bundles app` 성공. `native-host/src-tauri/target/debug/bundle/macos/withlog.app`을 갱신했다. 번들 자체의 실행 검사는 이번 단계에 포함하지 않는다.
- 표 복사에서 앱 JSON을 표만 남기는 보완과 화면 해제 뒤 표 RAF·드래그 정리는 마지막 단위 검사 및 A1 부분 회차 13개로 다시 확인했다.

실제 한국어 IME의 물리 입력, 운영체제 클립보드 조합 전체, 파일 선택 대화 상자, 미제공 원본 골든과 18장 손 확인은 완료로 주장하지 않는다. 현재 WKWebView 조작은 devUrl로 실행하며 번들 프로토콜에서의 실사용 확인과 구분한다. 모든 파일 변경 검사는 격리 HOME·vault·소켓에서 했다.

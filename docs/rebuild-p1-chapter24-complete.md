# 24장 완료 — 템플릿 명령 5개

작성일: 2026-10-29

이번 요청에 붙인 24장을 기준으로 기존 `list_templates`/`list-templates`, `get_template`/`get-template`를 확인하고, `save_template`/`save-template`, 명령 전용 `delete-doc-template`, `save-ritual-template`를 구현했다. 읽기 2개와 쓰기 3개가 모두 동작한다.

## 구현

| 파일 | 변경 |
|---|---|
| `src/withlog/cmd/TemplateCommands.java` | 문서 만들기·고치기·삭제, 리추얼 고치기, 필드 검증 순서와 응답 |
| `src/withlog/write/TemplateFile.java` | 24.5/24.8의 갈래별 YAML 키 순서, 파일 경로와 본문 바이트 |
| `src/withlog/args/ArgsParser.java` | save_template의 선택 문자열 5개와 본문 상한, 쓰기 명령 3개의 옵션·자리 인자·사용법 |
| `src/withlog/cmd/CommandRegistry.java`, `src/withlog/engine/EngineExecutor.java` | 지원 명령과 실행 분기, 공통 쓰기 단계 연결 |
| `src/withlog/cmd/ListTemplates.java` | 필터링한 진단을 bodies 검증 전에 내고 소켓 stderr에도 전달 |
| `src/withlog/write/FrontmatterWriter.java` | 기존 큰따옴표 문자열 쓰개를 템플릿 쓰기도 재사용할 수 있도록 공개 |

문서 만들기는 id를 안 주거나 빈 글로 주면 선택된다. 본문, 다듬은 이름, 유형 순서로 검사하고, 기본 유형 plan과 builtin false로 새 id를 발급한다. 만들기는 템플릿 폴더를 훑지 않아서 다른 템플릿의 치명적 YAML 오류와 무관하게 돈다. 고치기는 id, 준 이름, 준 유형을 본 뒤 훑기에서 처음 찾은 문서 템플릿의 읽힌 값에 준 칸만 얹는다. 유형은 다듬지 않고 로캘 없이 소문자로 바꾼다. 본문과 설명의 빈 값은 지우기이고, 생략은 기존 값 유지다.

문서 파일은 늘 `<id>.md`에 원자적으로 쓴다. 키는 id, name, type, format, desc, builtin 순서이며 본문 뒤에 줄바꿈을 더하지 않는다. 옛 포맷이 HTML이나 JSON이면 새 마크다운을 쓴 뒤 `<id>.<옛 확장자>`를 지운다. 이름과 설명의 짝 없는 서로게이트는 대문자 YAML 탈출로 남기고, 본문은 기존 UTF-8 쓰기 규칙대로 `?`가 된다.

삭제는 처음 찾은 템플릿이 없으면 성공, 리추얼이나 빌트인이면 WL-400이다. 사용자 문서 템플릿은 `<id>.md`, `<id>.html`, `<id>.json` 순서로 지우고 실제로 지운 경로만 removed에 싣는다. 파일 이름과 id가 다르면 찾은 파일 이름을 대신 지우지 않는다.

리추얼은 처음 찾은 같은 id가 리추얼이어야 한다. 폴더를 다시 훑어 같은 rev를 든 읽힌 리추얼이 정확히 1개인지 검사한 뒤 `<rev>.md`에 쓴다. 문서에 같은 id가 가려진 리추얼도 rev 셈에는 든다. rev, icon, format은 읽힌 값을 보존하고, HTML 리추얼도 울타리는 `---`다. 응답의 builtin은 false이고 action은 updated다.

들여쓴 블록 경고는 공통 `WarningsDetector`로 이번에 받은 body만 검사한다. 본문을 생략한 고치기는 옛 본문의 들여쓰기로 경고하지 않는다. 본문 길이 200,000 UTF-16 단위 상한은 도구 save_template에만 걸고, 명령 표면에는 걸지 않는다.

## 유지한 경계와 문서 해석

24.9의 미결정 동작을 유지한다. 충돌 사본과 같은 id를 합치지 않고, 별칭 파일 이름을 청소하지 않고, 반쪽 이관은 HTML의 옛 값을 바탕으로 한다. 리추얼 custom.md는 고친 뒤에도 남아 다음 저장에서 rev 중복으로 설 수 있다. 템플릿 쓰기에는 노트 토큰이나 편집 도장을 더하지 않는다. 템플릿 읽기는 영속 색인에 기대지 않아 기존 색인 없는 구조와 차이가 없다. 쓰기 전 노트 훑기의 낡은 행 차이는 기존 8.6을 따른다.

붙인 글의 바이트 예시와 일반 규칙이 갈리는 두 곳은 다음처럼 처리했다.

1. 붙인 24장은 빈 설명을 `desc: ""`, 앞뒤 ASCII 공백이 있는 한 줄 이름을 `name: " a "`로 명시한다. 템플릿 편집 쓰기는 이 예시를 따르고, 나머지 스칼라·블록·탈출은 기존 1.9 쓰개를 쓴다. 23장의 기존 씨앗 쓰개가 쓰는 `desc: ''`, `name: ' a '`는 바꾸지 않았다. 둘 다 같은 값으로 읽히지만 파일 바이트는 다르다.
2. 24.5는 CRLF를 떼고 이어 LF도 떼라고 적으면서, 바로 뒤 CRLF+LF 예시는 LF가 남는다고 적는다. 구현은 기존 1.6과 같은 명시 절차를 유지해서 CRLF+LF 뒤의 본문은 두 줄바꿈을 모두 뗀다. 이 경계를 실제 파일로 검증했다.

원본 Kotlin 엔진과 차등 실행한 결과는 아니다. 이번 요청의 규칙과 예시를 기준으로 Java 엔진과 실제 파일·소켓·git을 검증한 결과다.

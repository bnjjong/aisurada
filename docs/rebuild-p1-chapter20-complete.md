작성일: 2026-10-29

## 기준 자료

붙여 준 글은 설명서 20장을 다시 쓴 판으로 보인다. 20.9(얼어 있는 특이점)는 거의 그대로이지만, 20.3~20.6에 설명서와 어긋나거나 글 안에서 서로 어긋나는 자리가 있었다. 지난 회차들의 기준이 설명서였고 엔진 전체가 설명서의 종료 코드와 문구를 따르므로, 어긋난 자리는 설명서를 따랐다.

| 자리 | 붙여 준 글 | 설명서(따른 쪽) |
|---|---|---|
| WL 실패의 종료 코드 | 1 | 3(6.5. `WL-412`만 5) |
| 아젠다 id 모양 | `ag-`로 시작 | `^ag[0-9a-z]+-[0-9a-f]{8}$`이거나 `ag-recovered`. 붙여 준 글의 예시 id도 이 모양이다 |
| id 발급 | `ag-` + KSUID 27자 | 1.4(`ag` + 36진수 밀리초 + `-` + 16진수 8자리) |
| `list-agendas` 차례 | 20.1은 slug 차례, 20.5는 rowid 차례 | slug의 UTF-16 차례 |
| 빈 `repo`, `project` | `null` | 키째 뺀다 |
| `deepLink` | `?vault=` | `?ws=`(11.6과 같다) |
| 실패 문구 | `아젠다 제목이 필요하다`, `아젠다를 찾지 못했다` 등 | `title 이 필요하다`, `Agenda not found: <id>`, `노트가 <n>건 있는 아젠다는 지울 수 없다. 먼저 그 노트를 옮기거나 버린다: <slug>` 등 20.4의 문구 블록 |
| `--write` 누락 실패 | 있음 | 없음. 쓰기 깃발은 엔진 안의 선언이다(7.1) |
| id 없는 `update-agenda` | 인자 가르기에서 섬 | 표식과 색인 맞추기 뒤의 칸 검사에서 섬(20.3의 5번) |
| 지울 파일이 없을 때 | `WL-404` | 경고 로그만 남기고 성공 |
| hue 실패 문구 | 끝에 색 목록 | `hue 값이 아니다: <다듬은 값>`만 |
| 다듬기 | U+0020 이하 | 0.3의 다듬기(U+00A0, U+3000 포함, U+FEFF와 U+200B 제외) |

붙여 준 글을 담은 미추적 파일 3개는 설명서와 다른 내용이라 커밋에 넣지 않고 그대로 두었다.

## 지은 것

### 공용 부품

| 파일 | 하는 일 |
|---|---|
| `write/AgendaFile` | 파일 자리, slug 비켜서기(`-2`~`-100`), 가장 덜 쓰인 색, 파일 바이트. `create_doc`도 쓴다 |
| `out/AgendaRow` | 20.6의 아젠다 객체(키 차례 id, slug, title, hue, repo, project, summary, deepLink) |
| `cmd/AgendaArgs` | id 칸(없거나 공백뿐, 모양), hue 칸, id로 찾기(`WL-404 Agenda not found`) |
| `vault/AgendaReader` | 색 12개(`HUES`)와 slug 모양 검사를 공개로 돌림 |
| `write/FrontmatterWriter` | 아젠다 프론트매터에 `repo`, `project` 줄 |

### 명령

- **`list-agendas`**: 표식을 안 보고 아젠다 파일을 읽어 slug 차례로 낸다. 아젠다가 없으면 `[]`이다.
- **`create-agenda`**: 표식 → 색인 맞추기 → `title`, `hue`, `project` 칸 → id 발급 → slug 비켜서기 → 자동 색 → 파일 쓰기. 같은 이름이 있어도 늘 새로 만든다. 50단위 자르기가 서로게이트 쌍을 가르면 `WL-400 경로로 쓸 수 없는 값이다`로 서고 아무것도 안 쓴다.
- **`update-agenda`**: 표식 → 색인 맞추기 → id 있음, id 모양, `hue`, `project` 칸 → id로 찾기 → 준 칸만 얹어 파일을 통째로 다시 쓴다. `repo`와 `project`는 「안 줌/빈 값/값」 3갈래이고, 빈 `title`은 이름을 안 바꾸고, `summary`는 다듬지 않는다. 모르는 키(`status:` 같은 것)는 다시 쓸 때 사라진다.
- **`delete-agenda`**: 표식 → 색인 맞추기 → id 칸 → 찾기 → 그 아젠다를 가리키는 루트 노트 수(층을 안 가림) → 1건 이상이면 `WL-400` → 파일을 `.withlog/trash/agendas/<slug>-<id>.md`로 이름 바꾸기 1번. 원래 자리가 비었으면 성공하고, 옮길 자리가 차 있거나 휴지통 폴더를 못 만들면 `WL-500`이다.

## 색인이 없는 판의 차이(8.6)

이 판은 색인을 두지 않아서 「색인 행」은 그 호출이 읽은 아젠다 파일(같은 id는 이름 차례로 뒤 파일)이다. 8.6이 결정 전에 허용한 대로 디스크를 따르고, 그래서 지금 엔진과 갈리는 자리는 이렇다.

| 자리 | 지금 엔진 | 이 판 |
|---|---|---|
| 손으로 지운 아젠다 파일(20.9의 1번) | 색인 행이 남아 목록에 나오고 비켜서기에서 찬 자리로 셈 | 목록에서 빠지고, 고치기·지우기는 `WL-404`, 비켜서기에서는 빈 자리 |
| 1번도 맞춘 적 없는 vault의 `list-agendas` | `[]` | 파일의 아젠다 |
| 2.1로 못 읽는 아젠다 파일의 `update-agenda` | 옛 행으로 덮어씀 | `WL-404` |
| 옮길 자리가 차서 선 `delete-agenda`(20.9의 10번, 12번) | 행만 지워져 다음 맞추기까지 목록에서 빠짐 | 목록에 그대로 남음 |
| 같은 slug를 다른 id로 쓰는 파일이 있을 때의 `list-agendas` | 색인 행 그대로 | 다른 읽기 명령처럼 `[]` |
| serve 모드에서 같은 이름의 `create-agenda` 2개가 동시에 돎 | 뒤쪽이 색인 유일 제약으로 예상 밖 실패 | 둘 다 성공하고 같은 파일을 차례로 씀. 앞쪽 응답의 id는 파일에서 사라짐 |

`create_doc`의 자동 색 세기는 파일 수(`slugToAgenda`)에서 행 수(`idToAgenda`)로 바뀌었다. 같은 id의 아젠다 파일 2개가 없는 vault에서는 결과가 같다.

## 그대로 둔 것과 정할 것

- 20.9의 16가지 특이점은 부록 D에서 모두 「정하지 않음」이라 지금 엔진처럼 냈다. 색인에 기대는 1번, 10번의 일부, 5번의 동시 실행 갈래만 위 표처럼 디스크를 따른다.
- 설명서 20.9 끝의 「정할 것」(1번과 5번을 고칠지, 2번의 읽기를 1.8의 YAML 읽기로 바꿀지, 13번을 건너뛰기로 고칠지)은 의뢰자 몫이라 손대지 않았다.
- vault git 자동 커밋과 쓴 쪽 기록은 이전 회차처럼 짓지 않았다.
- 붙여 준 글을 설명서로 바로잡을지, 설명서 20장 원문으로 `docs/engine-manual/20-agendas.md`를 바꿀지는 의뢰자가 정한다.

기록은 개발 폴더의 `spec-gaps-15차.md`에 있다.
